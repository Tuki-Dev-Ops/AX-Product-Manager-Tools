# 企画ドキュメント作業構造

[한국어](README.md) · [English](README.en.md) · [中文](README.zh.md) · **日本語**

IT サービスの企画ドキュメントを作成し、ドキュメント間のつながりと作業状況を管理するための構造である。
執筆基準は [CLAUDE.md](CLAUDE.md) に従う。

---

## 背景

企画作業はプロジェクト概要、企画レビュー、サービス構造、フロー、IA、ワイヤーフレーム、機能仕様に分かれる。
分割すると各ドキュメントは読みやすくなるが、一つを直しても他は連動して変わらない。

* 01 に要件を追加したが、03 の機能一覧に反映されない。
* 05 で画面を削除したのに、07 の機能仕様にはその画面が残る。
* 04 のフローにある画面が、05 の画面一覧に存在しない。

ドキュメントが増えるほど、こうしたずれを目視で見つけることが難しくなる。
レビュー段階で見落とすと、設計・開発段階で手戻りになる。

このリポジトリでは、ドキュメント間のつながりを本文ではなく別データとして管理し、
生成のたびに切れているつながりを検出する。

## 目的

| 目的 | 方法 |
| --- | --- |
| トレーサビリティの確保 | 要件 → 機能 → フロー → 画面 → 仕様を識別子でつなぐ |
| 整合性チェック | ダッシュボード生成時に切れたつながりを自動で検出する |
| 作業状況の把握 | ドキュメントごとの状態、進捗、変更履歴を一画面で確認する |
| 執筆基準の統一 | 文体、用語、状態名、表記の基準を `CLAUDE.md` 一つで管理する |

ドキュメントを自動生成することが目的ではない。
人が判断して書いたドキュメント同士がずれないよう保つことが目的である。

## 実行方法

### 準備

Python 3.9 以上と PyYAML が必要である。

```bash
pip install pyyaml
```

### ダッシュボードの生成

```bash
python tools/build_dashboard.py
```

`dashboard/index.html` が生成される。ブラウザでそのまま開けばよい。
ドキュメント本文が HTML に埋め込まれるため、サーバーは不要である。

| タブ | 内容 |
| --- | --- |
| 状況 | 全体進捗、ドキュメント別の進捗と完了予定時刻、進行中・待機・完了の件数 |
| 変更履歴 | 変更項目の全件。キーワード、状態、出所、ドキュメントで絞り込む |

ドキュメント項目を選ぶと、その本文をダッシュボード内で直接確認できる。
フロー、IA、アーキテクチャ、ワイヤーフレームは本文内に図として描画される。

整合性チェックの結果は画面には出さない。生成コマンド実行時にコンソールへ出力する。

```text
生成: dashboard/index.html (639KB, ドキュメント本文を含む)
全体進捗 100% · 進行中 0 件 · 待機 0 件 · 完了 8 件
チェック: 未決項目 0 件, 未接続項目 0 件
```

### 画面コードビューア

`dashboard/wireframe.html` はワイヤーフレームを画面単位で確認するツールである。
左で画面を選ぶと、右に画面と HTML がそのまま表示される。
「コードをコピー」でその画面の HTML と CSS をそのまま取得できる。

### 作業手順

1. ドキュメントを修正する。
2. `_data/changes.yaml` に変更項目を追加する。影響する下位ドキュメントを `affects` に記載する。
3. 新規または変更した識別子を `_data/trace.yaml` に反映する。
4. 要確認・前提・意思決定が必要な項目は `_data/issues.yaml` に記載する。
5. `_data/documents.yaml` の状態、進捗、完了予定、バージョン、更新日を修正する。
6. ダッシュボードを再生成し、コンソールのチェック結果を確認する。

上位ドキュメントが変わった場合、それを継承するすべての下位ドキュメントの状態を「レビュー中」に戻す。

## 構造

### フォルダ構成

```text
.
├── CLAUDE.md                  執筆基準 + 運用ルール
├── README.md                  本書
├── docs/                      顧客向け企画ドキュメント（最終成果物）
│   ├── 01_프로젝트개요.md        プロジェクト概要
│   ├── 02_기획검토.md            企画レビュー
│   ├── 03_서비스구조.md          サービス構造
│   ├── 04_Flow.md               フローチャート
│   ├── 05_IA.md                 情報アーキテクチャ
│   ├── 06_Wireframe.md          ワイヤーフレーム
│   ├── 07_기능명세.md            機能仕様
│   └── 08_검토결과.md            レビュー結果
├── research/                  調査原本。企画判断は docs/02 に整理する
├── _data/                     ドキュメント間の接続データ
│   ├── documents.yaml         ドキュメント別の状態・進捗・完了予定・継承関係
│   ├── trace.yaml             要件 → 機能 → フロー → 画面 → 仕様の追跡項目
│   ├── changes.yaml           変更履歴
│   └── issues.yaml            要確認・前提・意思決定が必要・定義の不一致
├── tools/
│   ├── build_dashboard.py     YAML + ドキュメント → ダッシュボード生成、整合性チェック
│   └── dashboard_template.html
├── dashboard/
│   ├── index.html             ダッシュボード（生成物）
│   ├── wireframe.html         画面コードビューア（生成物）
│   └── admin.html             内部管理画面まとめ（生成物）
└── agent-system/              ドキュメント補強に用いる役割別の指示書
```

`dashboard/` 配下は生成物である。直接修正しない。
画面を変える場合は `tools/dashboard_template.html` を修正して再生成する。

### ドキュメントの継承関係

下位ドキュメントは上位ドキュメントで定義した項目を引き継いで具体化する。下位で新しい項目を作らない。

```text
01 プロジェクト概要 ─ 定義: 要件(REQ)
 ├─→ 02 企画レビュー ─ 定義: 意思決定(DC), 改善提案
 │      └─→ 03
 └─→ 03 サービス構造 ─ 定義: ユーザー種別(UT), 主要機能(FN)
        ├─→ 04 フローチャート 定義: フロー(FL)     参照: FN, UT
        ├─→ 05 IA ────────── 定義: 画面(SC)        参照: FN, FL
        │      └─→ 06 ワイヤーフレーム 定義: 画面詳細 参照: SC, FL
        └─→ 07 機能仕様 ──── 定義: 仕様(FS)        参照: FN, SC, DC
08 レビュー結果 ──────── 定義: 課題(IS)            参照: 04〜07 の整合性
```

| ドキュメント | 上位 | ここで定義する内容 | 上位から引き継ぐ項目 |
| --- | --- | --- | --- |
| 01 プロジェクト概要 | なし | 要件(REQ)、範囲、対象ユーザー | なし |
| 02 企画レビュー | 01 | 意思決定(DC)、改善提案 | REQ、範囲 |
| 03 サービス構造 | 01, 02 | ユーザー種別(UT)、主要機能(FN) | REQ、DC |
| 04 フローチャート | 03 | フロー(FL) | FN、UT |
| 05 IA | 03, 04 | 画面(SC)、メニュー構造 | FN、FL |
| 06 ワイヤーフレーム | 05, 04 | 画面ごとの構成・動作・例外 | SC、FL |
| 07 機能仕様 | 03, 05, 06, 02 | 機能仕様(FS) | FN、SC、DC |
| 08 レビュー結果 | 04, 05, 06, 07 | 課題(IS)、修正事項 | FL、SC、FS |

### 識別子の体系

識別子は `_data/trace.yaml` で一度だけ定義し、ドキュメントでは参照のみ行う。
一度付与した識別子は変更しない。項目を削除しても再利用しない。

| 接頭辞 | 項目 | 定義するドキュメント |
| --- | --- | --- |
| REQ | 要件 | 01 |
| DC | 意思決定事項 | 02 |
| UT | ユーザー種別 | 03 |
| FN | 主要機能 | 03 |
| FL | ユーザーフロー | 04 |
| SC | 画面 | 05 |
| FS | 機能仕様 | 07 |
| IS | レビュー課題 | 08 |
| CH | 変更履歴 | `_data/changes.yaml` |

画面 ID は `{チャネル}-{業務}-{種別}` 形式を用いる。例: `ADM-EVNT-LIST`

### 整合性チェック

ダッシュボード生成時に以下を点検する。違反項目は対応すべきドキュメントとあわせてコンソールに出力する。

| 点検 | 対応ドキュメント |
| --- | --- |
| 要件(REQ)がどの機能(FN)にも接続されていない | 03 |
| 機能(FN)がどのフロー(FL)にも含まれていない | 04 |
| 機能(FN)に画面(SC)がない | 05 |
| 画面(SC)がどのフロー(FL)にも現れない | 04 |
| 画面(SC)のワイヤーフレームが未着手 | 06 |
| 画面(SC)に機能仕様(FS)がない | 07 |
| 存在しない ID を参照している | 定義の不一致 |

### ドキュメントの状態と進捗

`_data/documents.yaml` のドキュメント項目に以下の値を記載する。

| 項目 | 値 | 説明 |
| --- | --- | --- |
| status | 未着手 / 作成中 / レビュー中 / 確定 | 作業状態 |
| category | 企画 / 設計 / 仕様 / レビュー | ドキュメント分類。ダッシュボードにタグで表示 |
| progress | 0〜100 | 作業進捗。状態が「確定」なら 100 として扱う |
| eta | 2026-09-05 18:00 | 完了予定時刻。空欄なら「未定」と表示 |

```text
未着手       作成を開始していない
作成中       ドラフト作成中
レビュー中   ドラフト完了。レビュー中、または上位変更により再確認が必要
確定         レビュー完了。下位ドキュメントの基準として使用できる
```

全体進捗はドキュメント 8 件の進捗の平均である。
完了予定時間は、未完了ドキュメントのうち最も遅い完了予定時刻までの残り時間を時:分:秒で表示する。

### 調査資料

インターネット調査の結果は `research/` に原本のまま残す。
ドキュメントには調査結果をそのまま転記せず、本サービスに適用する判断に変換して `docs/02_기획검토.md` に記載する。
根拠 URL は調査原本に保持する。
