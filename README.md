# 기획 문서 작업 구조

**한국어** · [English](README.en.md) · [中文](README.zh.md) · [日本語](README.ja.md)

IT 서비스 기획 문서를 작성하고, 문서 간 연결 관계와 작업 상황을 관리하기 위한 구조다.
문서 작성 기준은 [CLAUDE.md](CLAUDE.md)를 따른다.

---

## 배경

기획 문서는 프로젝트 개요, 기획 검토, 서비스 구조, Flow, IA, 와이어프레임, 기능 명세로 나뉜다.
문서를 나누면 각 문서는 읽기 쉬워지지만, 한 문서를 고쳤을 때 다른 문서가 함께 바뀌지 않는다.

* 01에서 요구사항을 추가했는데 03의 기능 목록에는 반영되지 않는다.
* 05에서 화면을 지웠는데 07의 기능 명세에는 그 화면이 남는다.
* 04의 Flow에는 있는 화면이 05의 화면 목록에는 없다.

문서가 늘어날수록 이 어긋남을 사람이 눈으로 확인하기 어렵다.
검토 단계에서 발견하지 못하면 설계와 개발 단계에서 재작업이 발생한다.

이 저장소는 문서 사이의 연결을 문서 본문이 아닌 별도의 데이터로 관리하고,
연결이 끊긴 항목을 문서를 생성할 때마다 찾아내는 방식으로 이 문제를 다룬다.

## 목적

| 목적 | 방식 |
| --- | --- |
| 추적성 확보 | 요구사항에서 기능, Flow, 화면, 기능 명세까지 식별자로 연결한다 |
| 정합성 점검 | 연결이 끊긴 항목을 상황판 생성 시점에 자동으로 찾아낸다 |
| 작업 상황 파악 | 문서별 상태, 진행률, 변경 이력을 한 화면에서 확인한다 |
| 작성 기준 통일 | 문장, 용어, 상태명, 표기 기준을 `CLAUDE.md` 하나로 관리한다 |

문서 자체를 자동으로 만드는 것이 목적이 아니다.
사람이 판단해서 쓴 문서가 서로 어긋나지 않도록 유지하는 것이 목적이다.

## 실행 방법

### 준비

Python 3.9 이상과 PyYAML이 필요하다.

```bash
pip install pyyaml
```

### 상황판 생성

```bash
python tools/build_dashboard.py
```

`dashboard/index.html`이 생성된다. 브라우저에서 바로 열면 된다.
문서 본문이 HTML 안에 함께 들어가므로 별도의 서버가 필요 없다.

| 탭 | 내용 |
| --- | --- |
| 현황 | 전체 진행률, 문서별 진행률과 완료 예상 시각, 진행 중·대기·완료 건수 |
| 변경 이력 | 변경 항목 전체. 검색어, 상태, 출처, 문서로 필터 |

문서 항목을 선택하면 해당 문서의 본문을 상황판 안에서 바로 볼 수 있다.
Flow, IA, 아키텍처, 와이어프레임은 본문 안에서 도형으로 그려진다.

정합성 점검 결과는 화면에 넣지 않는다. 생성 명령을 실행할 때 콘솔에 출력한다.

```text
생성: dashboard/index.html (639KB, 문서 본문 포함)
전체 진행률 100% · 진행 중 0건 · 대기 0건 · 완료 8건
점검: 미결 항목 0건, 연결되지 않은 항목 0건
```

### 화면 코드 뷰어

`dashboard/wireframe.html`은 와이어프레임을 화면 단위로 확인하는 도구다.
왼쪽에서 화면을 고르면 오른쪽에 화면과 HTML이 나온다.
'코드 복사'로 해당 화면의 HTML과 CSS를 그대로 가져갈 수 있다.

### 작업 절차

1. 문서를 수정한다.
2. `_data/changes.yaml`에 변경 항목을 추가한다. 영향받는 하위 문서를 `affects`에 적는다.
3. 새로 정의하거나 바뀐 항목을 `_data/trace.yaml`에 반영한다.
4. 확인 필요·가정·의사결정 필요 항목은 `_data/issues.yaml`에 적는다.
5. `_data/documents.yaml`의 상태, 진행률, 완료 예상, 버전, 갱신일을 수정한다.
6. 상황판을 다시 생성하고, 콘솔에 나온 점검 결과를 확인한다.

상위 문서가 바뀌면 그 문서를 상속하는 모든 하위 문서의 상태를 '검토 중'으로 되돌린다.

## 구조

### 폴더 구성

```text
.
├── CLAUDE.md                  문서 작성 기준 + 운영 규칙
├── README.md                  이 문서
├── docs/                      사용자 대상 기획 문서 (최종 산출물)
│   ├── 01_프로젝트개요.md
│   ├── 02_기획검토.md
│   ├── 03_서비스구조.md
│   ├── 04_Flow.md
│   ├── 05_IA.md
│   ├── 06_Wireframe.md
│   ├── 07_기능명세.md
│   └── 08_검토결과.md
├── research/                  조사 원본. 기획 판단은 docs/02에 정리한다
├── _data/                     문서 간 연결 데이터
│   ├── documents.yaml         문서별 상태·진행률·완료 예상·상속 관계
│   ├── trace.yaml             요구사항 → 기능 → Flow → 화면 → 명세 추적 항목
│   ├── changes.yaml           변경 이력
│   └── issues.yaml            확인 필요 · 가정 · 의사결정 필요 · 정의 간 불일치
├── tools/
│   ├── build_dashboard.py     YAML + 문서 → 상황판 생성, 정합성 점검
│   └── dashboard_template.html
├── dashboard/
│   ├── index.html             상황판 (생성물)
│   ├── wireframe.html         화면 코드 뷰어 (생성물)
│   └── admin.html             내부 어드민 화면 모음 (생성물)
└── agent-system/              문서 보강 작업에 쓰는 역할별 지시서
```

`dashboard/` 아래 파일은 생성물이다. 직접 고치지 않는다.
화면을 바꿀 때는 `tools/dashboard_template.html`을 고치고 다시 생성한다.

### 문서 상속 관계

하위 문서는 상위 문서에서 정의한 항목을 가져와 구체화한다. 하위 문서에서 새 항목을 만들지 않는다.

```text
01 프로젝트 개요 ─── 정의: 요구사항(REQ)
 ├─→ 02 기획 검토 ─── 정의: 의사결정(DC), 개선 제안
 │      └─→ 03
 └─→ 03 서비스 구조 ─ 정의: 사용자 유형(UT), 주요 기능(FN)
        ├─→ 04 Flow Chart ─ 정의: Flow(FL)          참조: FN, UT
        ├─→ 05 IA ────────── 정의: 화면(SC)           참조: FN, FL
        │      └─→ 06 Wireframe ─ 정의: 화면 상세    참조: SC, FL
        └─→ 07 기능 명세 ─── 정의: 명세(FS)           참조: FN, SC, DC
08 검토 결과 ──────────── 정의: 이슈(IS)             참조: 04~07 정합성
```

| 문서 | 상위 문서 | 이 문서에서 정의 | 상위에서 가져오는 항목 |
| --- | --- | --- | --- |
| 01 프로젝트 개요 | 없음 | 요구사항(REQ), 범위, 대상 사용자 | 없음 |
| 02 기획 검토 | 01 | 의사결정(DC), 개선 제안 | REQ, 범위 |
| 03 서비스 구조 | 01, 02 | 사용자 유형(UT), 주요 기능(FN) | REQ, DC |
| 04 Flow Chart | 03 | Flow(FL) | FN, UT |
| 05 IA | 03, 04 | 화면(SC), 메뉴 구조 | FN, FL |
| 06 Wireframe | 05, 04 | 화면별 구성·동작·예외 | SC, FL |
| 07 기능 명세 | 03, 05, 06, 02 | 기능 명세(FS) | FN, SC, DC |
| 08 검토 결과 | 04, 05, 06, 07 | 이슈(IS), 수정 사항 | FL, SC, FS |

### 식별자 체계

식별자는 `_data/trace.yaml`에서 한 번 정의하고, 문서에서는 참조만 한다.
한 번 부여한 식별자는 바꾸지 않는다. 항목이 삭제되어도 재사용하지 않는다.

| 접두어 | 항목 | 정의하는 문서 |
| --- | --- | --- |
| REQ | 요구사항 | 01 |
| DC | 의사결정 사항 | 02 |
| UT | 사용자 유형 | 03 |
| FN | 주요 기능 | 03 |
| FL | 사용자 Flow | 04 |
| SC | 화면 | 05 |
| FS | 기능 명세 | 07 |
| IS | 검토 이슈 | 08 |
| CH | 변경 이력 | `_data/changes.yaml` |

화면 ID는 `{채널}-{업무}-{유형}` 형식을 쓴다. 예: `ADM-EVNT-LIST`

### 정합성 점검

상황판을 생성할 때 아래 조건을 점검한다. 위반 항목은 처리해야 할 문서와 함께 콘솔에 출력한다.

| 점검 | 처리 문서 |
| --- | --- |
| 요구사항(REQ)이 어떤 기능(FN)에도 연결되지 않음 | 03 |
| 기능(FN)이 어떤 Flow(FL)에도 포함되지 않음 | 04 |
| 기능(FN)에 화면(SC)이 없음 | 05 |
| 화면(SC)이 어떤 Flow(FL)에도 나타나지 않음 | 04 |
| 화면(SC)의 Wireframe이 미착수 | 06 |
| 화면(SC)에 기능 명세(FS)가 없음 | 07 |
| 존재하지 않는 ID를 참조함 | 정의 간 불일치 |

### 문서 상태와 진행률

`_data/documents.yaml`의 문서 항목에 아래 값을 적는다.

| 항목 | 값 | 설명 |
| --- | --- | --- |
| status | 미착수 / 작성 중 / 검토 중 / 확정 | 작업 상태 |
| category | 기획 / 설계 / 명세 / 검토 | 문서 분류. 상황판에 태그로 표시 |
| progress | 0~100 | 작업 진행률. 상태가 '확정'이면 100으로 처리 |
| eta | 2026-09-05 18:00 | 완료 예상 시각. 비우면 '미정'으로 표시 |

```text
미착수   작성을 시작하지 않음
작성 중  초안 작성 중
검토 중  초안 완료, 검토 또는 상위 문서 변경으로 재확인 필요
확정     검토 완료, 하위 문서의 기준으로 사용 가능
```

전체 진행률은 문서 8건의 진행률 평균이다.
완료 예상 시간은 미완료 문서 중 가장 늦은 완료 예상 시각까지 남은 시간을 시:분:초로 표시한다.

### 조사 자료

인터넷 조사 결과는 `research/`에 원본으로 남긴다.
문서에는 조사 결과를 그대로 옮기지 않고, 본 서비스에 적용할 판단으로 바꿔서 `docs/02_기획검토.md`에 적는다.
근거 URL은 조사 원본에 유지한다.

## 화면 구현 준비 (app/)

상황판과 화면 뷰어를 React + Vite로 다시 만들기 위한 환경이다. 지금은 빌드 설정과 빈 라우팅만 있다.

```bash
cd app
npm install
npm run dev        # 개발 서버
npm run build      # 타입 검사 + 빌드
npm run lint       # oxlint
npm run format     # prettier
```

| 폴더 | 용도 |
| --- | --- |
| `src/app` | 앱 껍데기와 라우팅 |
| `src/pages` | 주소 하나에 대응하는 화면 |
| `src/components` | 화면끼리 나눠 쓰는 조각 |
| `src/lib` | 주소 규칙 같은 순수 함수 |
| `src/styles` | 디자인 토큰과 바탕 스타일 |

색과 여백은 `src/styles/tokens.css`에만 정의한다. 값은 05 IA 공통 화면 규칙과 지금 와이어프레임에서 쓰던 것을 그대로 옮겼다.
주소 체계는 지금 상황판과 같다. `/`, `/changes`, `/doc/:no/:sec?/:flow?`, `/wireframe/:id?`.
