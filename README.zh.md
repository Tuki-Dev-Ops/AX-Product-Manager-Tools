# 策划文档工作结构

[한국어](README.md) · [English](README.en.md) · **中文** · [日本語](README.ja.md)

用于编写 IT 服务策划文档，并管理文档之间的关联关系与工作状态的结构。
文档编写标准见 [CLAUDE.md](CLAUDE.md)。

---

## 背景

策划工作分为项目概要、策划评审、服务结构、流程、信息架构、线框图、功能规格等文档。
拆分后每份文档都更易读，但修改其中一份时，其他文档不会随之更新。

* 在 01 中新增了需求，却没有反映到 03 的功能清单。
* 在 05 中删除了页面，07 的功能规格里仍然保留着该页面。
* 04 的流程中出现的页面，在 05 的页面清单中找不到。

文档越多，这类偏差越难靠人工发现。
评审阶段没有发现的问题，会在设计和开发阶段变成返工。

本仓库把文档之间的关联作为独立数据管理，而不是写在正文里，
并在每次生成文档时找出断开的关联。

## 目的

| 目的 | 方式 |
| --- | --- |
| 建立可追溯性 | 用标识符把需求 → 功能 → 流程 → 页面 → 规格串联起来 |
| 一致性检查 | 生成看板时自动找出断开的关联 |
| 掌握工作状态 | 在一个界面上确认各文档的状态、进度和变更履历 |
| 统一编写标准 | 句式、术语、状态名称、标注规则统一由 `CLAUDE.md` 管理 |

目的不是自动生成文档。
目的是让人写出的文档之间不发生偏差。

## 运行方法

### 准备

需要 Python 3.9 以上版本和 PyYAML。

```bash
pip install pyyaml
```

### 生成看板

```bash
python tools/build_dashboard.py
```

生成 `dashboard/index.html`，用浏览器直接打开即可。
文档正文已嵌入 HTML，无需另外部署服务器。

| 标签页 | 内容 |
| --- | --- |
| 状态 | 整体进度、各文档进度与预计完成时间、进行中·待办·完成件数 |
| 变更履历 | 全部变更条目，可按关键词、状态、来源、文档筛选 |

选择文档条目后，可在看板内直接查看该文档正文。
流程、信息架构、架构图、线框图会在正文中以图形绘制。

一致性检查结果不显示在界面上，而是在执行生成命令时输出到控制台。

```text
生成: dashboard/index.html (639KB, 含文档正文)
整体进度 100% · 进行中 0 件 · 待办 0 件 · 完成 8 件
检查: 未决事项 0 件, 未关联事项 0 件
```

### 页面代码查看器

`dashboard/wireframe.html` 用于按页面确认线框图。
在左侧选择页面，右侧即时显示页面和 HTML。
点击「复制代码」可直接取得该页面的 HTML 与 CSS。

### 工作流程

1. 修改文档。
2. 在 `_data/changes.yaml` 中添加变更条目，并在 `affects` 中写明受影响的下游文档。
3. 将新增或变更的标识符反映到 `_data/trace.yaml`。
4. 待确认、假设、待决策事项记入 `_data/issues.yaml`。
5. 修改 `_data/documents.yaml` 中的状态、进度、预计完成时间、版本和更新日期。
6. 重新生成看板，确认控制台输出的检查结果。

上游文档变更后，所有继承该文档的下游文档状态回退为「评审中」。

## 结构

### 目录构成

```text
.
├── CLAUDE.md                  文档编写标准 + 运作规则
├── README.md                  本文档
├── docs/                      面向客户的策划文档（最终交付物）
│   ├── 01_프로젝트개요.md        项目概要
│   ├── 02_기획검토.md            策划评审
│   ├── 03_서비스구조.md          服务结构
│   ├── 04_Flow.md               流程图
│   ├── 05_IA.md                 信息架构
│   ├── 06_Wireframe.md          线框图
│   ├── 07_기능명세.md            功能规格
│   └── 08_검토결과.md            评审结果
├── research/                  调研原始资料。策划判断整理到 docs/02
├── _data/                     文档间关联数据
│   ├── documents.yaml         各文档的状态·进度·预计完成时间·继承关系
│   ├── trace.yaml             需求 → 功能 → 流程 → 页面 → 规格的追溯条目
│   ├── changes.yaml           变更履历
│   └── issues.yaml            待确认 · 假设 · 待决策 · 定义冲突
├── tools/
│   ├── build_dashboard.py     YAML + 文档 → 生成看板，一致性检查
│   └── dashboard_template.html
├── dashboard/
│   ├── index.html             看板（生成物）
│   └── wireframe.html         页面代码查看器（生成物）
└── agent-system/              用于补全文档的角色指示书
```

`dashboard/` 下的文件是生成物，不直接修改。
需要修改界面时，修改 `tools/dashboard_template.html` 后重新生成。

### 文档继承关系

下游文档承接上游文档定义的条目并加以具体化，不在下游文档中新建条目。

```text
01 项目概要 ──────── 定义: 需求(REQ)
 ├─→ 02 策划评审 ──── 定义: 决策(DC), 改进建议
 │      └─→ 03
 └─→ 03 服务结构 ──── 定义: 用户类型(UT), 主要功能(FN)
        ├─→ 04 流程图 ──── 定义: 流程(FL)          引用: FN, UT
        ├─→ 05 信息架构 ── 定义: 页面(SC)          引用: FN, FL
        │      └─→ 06 线框图 ─ 定义: 页面细节      引用: SC, FL
        └─→ 07 功能规格 ── 定义: 规格(FS)          引用: FN, SC, DC
08 评审结果 ───────── 定义: 问题(IS)               引用: 04~07 一致性
```

| 文档 | 上游文档 | 本文档定义的内容 | 从上游承接的条目 |
| --- | --- | --- | --- |
| 01 项目概要 | 无 | 需求(REQ)、范围、目标用户 | 无 |
| 02 策划评审 | 01 | 决策(DC)、改进建议 | REQ、范围 |
| 03 服务结构 | 01, 02 | 用户类型(UT)、主要功能(FN) | REQ、DC |
| 04 流程图 | 03 | 流程(FL) | FN、UT |
| 05 信息架构 | 03, 04 | 页面(SC)、菜单结构 | FN、FL |
| 06 线框图 | 05, 04 | 各页面的构成·操作·例外 | SC、FL |
| 07 功能规格 | 03, 05, 06, 02 | 功能规格(FS) | FN、SC、DC |
| 08 评审结果 | 04, 05, 06, 07 | 问题(IS)、修改事项 | FL、SC、FS |

### 标识符体系

标识符在 `_data/trace.yaml` 中定义一次，文档中只做引用。
一旦赋予的标识符不再变更，条目被删除后也不重复使用。

| 前缀 | 条目 | 定义文档 |
| --- | --- | --- |
| REQ | 需求 | 01 |
| DC | 决策事项 | 02 |
| UT | 用户类型 | 03 |
| FN | 主要功能 | 03 |
| FL | 用户流程 | 04 |
| SC | 页面 | 05 |
| FS | 功能规格 | 07 |
| IS | 评审问题 | 08 |
| CH | 变更履历 | `_data/changes.yaml` |

页面 ID 采用 `{渠道}-{业务}-{类型}` 格式，例如 `ADM-EVNT-LIST`。

### 一致性检查

生成看板时检查以下条件，违反项与负责处理的文档一并输出到控制台。

| 检查项 | 处理文档 |
| --- | --- |
| 需求(REQ)未关联到任何功能(FN) | 03 |
| 功能(FN)未包含在任何流程(FL)中 | 04 |
| 功能(FN)没有对应页面(SC) | 05 |
| 页面(SC)未出现在任何流程(FL)中 | 04 |
| 页面(SC)的线框图尚未着手 | 06 |
| 页面(SC)没有功能规格(FS) | 07 |
| 引用了不存在的 ID | 定义冲突 |

### 文档状态与进度

在 `_data/documents.yaml` 的文档条目中填写以下值。

| 项目 | 取值 | 说明 |
| --- | --- | --- |
| status | 未着手 / 编写中 / 评审中 / 已确定 | 工作状态 |
| category | 策划 / 设计 / 规格 / 评审 | 文档分类，在看板上以标签显示 |
| progress | 0~100 | 工作进度。状态为「已确定」时按 100 处理 |
| eta | 2026-09-05 18:00 | 预计完成时刻。留空显示为「未定」 |

```text
未着手   尚未开始编写
编写中   草案编写中
评审中   草案完成，处于评审中或因上游文档变更需要复核
已确定   评审完成，可作为下游文档的依据
```

整体进度为 8 份文档进度的平均值。
预计完成时间显示为距未完成文档中最晚预计完成时刻的剩余时间，格式为时:分:秒。

### 调研资料

网络调研结果以原文保存在 `research/` 下。
文档中不直接照搬调研结果，而是转换为适用于本服务的判断，记入 `docs/02_기획검토.md`。
依据 URL 保留在调研原文中。
