# 매장 수명주기와 메뉴 복제 조사

조사일 2026-09-04. 제품 공식 문서, 법령 원문, 회계기준을 확인했다.

## 1. 상용 제품의 폐점 처리

조사한 8개 제품 중 매장을 삭제할 수 있는 것은 하나뿐이다.

| 제품 | 삭제 | 처리 방식 | 과거 데이터 |
| --- | --- | --- | --- |
| Toast | 경로 없음 | 아카이브 플래그 | 조회 시 아카이브 포함 지정이 필요하다 |
| Square | 불가. 명시 | 비활성화만. 재활성화 가능 | 이력 제공 목적으로 유지 |
| Lightspeed X-Series | 가능. 복구 불가 | 아웃렛 삭제 | 판매 데이터는 리포팅 유지. 재고는 함께 삭제 |
| Olo | 불가. 명시 | 활성, 일시 폐점, 영구 폐점 3단계 | 거래 데이터 보존이 삭제 금지의 사유 |
| Flipdish | 삭제 API 없음 | 게시 취소와 아카이브 | 주문과 감사 로그 보존 |
| 토스플레이스 | 미확인 | 약관상 해지 시 삭제가 원칙 | 미확인 |

Square는 비활성 매장을 사용자가 요청하지 않으면 숨기라고 규격에 적는다.

- https://developer.squareup.com/reference/square/enums/LocationStatus
- https://squareup.com/help/us/en/article/5580-manage-multiple-locations-with-square

Olo는 삭제를 막는 이유를 거래 데이터와 고객의 즐겨찾기 매장 정보 보존으로 밝힌다.

- https://olosupport.zendesk.com/hc/en-us/articles/46364209387931-Manage-Stores

### 상태 3단계 분리

Olo는 주문 일시 중단, 일시 폐점, 영구 폐점을 각각 다른 값으로 둔다. 주문 중단은 재개 예정 시각과 고객 안내 문구를 함께 받는다.

운영자가 수시로 바꾸는 값과 마스터 데이터 상태값을 한 필드에 합치지 않았다.

- https://olosupport.zendesk.com/hc/en-us/articles/115000122283-Enable-Your-Store-for-Online-Ordering

## 2. 매장 그룹 재배치

조사한 6개 제품 모두 그룹이나 지역 소속이 바뀔 때 과거 리포트를 어떻게 하는지 공식 문서에 적지 않았다. 전부 미확인이다.

간접 근거는 하나 확인했다. Toast는 메뉴의 매출 분류를 바꾸면 이후 리포트에는 반영되지만 이미 만들어진 리포트는 바뀌지 않는다고 명시한다.

- https://doc.toasttab.com/doc/platformguide/adminAssigningSalesCategories.html

### 회계기준

제품 문서에 답이 없어 회계기준을 확인했다.

IFRS 8 문단 29는 내부 조직 구조가 바뀌어 보고부문 구성이 달라지면 과거 기간을 재작성하도록 정한다. 정보를 구할 수 없거나 개발 비용이 과도한 경우는 예외다.

문단 30은 재작성하지 않으면 변경이 일어난 해에 신 기준과 구 기준을 모두 공시하도록 정한다.

- https://www.ifrs.org/content/dam/ifrs/publications/pdf-standards/english/2021/issued/part-a/ifrs-8-operating-segments.pdf
- https://www.kifrs.com/s/1108

### 차원 모델링

Kimball의 Type 1은 덮어쓰기로 이력을 파괴한다. Type 2는 새 행을 추가해 사실 데이터가 발생 시점의 속성에 계속 연결되게 한다. 유효 시작일, 만료일, 현재 행 표시자 세 컬럼을 요구한다.

두 관점을 함께 지원하는 방법도 제시한다. 사실 테이블에 대리키와 자연키를 함께 두어 시점 기준과 현재 기준을 모두 조회하게 한다.

- https://www.kimballgroup.com/data-warehouse-business-intelligence-resources/kimball-techniques/dimensional-modeling-techniques/type-2/
- https://www.kimballgroup.com/2005/03/slowly-changing-dimensions-are-not-always-as-easy-as-1-2-3/

## 3. 메뉴 복제

| 제품 | 방식 | 제약 |
| --- | --- | --- |
| Toast | 버전 권장. 복사 비권장 | 복사는 리포팅에 중복 항목을 만든다 |
| Square | 매장 공유와 재정의가 기본. 메뉴 복제는 별도 | 복제본은 원본과 독립 |
| Lightspeed K-Series | 공유 상태 전환 | 단방향이며 되돌릴 수 없다 |
| Olo | 복사 없음 | 본사 메뉴가 마스터. 매장은 켜고 끄기만 |
| Flipdish | 파일 내려받기와 올리기 | 복제 후 동기화 유지 여부 미확인 |
| 토스플레이스 | 매장에서 상품 불러오기 | 본사 일괄 관리 시작 후 매장 수정 불가 |

Toast는 복사를 권장하지 않는 이유를 리포팅의 중복 항목으로 밝힌다. 대안인 버전은 항목 수를 늘리지 않고 매장이 보는 버전만 바꾼다.

- https://support.toasttab.com/en/article/Copying-Menus-to-Other-Locations-Using-Multi-Location-Management
- https://support.toasttab.com/en/article/What-s-the-difference-between-a-copy-a-deep-copy-and-a-version

Square의 메뉴 복제는 복제본이 원본과 독립적으로 동작한다. 다만 외부 배달 채널은 복제 시 자동으로 붙지 않는다.

- https://squareup.com/help/us/en/article/6424-create-menus-with-square-for-restaurants

Lightspeed K-Series는 상품 상태를 로컬, 공유, 전역으로 바꾸면 되돌릴 수 없다. 공유된 메뉴는 처음 만든 매장에서만 수정된다.

- https://k-series-support.lightspeedhq.com/hc/en-us/articles/4755505361947-Sharing-menus-with-business-locations

원본과 사본을 연결하는 제품은 모두 본사 마스터 모델이다. 값만 복사하는 제품은 매장이 원본을 갖는 모델이다.

## 5. 통계의 시점 처리

대상에 따라 원칙이 갈린다.

| 구분 | 처리 |
| --- | --- |
| 국민계정 기준년 개편 | 공표 시계열 전체를 소급 개정한다 |
| 행정구역 변경 | 원 통계표는 당시 기준을 유지하고 재집계본을 별도 계열로 제공한다 |
| 산업분류 개정 | 과거 계열은 그대로 두고 연계표로 잇는다 |

한국은행은 2020년 기준년 개편에서 1953년부터 2023년까지 전 구간을 새 기준으로 다시 계산했다. 다만 연쇄가중법 도입으로 금액 수준은 조정되어도 증감률은 유지된다.

- https://www.bok.or.kr/portal/bbs/B0000501/view.do?menuNo=201263&nttId=10084504

국가데이터처는 행정구역이 바뀌어도 원 통계표를 덮어쓰지 않는다. 1990년, 2000년, 2010년 세 기준 각각으로 과거 자료를 재집계해 별도로 제공한다. 하나의 기준으로 소급 통일하지 않고 기준 시점별 계열을 병렬로 둔다.

- https://www.korea.kr/news/policyNewsView.do?newsId=148723930

국제통화기금 분기 국민계정 매뉴얼은 대규모 개정 시 전체 계열을 가능한 한 소급하되, 새 계열의 시작 시점을 명확히 알려 과거 계열과 직접 비교할 수 없음을 이용자가 알게 하라고 정한다.

- https://www.imf.org/external/pubs/ft/qna/pdf/2017/chapter12.pdf

통계법에는 소급 개정 조항이 없다. 시점 처리는 법이 아니라 작성기관의 개정 정책 영역이다.
