# 어드민 화면 UI·UX 기준 조사

조사일 2026-09-08. 국내 공공·민간에서 통용되는 관리자 화면 기준을 확인하고 본 서비스에 적용할 항목을 정리했다.

주 근거는 행정안전부가 배포하는 **KRDS(디지털 정부서비스 UI/UX 가이드라인)**이다. 국내에서 문서로 공개된 기준 중 가장 구체적이고, 웹 접근성 지침과도 이어진다.

---

## 1. 입력폼

| 항목 | 기준 | 근거 |
| --- | --- | --- |
| 라벨 | 모든 입력 칸에 라벨을 둔다. 칸 가까이 배치한다 | KRDS 텍스트 입력 필드 |
| 안내 문구 | 라벨이나 도움말을 대신할 수 없다. 값을 입력하기 시작하면 사라지기 때문이다 | 같은 문서 |
| 필수 표기 | 필수와 선택 중 수가 적은 쪽을 표시한다. 대부분 필수면 선택만 표시한다 | KRDS 입력폼 패턴 |
| 오류 메시지 | 어느 항목에서 무엇이 잘못됐는지 그 칸 옆에 적는다 | 같은 문서 |
| 모달 입력 수 | 5개 이내로 구성한다 | 같은 문서 |
| 버튼 배치 | 오른쪽 아래에 두고 제출 버튼을 가장 오른쪽에 둔다 | 같은 문서 |

## 2. 버튼

| 항목 | 기준 | 근거 |
| --- | --- | --- |
| 계층 | 주요(채운 버튼), 보조(테두리 버튼), 3차(글자 버튼) 세 단계 | KRDS 버튼 |
| 강조 개수 | 한 화면에 주요 버튼은 하나만 둔다 | 같은 문서 |
| 문구 | 실행되는 기능을 예측할 수 있는 동사형으로 적는다. 저장, 삭제, 닫기 | 같은 문서 |
| 크기 | 한 묶음 안에서는 같은 크기를 쓴다 | 같은 문서 |
| 최소 조작 영역 | 마우스 17×17px, 터치 44×44px 이상 | 같은 문서 |

확인과 취소의 순서는 국내 모바일과 웹에서 긍정 동작을 오른쪽에 두는 쪽으로 굳어졌다.
KRDS도 제출 버튼을 가장 오른쪽에 두도록 한다.

## 3. 표

| 항목 | 기준 | 근거 |
| --- | --- | --- |
| 숫자 열 | 오른쪽 정렬한다. 수를 비교하기 쉽다 | KRDS 표 |
| 날짜·우편번호·전화번호 | 왼쪽 정렬한다. 수가 아니라 식별 값이다 | 같은 문서 |
| 행 높이 | 셀 안 글자가 3줄을 넘지 않게 한다. 행 사이 간격을 준다 | 같은 문서 |
| 빈 셀 | 대시(-)를 넣어 값이 없음을 알린다. 비워 두지 않는다 | 같은 문서 |
| 대량 데이터 | 정렬, 검색, 필터, 페이지 이동을 함께 제공한다 | 같은 문서 |
| 좁은 화면 | 단순한 표는 세로로 쌓고, 복잡한 표는 첫 열을 고정하고 가로로 스크롤한다 | 같은 문서 |
| 접근성 | thead, th, scope, caption을 갖춘다 | 같은 문서 |

## 4. 본 서비스에 적용할 판단

| 항목 | 적용 |
| --- | --- |
| 필수 표기 | 화면마다 필수와 선택 중 적은 쪽만 표시한다. 등록 화면은 대부분 필수이므로 선택 항목에만 '(선택)'을 적는다 |
| 주요 버튼 | 한 화면에 하나만 둔다. 나머지는 보조 버튼으로 내린다 |
| 표 정렬 | 숫자만 오른쪽으로 둔다. 우편번호, 사업자번호, 지점번호, 날짜, 시각은 왼쪽에 둔다 |
| 빈 값 | 표의 빈 셀에 대시를 넣는다 |
| 모달 입력 수 | 탭으로 나눠 한 화면의 입력 수를 줄인다. 상권 등록은 정보·계정·매장·히스토리로 나눈다 |
| 조작 영역 | 어드민 버튼 높이 40px를 유지한다. 키오스크는 44px 이상을 적용한다 |
| 안내 문구 | 라벨을 대신하지 않는다. 지금 구조를 유지한다 |

모달 입력 5개 기준은 상권 등록에서 지키지 않는다. 브랜드 정보와 본사 사업자 정보, 정산계좌는
한 번에 받아야 하고, 탭으로 더 쪼개면 저장 시점이 갈려 반쪽짜리 상권이 남는다. 정보 탭 안에서
'본사 정보' 구역으로 나누고, 계정·매장·히스토리를 탭으로 분리하는 선까지만 적용한다.

표 정렬 기준을 적용하면서 표 데이터에서 오류를 찾았다. 금액의 천 단위 구분이 셀 구분 쉼표와
섞여 열이 밀린 행이 11개 있었다. 셀 구분은 '쉼표 뒤 공백'으로 바꾸고 괄호 안 쉼표는 나누지
않도록 고쳤다.
