# 조사 자료 — 키오스크 및 외부 POS 연동

조사일 2026-09-03. 02 기획 검토의 근거 자료다. 기획 판단은 `docs/02_기획검토.md`에 정리한다.

조사 대상: 오케이포스 뉴키오스크 공식 매뉴얼, 토스플레이스 공식 가이드 및 개발자 문서, 페이히어 도움말, Toast POS, Square for Restaurants.

POS 내부 기능은 과업 범위 밖이다. 7절에 참고용으로만 분리했다.

## 2. 키오스크 주문 흐름

```text
대기화면
 ├─ 설정 '이미지'   → 대기화면 표시 → 터치
 └─ 설정 '상품선택' → 대기화면 생략
 ↓
매장·포장 선택
 ├─ '먹고가기/포장' → 선택 화면 표시
 ├─ '먹고가기만'    → 생략, 먹고가기 확정
 ├─ '포장만'        → 생략, 포장 확정
 └─ '테이블선택'    → 테이블 선택 화면 추가
 부수 효과: 포장 할인가 적용, 취식유형 전용 상품 숨김
 ↓
카테고리·메뉴 선택
 품절 상품 → '품절' 표시 또는 숨김
 판매시간 외·일판매수량 소진 상품 → 미노출
 ↓
옵션 선택
 ├─ 필수 옵션 있음 → 팝업 자동 표시, 미선택 시 진행 불가
 └─ 필수 옵션 없음 → 단계 생략
 최소·최대 선택 수 검증 → 수량 지정 → 담기
 ↓
장바구니
 수정 / 삭제 / 더 담기 / 상품 추천 팝업
 ↓
주문 내역 확인
 └─ 진동벨 수기입력 설정 시 → 진동벨 번호 입력 화면 삽입
 ↓
할인·적립
 포인트(휴대폰번호 입력 또는 건너뛰기) / 쿠폰 / 선불권
 적용 순서: 쿠폰 → 선불권 → 포인트
 ↓
결제수단 선택
 ├─ 카드      → 카드 결제
 ├─ 간편결제  → QR·바코드 스캔
 ├─ 현금      → 현금영수증 입력
 └─ 모바일쿠폰 → 쿠폰 바코드 스캔
 ↓
결제 처리
 ├─ 승인 성공 → 다음 단계
 └─ 승인 실패 → 오류 메시지 → 결제수단 선택으로 복귀
 ↓
고객 호출 정보 입력 (설정된 방식 1개)
 ├─ 주문번호     → 화면 표시
 ├─ 진동벨 자동배출
 ├─ 닉네임       → 랜덤 발급
 └─ 휴대폰번호   → 입력 + 최초 1회 약관 동의
 ↓
주문번호 출력 / 완료
 영수증 출력(출력 여부 팝업 또는 자동)
 교환권 출력(설정 시)
 주방 주문서 출력 또는 KDS 전달
 알림톡 발송(휴대폰번호 방식)
 ↓
대기화면 복귀
```

## 3. VAN 결제 처리 순서

### 카드 결제

1. 결제수단 '신용카드' 선택을 받고 결제 금액을 확정한다.
2. 키오스크가 VAN사 로컬 에이전트를 호출한다. VAN 서버와 직접 전문을 주고받지 않고 에이전트가 카드 단말을 제어하는 구조가 표준이다.
3. 고객이 IC 리더기에 카드를 삽입한다. 접촉, 비접촉, QR·바코드가 입력 채널로 존재한다.
4. 5만원 초과 시 할부 개월 수를 입력한다. 승인 요청 전 단계다.
5. 승인 요청 전문을 전송한다. 타임아웃은 30초를 권장한다.
6. 승인 응답을 수신한다.
7. 5만원 초과 시 사인패드에서 서명을 받는다. 5만원 이하는 무서명 처리한다.
8. 영수증을 출력한다.
9. 주방 주문서를 출력하거나 KDS로 전달한다.
10. 주문번호를 표시하고 진동벨 배출 또는 알림톡을 발송한다.

### 간편결제

1. 결제수단에서 간편결제를 선택한다.
2. 고객이 앱에서 바코드·QR을 제시한다. 고객이 제시하고 매장이 스캔하는 방식이다.
3. 키오스크가 내장 카메라 또는 스캐너로 스캔한다.
4. 간편결제사가 실물 카드정보를 대체하는 일회용 카드번호를 생성한다.
5. VAN이 이를 카드사로 전달해 일반 카드 승인과 동일 경로로 처리한다.
6. 승인 결과가 VAN을 거쳐 키오스크로 회신된다.

일회용 바코드는 재사용할 수 없다. 지원 간편결제 종류는 VAN사마다 다르다.

### 현금 결제

1. 결제수단에서 현금을 선택한다.
2. 현금영수증 발급 유형을 선택한다. 소득공제(휴대폰번호·주민등록번호·현금영수증 카드), 지출증빙(사업자등록번호·지출증빙 카드), 미발급, 자진발급 중 하나다.
3. 승인 후 영수증을 출력한다.

### 취소와 망취소

1. 일반 취소는 관리자 모드의 거래내역에서 대상 영수증을 선택해 환불한다. 원 결제수단을 리더기에 접촉한다.
2. 취소 키는 원승인번호와 원승인일자 조합이다.
3. 5만원 이상은 취소 시에도 서명이 필요하다.
4. 망취소는 세 가지 상황에서 반드시 호출한다. 응답 타임아웃, 승인 요청 중 연결 단절, 응답을 받았으나 성공 여부를 판단할 수 없는 경우다.
5. 망취소 요청은 원 승인 요청과 동일한 데이터를 재사용한다.
6. 승인은 성공했으나 금액이 불일치하거나 저장에 실패한 경우에도 취소가 필요하다.
7. VAN 채널 취소에는 부분취소 금액 필드가 없다. 부분취소는 미지원으로 읽힌다.
8. 키오스크 결제 건을 POS에서 취소하려면 VAN 본사에 교차 취소 신청이 필요하다.

## 4. 주문 상태값

### 제품별 실제 용어

| 제품 | 상태값 |
| --- | --- |
| 오케이포스 KDS (조리상태만) | 조리전 ↔ 조리완료 |
| 오케이포스 KDS (조리 및 서빙) | 조리전 ↔ 조리완료 ↔ 서빙완료 |
| 토스 POS 주문현황 | 호출 / 완료 |
| Toast KDS | Sent → Fulfilled, 되돌림 시 Recalled |
| Square KDS | Open → Completed, 되돌림은 Recall |

### 공통분모

```text
주문 접수 (결제 완료 시점에 주방 전달)
 ↓
조리 전
 ↓
조리 완료
 ↓
[선택] 서빙 완료   ※ 후불 홀 매장에서만 사용
 ↓
고객 호출 → 픽업 완료
```

조리 중이라는 중간 상태는 표준이 아니다. 조사한 제품 모두 2단계 토글이 기본이고, 서빙완료를 더한 3단계가 최대다. 주방 전달 트리거는 결제 완료 시점이다. 취소는 별도 종료 상태로 존재하되 모든 제품이 KDS에 독립 상태로 표시하지는 않는다.

### 주방 전달 경로

| 방식 | 라우팅 단위 | 보편성 |
| --- | --- | --- |
| 주방프린터 출력 | 상품-프린터 연결. 미연결 상품은 출력되지 않는다 | 대부분 |
| 주방프린터 출력 | 카테고리·상품·테이블 단위 지정 | 대부분 |
| KDS 화면 표시 | 기기별 표시 메뉴 설정 | 일부 |
| KDS 주문 채널 필터 | 포스·키오스크·배달 중 표시 대상 선택 | 일부 |

## 5. 외부 POS 연동 구조

우리 ERP가 마스터이고 POS가 받아가는 구조를 만든다. 아래는 국내외 POS가 실제로 외부에서 매장·메뉴를 받는 방식이다.

### 연동 모델 세 가지

| 모델 | 동작 | 채택 제품 | 보편성 |
| --- | --- | --- | --- |
| 본사 대시보드에서 매장 일괄 배포 | 본사에서 등록·수정 후 적용 버튼으로 하위 매장에 일괄 반영한다. 적용 후 매장에서 개별 수정할 수 없다 | 토스플레이스, 페이히어 | 대부분 (프랜차이즈 제품) |
| 웹 마스터를 단말이 읽어감 | 상품·설정은 웹에 저장하고 단말은 클라이언트다. 변경 후 단말 재시작 시 반영한다 | 오케이포스 | 대부분 (국내 전통 POS) |
| 공개 API와 웹훅 | 외부 시스템이 매장·상품을 조회하고 변경 시 웹훅을 받는다 | 토스플레이스, Square, Toast | 일부 |

### 갱신 시점

| 방식 | 제품 | 문서 표현 |
| --- | --- | --- |
| 즉시 반영 | 토스플레이스 | 변경한 상품, 카테고리, 옵션 정보가 매장에 즉시 반영된다 |
| 즉시 반영 | 페이히어 | 본사에서 한 번 수정하면 전 지점 포스에 즉시 반영된다 |
| 단말 재시작 시 반영 | 오케이포스 | 웹에서 변경한 내용을 키오스크에 적용하려면 재부팅이 필요하다 |
| 웹훅 | 토스플레이스 | 상품 생성·수정·삭제, 매장 수정 이벤트 |
| 웹훅 또는 주기 폴링 | Square | 카탈로그 버전 변경 이벤트 또는 변경 시각 기준 조회 |
| 폴링 | Toast | 메뉴 최종 수정 시각 조회 후 변경 시에만 내려받는다 |
| 오프라인 복구 시 수신 | Final POS | 오프라인이던 단말은 다시 연결될 때 업데이트를 받아온다 |

수동 전송 버튼을 둔 제품은 확인되지 않았다. 가장 가까운 것이 토스플레이스의 변경사항 적용하기 버튼이다.

### 토스플레이스 공개 API

국내에서 확인된 유일한 공개 규격이다. 조회 전용이며 등록·수정 엔드포인트가 없다. 문서는 용도를 ERP·CRM 연동, 매출 분석, 재고 관리, 회계 연동으로 명시한다. 즉 POS가 마스터이고 외부가 구독자인 구조로 문서화되어 있다.

제공 리소스는 매장 정보, 상품 목록·단건·복수건·검색, 카테고리, 옵션이다.

| 리소스 | 주요 항목 |
| --- | --- |
| 매장 | 상호, 사업자번호, 표시명, 대표자명, 전화번호, 주소, 위경도, 영업시간(요일별 시작·종료, 익일은 24시 이상으로 표기) |
| 상품 | 카테고리, 상품명, 코드, 상태, 사용 여부, 가격, 옵션, 취식유형, 라벨, 이미지 |
| 카테고리 | 제목, 코드, 사용 여부, 정렬 순서 |
| 옵션 | 제목, 선택지, 필수 여부, 최소·최대 선택 수 |

웹훅 규약은 다음과 같다. 서버가 등록된 주소로 POST를 보내고 수신 측은 2xx를 반환해야 한다. 최소 한 번 전달을 보장하므로 동일 이벤트가 재전송될 수 있고, 전달 식별자를 멱등성 키로 사용해야 한다. 타임스탬프와 서명 헤더로 위조를 검증한다. 특정 주소에서 실패가 반복되면 전송을 중단할 수 있다.

### 매장별 커스터마이징

| 항목 | 동작 |
| --- | --- |
| 매장별 가격 차등 | 동일 상품이라도 매장별로 다른 가격을 설정할 수 있다 |
| 매장별 노출 제어 | 상품·옵션의 채널별 노출 여부를 매장 단위로 설정한다 |
| 관리 권한 위임 | 일부 매장은 본사 관리 대상에서 제외할 수 있다 |
| 매장 편집 잠금 | 본사 관리 시작 후 매장에서 수정할 수 없다 |
| 적용 전 확인 | 매장 적용 전 변경 내역을 다시 확인한다 |
| 최초 등록 | 기존 매장 상품 불러오기 또는 엑셀 일괄 업로드 |

Square는 매장별로 가격, 품절, 재고 추적을 덮어쓰는 구조를 명시적으로 제공한다. 또한 마스터 카탈로그가 어느 쪽인지 먼저 정하고 단방향으로 동기화하라고 문서에서 요구한다.

### 채널 간 상품 마스터 공유

| 사실 | 근거 |
| --- | --- |
| POS에 등록한 상품이 키오스크·테이블오더에 공유된다 | 토스플레이스 |
| 키오스크 단독 운영이어도 메뉴 관리는 POS에서 한다 | 토스플레이스 |
| 상품 마스터와 화면 배치는 별개다. 상품 추가 후 화면 등록을 따로 해야 노출된다 | 오케이포스 |
| 품절 상태는 실시간 반영, 상품·가격 변경은 재시작 필요 | 오케이포스 |

### 배달 플랫폼 연동

배달앱 메뉴와 POS 메뉴를 수동으로 일치시키는 것이 전제다. POS 품절이 배달앱에 자동 반영되는 기능은 일부 제품에만 있다. 배민·쿠팡이츠·요기요의 공식 연동 규격은 로그인이 필요해 확인하지 못했다.

## 6. 예외 처리

| 상황 | 처리 |
| --- | --- |
| 결제 승인 실패·카드 거절 | 오류 메시지 표시 후 결제수단 선택으로 복귀한다. 화면 분기를 공식 문서화한 제품은 확인되지 않았다 |
| 승인 응답 타임아웃 (30초 초과) | 망취소를 호출한다. 원 승인 요청과 동일 데이터를 재사용한다 |
| 승인 중 통신 단절 | 망취소를 호출한다 |
| 승인 응답 파싱 실패 | 성공 여부를 판단할 수 없으므로 망취소를 호출한다 |
| 승인 성공 후 저장 실패 | 취소 처리한다 |
| 승인 성공 후 금액 불일치 | 취소 처리한다 |
| 키오스크와 메인 단말 네트워크 단절 | 연결 실패 메시지를 표시한다. 같은 IP 대역이어야 하며 고정 IP를 권장한다 |
| 인터넷 오프라인 | Toast는 40초 후 오프라인 모드로 들어간다. 현금과 카드는 가능하나 기프트카드·적립은 비활성이다. 카드는 암호화 저장 후 복구 시 승인한다. 복구 후 거절되면 재처리할 수 없고 가맹점 책임이다. Square는 거래당 한도와 기기별 업로드 제한을 두며 오프라인 중에는 거절 알림이 없다 |
| 품절 | 기본은 품절 표시, 설정 시 화면에서 숨긴다 |
| 주문 중 타 기기에서 품절 발생 | 고객이 상품 선택 화면에 머무는 동안 일시적으로 품절 표시된다. 대기화면으로 돌아갔다 오면 숨김 처리된다 |
| 일 판매수량 소진 | 해당 상품을 품절 처리한다 |
| 주방프린터 장애·용지 없음 | 상태 체크를 설정하면 실시간 알림을 표시한다. 지원 기종이 한정된다. 미설정 시 감지하지 않는다 |
| 주방 주문서 메뉴 누락 | 상품이 프린터에 연결되지 않으면 출력되지 않는다 |
| 주문 중 이탈·타임아웃 | 자동 복귀 타임아웃 값은 공식 문서에서 확인되지 않았다. 결제 전 이탈 주문은 데이터로 남아 별도 조회할 수 있다 |
| 분할 결제 중 일부 취소 | 결제 내역에 표시가 남고 이어서 결제할 수 있다 |
| 웹훅 전송 실패 반복 | 서버가 전송을 중단할 수 있다. 수신 측은 전달 식별자로 멱등 처리해야 한다 |

## 7. 참고: 과업 범위 밖 (POS 내부 기능)

우리가 만들지 않는다. 연동 시 POS가 이미 무엇을 갖고 있는지 파악하는 용도로만 참조한다.

테이블 관리, 주문 등록, 주문 임시저장, 분할 결제, 분할 결제 취소, 결제수단 변경, 할인, 시재 관리, 개시·마감 정산, 영수증 재발행, 전자영수증, 결제내역 조회, 매출 조회, 계산서 출력, 주방주문서 재출력, 현금영수증 자진발급, 계좌이체 결제, 배달앱 연동, 예약 관리.

Toast와 Square는 매입 전 취소와 매입 후 환불을 구분한다. Square는 이미 제공된 것의 금액만 제거하는 처리를 별도로 둔다.

## 8. 조사 한계

1. 키오스크 주문 이탈 타임아웃 값과 결제 거절 시 화면 분기는 국내외 어느 제품도 공식 문서화하지 않아 근거를 확보하지 못했다.
2. 배민·쿠팡이츠·요기요의 공식 POS 연동 규격은 로그인이 필요해 확인하지 못했다.
3. VAN 전문 규격은 전 VAN사가 비공개다. 공개된 것은 TTA 표준 문서 1건뿐이다.
4. 페이히어, 오케이포스, 티오더, 하이오더의 공개 API는 확인 범위 내에서 존재하지 않는다.
