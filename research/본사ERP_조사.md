# 조사 자료 — 본사 ERP, 매장·메뉴·통계

조사일 2026-09-03. 02 기획 검토의 근거 자료다. 기획 판단은 `docs/02_기획검토.md`에 정리한다.

조사 대상: 오케이포스, 토스플레이스, 페이히어, 배달의민족 셀프서비스, 티오더, 도도포인트, 캐시노트, Toast, Square, Oracle Simphony 및 Simphony Venue Management. 법령은 원문을 확인했다.

## 0. 제시된 계층 구조의 검증 결과

`행사 > 상권 > 직영(지점) > 메뉴` 계층을 실제 제품과 대조했다.

| 전제 | 검증 결과 |
| --- | --- |
| 행사를 최상위 컨테이너로 둔다 | 상용 제품에서 확인되지 않는다. 행사 개체 자체는 Oracle Simphony 계열에만 있고, 그것도 매장의 상위 컨테이너가 아니라 매장과 매출단위를 가로지르는 교차 차원이다 |
| 상권을 운영 계층으로 둔다 | 어떤 POS·ERP에서도 확인되지 않는다. 상권은 소상공인시장진흥공단, 서울신용보증재단, 나이스지니데이타의 분석용 지리 단위이며 운영 계층이 아니다. 실제 제품은 자유 태그 형태의 매장그룹으로 지역을 표현한다 |
| 1호점, 2호점 단위 | 확인되지 않는다. 매장코드 또는 매장그룹 태그로 표현한다 |
| 본사에서 하위 채널로 정보 배포 | 확인된다. 가장 보편적인 기능이다. 다만 배포 승인과 롤백은 거의 없다 |

실제 제품에 보편적으로 존재하는 계층은 `본사 > 브랜드 > 매장그룹(자유 태그) > 매장 > 단말`이다.

행사 단위 운영에 가장 근접한 실제 사례는 Simphony Venue Management다. `행사 > 스탠드 > 재고 > 정산` 사이클을 갖고, 행사 달력에서 행사를 초기화하고 스탠드 상태를 열고 닫으며 행사 전후 재고표와 과부족 보고서를 낸다.

기간 한정 매장을 실제 제품이 처리하는 방식은 다음과 같다.

| 방식 | 보편성 |
| --- | --- |
| 임시 매장도 새 매장으로 생성하고 종료 시 비활성화한다. 삭제는 불가하다 | 대부분 |
| 매장 유형에 이동형 구분자를 둔다. 푸드트럭과 팝업 스테이션이 예시로 나온다 | 일부 (Square) |
| 기간 한정 프로모션·할인으로 처리한다 | 일부 |
| 매장 그룹 태그로 묶는다 | 대부분 |

시작일과 종료일을 가진 매장 개체는 조사한 전 제품에서 확인되지 않았다.

| 기능 | 정의 | 보편성 |
| --- | --- | --- |
| 매장 기본정보 등록 | 매장명, 대표자명, 사업자번호, 상호, 전화, 주소를 입력해 매장코드를 생성한다 | 대부분 |
| 사업자번호 중복체크 | 동일 사업자번호 등록 매장 존재 여부를 확인한다 | 일부 |
| 매장 좌표 저장 | 위도·경도를 매장 속성으로 보관한다 | 해외 대부분. 국내 제품은 직접 입력 필드가 확인되지 않는다 |
| 영업시간·브레이크타임 | 요일별 개점·폐점 시각과 브레이크타임을 등록한다 | 대부분 |
| 휴무일·공휴일 | 국가공휴일을 일괄 불러오고 매장별 휴무일을 추가한다 | 일부 |
| 결제 단말 등록 | VAN사, 계약번호, 리더기 방식을 등록한다 | 일부 |
| 다중사업자 설정 | 한 매장에 복수 사업자와 단말 계약번호를 둔다. 푸드코트·정육식당용 | 일부 |
| 채널 사용여부 | 키오스크, QR오더, 배달, 주방 화면 사용 여부를 매장 옵션으로 켜고 끈다 | 대부분 |
| 설치 단말 수 지정 | 설치 대수를 입력하면 단말 슬롯이 자동 생성된다 | 일부 |
| 매장환경 복사 | 기존 매장 설정을 신규 매장에 복제한다. 등록 이후에는 불가하다 | 일부 |
| 매장 상태값 | 영업과 종료를 구분한다 | 대부분. 오케이포스는 오픈·폐점 2값, Square도 2값. 휴점·준비중·오픈예정은 전 제품 미확인 |
| 자동 폐점 처리 | 일정 기간 미사용 매장을 자동 폐점으로 전환한다 | 일부. 오케이포스는 오픈 후 30일간 로그인·매출이 없으면 자동 폐점한다 |
| 영업 일시중지 | 고객 화면에 준비중으로 노출하고 시간 경과 후 자동 복귀한다 | 대부분 |
| 변경 불가 항목 고정 | 용도구분, 브랜드취급, 상품분류레벨은 저장 후 변경할 수 없다. 변경하려면 폐점 후 재등록한다 | 일부 |

| 카테고리 계층 | 대·중·소 다단 분류를 둔다 | 일부. 오케이포스는 1~3단이며 매장 생성 시 고정되어 변경할 수 없다. 토스플레이스, 배민, 티오더는 1단 |

| 옵션 항목이 상품 레코드 | 옵션으로 쓸 항목을 상품으로 먼저 등록해야 한다 | 일부 |
| 세트·코스 메뉴 | 복수 상품을 묶어 단일 가격으로 판매한다 | 일부 |

| 품절 자동 해제 시각 | 품절 상태가 자동 복귀할 시각을 지정한다 | 일부 (Square만) |

| 판매가 예약 변경 | 지정 날짜부터 가격이 자동 적용되도록 예약한다 | 일부 |
| 메뉴 이미지 등록 | 상품 사진을 올린다 | 대부분 |

| 기간 한정 할인 | 기간, 요일, 시간, 대상 상품에 정률·정액 할인을 적용한다 | 일부 |
| 먹고가기·포장 전용 메뉴 | 주문 유형별로 판매 가능 상품을 분리한다 | 일부 |
| 다국어 메뉴 | 상품명과 분류명을 다국어로 등록한다 | 일부 |

### 관리축과 표시축의 분리

```text
관리축 (집계·원가용)              표시축 (화면 배치용)
상품분류 대분류                    메뉴판
 └ 중분류   ← 1~3단, 매장 생성      ├ 채널: 키오스크 / POS / QR오더
   └ 소분류    시 고정               ├ 주문유형: 먹고가기 / 포장
     └ 상품                          └ 화면 카테고리
        ├ 옵션 사용여부                  └ 화면 키 → 상품 연결 (라벨, 순번)
        ├ 판매시간 / 일판매제한
        ├ 품절여부
        └ 이미지 / 상세설명

옵션 구조 3단
 선택그룹 (예: 커피관련옵션)
  └ 선택분류 (예: 온도선택)   ← 최소·최대 선택수, 필수여부
     └ 선택상품 (예: HOT, ICE) ← 추가단가, 사용여부
```

상품을 추가해도 화면 키를 따로 등록해야 단말에 노출된다. 상품분류는 화면 구성과 별도로 관리한다.

## 3. 알레르기·영양성분

| 항목 | 내용 |
| --- | --- |
| 법정 알레르기 유발물질 | 19개 품목. 알류(가금류), 우유, 메밀, 땅콩, 대두, 밀, 고등어, 게, 새우, 돼지고기, 복숭아, 토마토, 아황산류, 호두, 닭고기, 쇠고기, 오징어, 조개류(굴·전복·홍합 포함), 잣 |
| 영양성분 표시 | 열량, 당류, 단백질, 포화지방, 나트륨 5종 |
| 표시 의무 대상 | 휴게음식점·일반음식점·제과점 중 가맹사업이고 직영점과 가맹점 합산 50개 이상 |
| 표시 대상 식품 | 대상 업소는 어린이 기호식품뿐 아니라 조리·판매하는 모든 식품에 표시한다 |
| 표시 위치 | 메뉴판, 메뉴북, 메뉴게시판, 제품안내판과 온라인 주문 시 식품명·가격 표시 주변 |
| 글자 크기 | 열량은 식품명 또는 가격 활자 크기의 80% 이상 |
| 과태료 | 영양성분 미표시 600만원 이하, 알레르기 미표시 300만원 이하 |

품목 수 표기가 자료마다 다르다. 법령 열거는 19개다. 조개류를 굴·전복·홍합으로 분해하면 21개, 조개류를 함께 세면 22개다. 18개는 잣 추가 이전 수치다.

### POS 제품의 지원 현황

조사한 국내 POS 제품의 공식 문서에서 알레르기·영양성분 필드는 확인되지 않았다. 토스플레이스 공개 API, Square, Toast, Simphony API에도 해당 필드가 없다. 배달의민족 셀프서비스만 메뉴 단위 알레르기·영양성분 입력 필드를 명시한다.

등록 단위는 메뉴 단위만 확인된다. 옵션 단위 등록은 어디에도 없다. 업계는 옵션 조합마다 완제품을 별도 상품으로 복제하는 방식을 쓴다.

원산지는 오케이포스와 토스플레이스 모두 매장 단위 자유 텍스트다. 메뉴 단위가 아니다.

## 4. 본사에서 외부 채널로 정보 제공

| 기능 | 정의 | 보편성 |
| --- | --- | --- |
| 읽기 전용 조회 API | 외부에 매장·메뉴를 조회로만 노출한다. 쓰기는 제공하지 않는다 | 대부분 |
| 매장 단위 스코핑 | 경로에 매장 식별자를 넣어 매장별로 조회한다 | 대부분 |
| 엔티티별 분리 조회 | 상품, 분류, 옵션, 세트를 각각 독립 리소스로 제공한다 | 대부분 |
| 매장 단위 통 스냅샷 | 메뉴 전체 계층을 한 번에 해석된 형태로 제공한다 | 일부 (Toast) |
| 게시 후에만 노출 | 작업 중 변경은 외부에 보이지 않고 게시해야 반영된다 | 일부 (Toast) |
| 변경 통지 웹훅 | 변경 발생 시 외부에 이벤트를 보낸다 | 대부분 |
| 증분 조회 | 마지막 동기 시각 이후 변경분만 조회한다 | 일부. Square만 명시적이다. 토스플레이스는 페이지 단위만 있고 변경 시각 필터가 확인되지 않는다 |
| 주기 폴링 | 정해진 주기로 단말이 마스터를 내려받는다 | 일부 |
| 단말 재실행 시 반영 | 저장 후 단말을 재시작해야 적용된다 | 국내 설치형에서 대부분 |
| 무인 매장 자동 반영 | 재실행 없이 유휴 시점에 마스터를 자동 수신한다 | 일부. 대기화면 10분 무조작 또는 결제 완료 후 대기화면 전환 시 반영한다. 키오스크 단독 운영 매장에 한정된다 |
| 즉시 반영 | 저장 즉시 단말에 반영한다 | 클라우드형에서 대부분 |
| 수동 적용·전송 버튼 | 저장과 별개로 배포를 명시적으로 실행한다 | 대부분 |
| 일괄 배포 범위 선택 | 브랜드 전체, 본사에서 특정 매장, 매장에서 매장 | 일부 |
| 병합 정책 선택 | 미선택 항목을 삭제할지 유지할지 지정한다 | 일부 |
| 채널별 노출 제어 | 채널별로 노출 항목을 서버가 필터링한다 | 일부 |
| 채널 간 품절 연동 | 한 채널의 품절이 다른 채널에 함께 반영된다 | 일부 |
| 인증 방식 | 접근 키와 비밀 키 헤더 쌍. 웹훅은 서명과 멱등키 | 대부분 |
| 배포 승인 워크플로 | 본사 배포를 가맹점이 승인한다 | 확인되지 않는다. 국내외 14개 제품 전부 미확인이며, 사전 권한 설정(본사통제·매장통제)으로 대체한다 |
| 배포 이력·버전·롤백 | 배포 버전을 보관하고 되돌린다 | 거의 없다. Toast는 되돌릴 방법이 수동 재변경 후 재게시뿐이라고 문서에 명시한다 |

역방향 승인은 존재한다. 매장이 정보변경을 요청하면 상위에서 확정 처리하고, 매장 프로그램 재시작 시 반영된다.

### 외부 채널이 실제로 받아가는 정보 항목

토스플레이스 공개 API 기준으로 확인된 필드다.

| 리소스 | 항목 |
| --- | --- |
| 매장 | 식별자, 상호, 표시명, 사업자번호, 대표자명, 전화번호, 주소, 위도, 경도, 영업시간(요일, 시작, 종료), 속성 |
| 메뉴 | 식별자, 매장 식별자, 제목, 코드, 분류, 상태(판매중·품절), 사용 여부, 노출 일정, 정렬 순서, 설명, 이미지, 라벨, 가격(가격 유형, 가격, 바코드), 가격 변형, 취식유형, 옵션, 생성·수정 시각 |
| 분류 | 식별자, 매장 식별자, 제목, 코드, 사용 여부, 정렬 순서, 생성·수정 시각 |

| 세트 | 기본가, 정가, 대상 그룹(최소·최대 수량, 대상 상품, 추가금, 기본값) |

이 규격에 과세구분, 원산지, 알레르기 필드는 없다. 토스플레이스는 품절 상태를 메뉴 전시를 위한 시각적 표기 정보라고 명시한다. 주문을 강제로 차단하는 제약이 아니다.

### 상권 데이터를 붙이려면 외부 결합이 필요하다

| 소스 | 공간 단위 | 제공 지표 |
| --- | --- | --- |
| 소상공인시장진흥공단 상가정보 공개 API | 지정상권, 반경, 사각형, 다각형, 행정동, 건물, 지번 | 점포 정보 중심이다. 상가업소번호, 상호명, 업종 대·중·소분류, 주소, 경도·위도, 행정동·법정동. 매출추정, 유동인구, 임대료는 이 API에 없다 |
| 서울 우리마을가게 상권분석 | 사전 구축 폴리곤. 골목상권 1,090개, 발달상권, 전통시장, 관광특구 | 점포수, 개폐업, 추정매출, 유동인구, 주거·직장인구, 임대료, 생존율, 소득분위. 분기 갱신, 2개월 지연 |
| 나이스지니데이타 | 전국 행정동을 42만 블록으로 분할 | 점포당 평균매출, 중앙값과 상·하위 20%, 결제건수, 결제단가, 메뉴 판매·가격대 |

표준 상권코드는 존재하지 않는다. 기관별로 각자 정의하고 코드를 부여한다. 공통 표준은 행정안전부 행정동코드와 법정동코드뿐이다.

매출 보존 기간은 제품마다 다르다. 오케이포스는 단말 내 조회 3개월, 매출자료 수신 90일이고 그 이전은 웹에서 조회한다.

## 6. 권한

| 역할 | 접근 범위 |
| --- | --- |
| 대리점 | 전 담당 매장. 매장 등록·폐점, VAN·단말 계약번호 등 시스템 설정. 가맹점 계정 대행 접속. 통제 옵션 변경은 대리점만 가능하다 |
| 본사 관리자 | 소속 전 브랜드·전 매장. 본사환경 옵션 고정, 마스터 메뉴 등록·배포, 통합 매출 조회 |
| 브랜드 관리자 | 지정 브랜드 소속 매장. 브랜드별 매출조회 |
| 그룹 관리자 | 배정된 매장그룹에 속한 매장만. 사원정보에서 등급과 그룹을 지정하고 메뉴 권한을 부여한다. 권한 복사는 동일 등급끼리만 가능하다 |
| 점주 | 자기 매장만. 사업자 정보는 변경할 수 있으나 VAN·단말 계약번호·오픈·폐점은 불가하다 |
| 판매원 | 허용된 기능만. 잠긴 기능은 점주 인증을 요구한다 |

권한 부여 방식의 국내 표준은 역할이 아니라 화면 단위 체크박스다. 본사정보관리와 매장환경설정 양쪽에서 각각 부여한다.

Toast는 매장 그룹을 지정하면 그룹 내 전 매장에 권한이 상속된다. 매장 접근 탭을 비우면 단말 로그인 없이 리포트만 보는 지역 관리자를 만들 수 있다. Simphony는 역할의 가시성 탭에서 구역·매장·매출단위를 지정하고 하위 전파를 체크한다.

## 7. 확인 필요

설계 판단에 직접 영향을 주는 순서로 정리한다.

1. 오케이포스 프랜차이즈 ERP 연동 표준 API 문서는 제목과 주소는 있으나 본문이 비어 있다. 우리 과제와 용도가 일치하므로 기술지원 문의로 확인을 권한다.
2. 배달 플랫폼 메뉴 연동 규격은 개발자 사이트가 없고 2차 출처가 서로 상충한다. 파트너센터 계약 경로로 1차 확인이 필요하다.
3. 토스플레이스 카탈로그에는 변경 시각 기준 증분 조회가 문서상 없다. 우리 ERP는 증분 조회를 넣어야 외부 채널의 전량 재조회를 피할 수 있다.
4. 키오스크 화면이 법령상 메뉴 등에 포함되는지 해석례가 확인되지 않았다. 법령·고시 전문에 키오스크 용어가 없다. 식약처 질의가 필요하다.
5. 매장 알레르기 표시 방법의 법령 원문 근거가 약하다. 현행 고시는 영양성분과 고카페인만 규율하고, 메뉴 주변 표시 또는 책자·포스터 일괄 표시는 안내·보도자료 수준에서만 확인된다.
6. 매장 상태값의 실무 전집합. 준비중, 휴점, 오픈예정은 국내외 14개 제품 전부 미확인이다. 필요하면 업계 관행이 아니라 우리 요구사항으로 정의해야 한다.
7. 매장 위경도 입력은 국내 제품에서 직접 입력 필드가 확인되지 않는다. 상권 분석과 결합하려면 우리가 설계해야 한다.

제품별 미확인 항목은 유니온포스 전 항목, 하이오더 매뉴얼 비공개, 아이오더 설정 매뉴얼 텍스트 추출 실패, 페이히어 권한 등급명이다.

## 8. 조사 방법상 주의

조사 중 요약 오류 1건을 검출했다. 토스플레이스 매출 페이지에 객단가와 요일별 지표가 있다는 1차 추출이 나왔으나 재확인 결과 문서에 없었다. 본문이 전부 이미지인 사이트는 반복 조회 시 값이 매번 달라져 전량 배제했다. 이 자료의 인용은 재검증을 통과한 것만 실었다.
