# 결제·정산 규제 조사

조사일 2026-09-04. 1차 출처는 국가법령정보센터 조문, 금융위원회 보도자료와 보도설명자료, 각 결제대행사 공식 개발자 문서다.

## 1. 전자지급결제대행업 등록 의무

### 정의와 처벌

전자금융거래법 제2조 제19호는 전자지급결제대행을 "제3자 사이에서 이루어지는 재화의 공급 또는 용역의 제공에 대한 대가의 지급이 전자지급수단으로 이루어지는 경우에 그 대가를 수수하고 정산을 대행하는 것"으로 정의한다. 미등록 영업은 제49조 제5항 제5호에 따라 3년 이하 징역 또는 2천만원 이하 벌금 대상이다.

- https://casenote.kr/법령/전자금융거래법

### 등록이 필요 없는 구조

금융위원회 보도설명자료(2024. 6. 24.)가 우리가 검토한 구조를 직접 다룬다.

플랫폼이나 본사가 정산을 대행하거나 매개하면 등록 대상이다. 다만 정산업무를 외부 결제대행사가 수행하면 등록이 필요 없다고 명시한다. 자료가 든 예시는 "전문 PG사를 통해 플랫폼 입점사에게 결제대금 정산하고 플랫폼 등은 정산에 필요한 정보만을 제공"하는 경우다.

같은 자료는 신용카드 결제에도 같은 기준을 적용한다고 밝힌다.

- https://fsc.go.kr/no010102/82523

경계선은 대금 수취와 정산 대행이다. 플랫폼 계좌를 자금이 경유하거나 플랫폼이 매장별 정산금액을 산정하고 집행하면 등록 대상이 된다.

### 2024년 9월 15일 시행 개정

가맹점 범위가 확대되었다. 일반 가맹점을 위해 거래를 대행하는 자도 가맹점에 포함되며, 그 가맹점이 될 수 있는 자를 전자지급결제대행업자 또는 전자고지결제업자로 한정했다.

전자금융업자에게 미등록 결제대행사와 대표가맹점 계약을 체결하지 않을 의무가 부과되었다. 가맹점 관련 규정은 1년 유예되어 2025년 9월 15일부터 시행 중이다.

- https://yulchonllc.com/fix/2024/fix-DF-2410/PDF/2410_YC_DF_NL_10_Sub03.pdf

### 2024년 9월 9일 제도개선방안

금융위는 프랜차이즈를 명시하며 자기 사업의 일부로 대금을 수취해 내부정산하는 경우는 등록 대상이 아니도록 규정하겠다고 밝혔다.

- https://www.fsc.go.kr/no010101/83047

### 2026년 12월 17일 시행 개정

2025년 12월 16일 공포되었고 아직 시행 전이다.

- 정의에 "제3자 사이에서"가 명시되었다. 자기 사업 내부정산을 배제하는 취지다.
- 제25조의4가 신설되었다. 정산대상금액 전액을 은행 등 정산자금관리기관을 통해 신탁, 예치, 지급보증보험 방식으로 외부관리해야 한다.
- 외부관리 비율은 시행 후 60퍼센트, 1년 후 80퍼센트, 2년 후 100퍼센트로 단계 적용된다.
- 위반 시 5천만원 이하 과태료 또는 6개월 이내 업무정지다.

- https://www.korea.kr/briefing/pressReleaseView.do?newsId=156735300

### 하위가맹점 구조

구조 자체는 금지되지 않는다. 결제대행사가 카드사와 대표가맹점 계약을 맺고 각 매장을 하위가맹점으로 두는 방식이 현재 표준이다. 조건은 셋이다.

1. 대표가맹점 지위를 갖는 자가 등록 결제대행사여야 한다. 선불과 직불 영역은 2025년 9월 15일부터 법정 의무다. 카드 영역은 법정 의무가 아니라 카드사 실무 관행이다.
2. 실제 재화와 용역을 제공한 가맹점 정보를 이용자가 알 수 있게 해야 한다. 거래대행 정보를 금융회사에 제공할 의무도 있다.
3. 세무자료 제출 주체가 등록 결제대행사다. 매출은 실제 가맹점에 귀속된다.

- https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?mi=40683&cntntsId=239036

### 미확인

- 2024년 9월 15일 시행령 중 미등록 결제대행사와의 대표가맹점 계약 금지 조문 번호
- 3차 이상 다단 구조의 허용 여부와 상위 결제대행사의 확인 의무 조문

## 2. 선불전자지급수단 등록 면제 기준

### 현행 수치

전자금융거래법 시행령 제15조 제5항은 발행잔액 30억원, 연간 총발행액 500억원으로 정한다. 법 제28조 제3항 제1호 나목은 두 값을 "및"으로 연결한다. 두 요건을 모두 충족해야 면제된다.

일부 2차 자료가 "또는"으로 적었으나 조문 기준으로 "및"이 맞다.

- https://casenote.kr/법령/전자금융거래법_시행령/

### 2024년 9월 15일 시행 확대

| 기준 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 가맹점 수 | 10개 이하 면제 | 사업주가 동일한 1개만 면제 |
| 발행액 | 발행잔액 30억원 이하 | 발행잔액 30억원 미만 및 연간 총발행액 500억원 미만 |

업종 기준이 폐지되었다. 종전에는 2개 업종 이상이어야 규제 대상이었다. 전자식으로 전환된 지류식 증표도 포함된다. 특수관계인 취급이 폐지되어 모회사와 자회사에만 쓰이는 경우도 해당한다.

선불충전금 전액 별도관리 의무는 유예 없이 시행되었다. 신규 등록 대상자의 유예기간은 2025년 3월 15일 종료되었다.

금융감독당국은 면제 요건을 엄격히 해석한다. 여러 선불수단을 발행하면서 일부의 가맹점이 1개씩이라도 면제 요건에 해당하지 않는다는 법령해석이 있다.

- https://www.fsc.go.kr/no010101/82339
- https://www.fsc.go.kr/no010101/83004

### 미확인

2026년 4월 28일 대통령령 제36281호로 시행령이 개정된 사실은 확인했으나 개정 내용을 1차 출처로 확인하지 못했다. 30억원과 500억원 기준이 바뀌었다는 근거는 발견되지 않았다.

## 3. 결제 연동 표준 흐름

### 인증과 승인의 분리

조사한 4사 모두 2단계 구조다.

| 결제대행사 | 흐름 |
| --- | --- |
| 토스페이먼츠 | 결제창 호출, 성공 주소로 이동, 서버가 승인 API 호출 |
| 나이스페이먼츠 | 결제창 호출, 복귀 주소로 인증결과 수신, 서버가 승인 API 호출 |
| KG이니시스 | 결제요청, 인증결과, 승인요청, 승인결과 4단계 |
| 포트원 | 래퍼 구조. 같은 결제 식별자로 여러 번 시도할 수 있으나 성공은 한 번만 |

토스페이먼츠는 승인 유효 시간을 10분으로 두고, 그 안에 승인 API를 호출하지 않으면 결제가 만료된다고 명시한다.

- https://docs.tosspayments.com/guides/v2/get-started/payment-flow
- https://manual.inicis.com/pay/stdpay_pc.html

### 서버측 금액 검증

4사 모두 명시한다. 클라이언트에서 금액을 조작할 수 있으므로 서버가 저장한 금액과 대조한 뒤 승인해야 한다.

나이스페이먼츠는 응답 유실이 발생할 수 있어 승인금액 검증 API로 반드시 확인하라고 안내한다. 서명 규칙은 거래번호, 금액, 시각, 비밀키를 이어 해시한 값이다.

- https://docs.tosspayments.com/guides/v2/payment-widget/integration
- https://github.com/nicepayments/nicepay-manual/blob/main/api/payment-window-client.md

### 멱등키

토스페이먼츠만 범용 지원한다.

| 항목 | 내용 |
| --- | --- |
| 헤더 | Idempotency-Key |
| 최대 길이 | 300자 |
| 유효기간 | 최초 요청일부터 15일 |
| 적용 범위 | 모든 POST 메서드 API |
| 동시 요청 | HTTP 409 |

나머지 3사는 멱등키 헤더를 문서에서 확인하지 못했다. 대체 수단으로 KG이니시스는 1회용 인증토큰과 고유 주문번호를 요구하고, 응답 유실 시 망취소 주소로 요청하게 한다. 망취소 가능 시간은 인증결과 응답 후 10분이며 일반 결제취소 용도로 쓰지 말라고 명시한다.

- https://docs.tosspayments.com/guides/using-api/idempotency-key

### 웹훅

| 결제대행사 | 재전송 | 서명 검증 | 순서 |
| --- | --- | --- | --- |
| 토스페이먼츠 | 최대 7회. 1, 4, 16, 64, 256, 1024, 4096분 | 일반 결제 웹훅에는 없음 | 미확인 |
| 포트원 | 최대 5회. 0, 1, 4, 16, 64, 256분 | 제공 | 보장하지 않는다고 명시 |
| 나이스페이먼츠 | 미확인 | 결제 응답과 같은 규칙 | 미확인 |
| KG이니시스 | 미확인 | 미확인 | 미확인 |

토스페이먼츠는 10초 이내 200 응답을 요구한다. 일반 결제 웹훅에 서명 수단이 없으므로 결제 식별자로 조회 API를 다시 호출해 확인해야 한다.

포트원은 웹훅을 신뢰하지 말고 조회 API 응답만 신뢰하라고 명시한다.

- https://docs.tosspayments.com/guides/v2/webhook
- https://developers.portone.io/opi/ko/integration/webhook/readme-v2

## 4. VAN 망취소와 서명 기준

이 항목은 확인하지 못했다. 여신전문금융업법과 시행령, 감독규정 원문, 여신금융협회 자료에 접근하지 못했다.

확인이 필요한 것은 다음과 같다.

- 망취소의 법적 정의와 발동 조건
- 무서명거래 5만원 기준의 근거가 법령인지 감독규정인지 카드사 자율 정책인지
- 2024년부터 2026년 사이 기준 변경 여부
- 무서명거래 시 부정사용 책임 분담

인접 사실은 확인했다. KG이니시스는 온라인 결제에서 승인 응답 수신 실패나 저장 실패 시 망취소를 요청하도록 하며 시간을 10분으로 제한한다. 이것이 단말 망취소와 같은 것인지는 확인하지 못했다.

## 5. 하이브리드 웹앱의 결제 제약

### 앱 이동

모바일 결제는 카드사와 은행 앱으로의 이동을 전제한다. 앱 스킴을 사전 등록해야 이동이 동작한다.

- 안드로이드는 매니페스트에 카드앱과 은행앱 패키지를 등록한다. 미등록 시 앱이 설치돼 있어도 스토어로 이동한다.
- 안드로이드는 웹뷰에서 주소 가로채기를 구현해야 한다. 미구현 시 알 수 없는 스킴 오류가 발생한다.
- iOS는 정보 목록에 조회 스킴을 선언한다. iOS 27부터 등록 한도가 50개에서 25개로 줄었고 조회 함수가 폐기 예정이다. 열기 함수를 쓰면 등록과 무관하게 호출할 수 있다.
- 모바일에서 결제창을 프레임 안에 띄울 수 없다. 결제창 호출 시 항상 페이지가 이동하기 때문이다.

- https://docs.tosspayments.com/guides/v2/webview
- https://docs.tosspayments.com/blog/android-ios-webview-deeplink

### 앱스토어 미등록 웹앱의 제약

이 항목이 설계에 직접 영향을 준다.

- 복귀에 쓰는 앱 스킴 파라미터는 상점 앱의 스킴을 넣는 자리다. 스토어에 등록된 앱이 없으면 앱 복귀 경로가 없고 브라우저 리다이렉트에만 의존한다.
- 토스페이먼츠 지원 환경 표에 홈 화면에 추가한 웹앱 항목이 없다.
- iOS에서 홈 화면에 추가한 상태의 외부 앱 호출과 복귀에 관한 서술이 두 결제대행사 공식 문서에 없다. 미확인이다.
- iOS 사파리가 결제 앱 복귀 시 새 탭을 여는 문제에 대한 공식 대응 안내도 없다.
- 카카오톡과 네이버 인앱브라우저의 결제 제약도 미확인이다.

### 결과 유실

포트원은 유실을 정상 시나리오로 본다. 연결 끊김이나 브라우저 새로고침으로 응답을 받지 못하는 경우가 발생하며, 복귀 전에 앱이 종료되는 경우도 있다고 적는다. 웹훅과 수동 승인을 함께 쓰도록 권장한다.

토스페이먼츠 구조에서는 리다이렉트 실패가 승인된 상태의 결과 유실이 아니라 미승인이 된다. 승인 API를 호출해야 결제가 확정되기 때문이다. 10분이 지나면 결제 세션이 소멸해 승인이 불가하다. 미승인 건을 자동 취소하는 배치가 필요 없다.

가상계좌는 발급 응답으로 완료 처리하면 안 된다. 입금 콜백을 받고 조회 API로 확인해야 한다.

- https://developers.portone.io/opi/ko/extra/mobile-payment/readme-v2
- https://docs.tosspayments.com/blog/redirect

## 6. 정산과 대사

### 확인한 것

토스페이먼츠 지급대행은 플랫폼을 대신해 입점 판매자에게 매출을 지급하는 서비스다. 잔액을 지급 가능액과 지급 불가액으로 구분하고, 당일 지급과 지정일 지급을 선택할 수 있다. 별도 이용 신청이 필요하다.

이 구조는 플랫폼이 정산 주체가 되는 방식이다.

등록 결제대행업체는 결제대행 명세를 매 분기 말일의 다음 달 15일까지 국세청장에게 제출해야 한다. 매출은 실제 가맹점에 귀속된다.

대사에 쓸 수 있는 결제 식별자는 결제대행사마다 다르다. 토스페이먼츠는 결제 키와 주문번호, 나이스페이먼츠는 거래번호와 주문번호와 시각, KG이니시스는 주문번호와 인증토큰, 포트원은 결제 식별자다.
