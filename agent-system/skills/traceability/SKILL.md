# 추적성 검증

## 검사 사슬

```text
Requirement → Service → Function → Screen → Flow → API → Data → System
```

## 절차

### 1. 자동 검사를 돌린다

```bash
python tools/build_dashboard.py
```

출력에서 미결 항목 건수와 연결되지 않은 항목 목록을 확인한다.

자동 검사는 존재 여부만 본다. 통과했다고 검증이 끝난 것이 아니다.

### 2. 아래로 내려간다

요구사항 하나를 잡고 끝까지 따라간다.

```text
REQ-005  본사 운영자는 행사와 상권 단위로 매출을 비교할 수 있다.
 ↓ Service   매출 분석
 ↓ Function  FN-115 매출 조회, FN-116 행사·상권 비교
 ↓ Screen    ADM-SALE-LIST, ADM-SALE-COMP
 ↓ Flow      FL-103, FL-133, FL-135
 ↓ API       매출 집계 조회, 비교 조회
 ↓ Data      주문, 매출 집계, 행사, 상권
 ↓ System    집계 배치, 데이터베이스
```

한 칸이라도 비면 누락이다.

### 3. 위로 올라간다

기능 하나를 잡고 왜 존재하는지 거슬러 올라간다.

올라가지 못하는 기능은 근거 없는 기능이다. 두 가지 중 하나다. 요구사항이 빠졌거나, 필요 없는 기능이다. 어느 쪽인지 판단해서 적는다.

### 4. 중복을 찾는다

이름이 다르다고 다른 기능이 아니다. 아래가 같으면 중복이다.

- 대상 사용자
- 입력과 결과
- 조작하는 데이터

중복으로 판정하면 어느 이름을 남길지 제안한다. 임의로 합치지 않는다.

### 5. 용어를 대조한다

같은 개념에 다른 용어를 쓰고 있지 않은지 본다. 문서별로 같은 대상을 가리키는 단어를 모아 비교한다.

| 개념 | 01 개요 | 03 구조 | 05 IA | 07 명세 |
| --- | --- | --- | --- | --- |
| 주문한 사람 | 고객 | 고객 | 고객 | 주문자 |

한 줄에 두 개 이상의 단어가 나오면 불일치다.

## 판정

| 판정 | 기준 |
| --- | --- |
| 정상 | 요구사항부터 시스템까지 연결된다 |
| 누락 | 요구사항은 있으나 기능이 없다 |
| 불일치 | 기능은 있으나 Flow에 없다 |
| 중복 | 같은 기능이 다른 이름으로 있다 |
| 확인 필요 | 요구사항만으로 판단할 수 없다 |

## 보고 형식

```text
[누락] REQ-012 매장 운영자가 정산 내역을 확인할 수 있어야 한다
  기능 없음. 화면 없음.
  근거: docs/07_기능명세.md 에 정산 관련 기능이 없다.
  조치 제안: 기능 정의 또는 범위 제외 결정
```

판정, 대상, 사실, 근거 위치, 조치 제안 순으로 적는다. 사실과 제안을 섞지 않는다.

## 검증 제외

아래는 연결되지 않아도 정상이다. 다만 그렇다는 사실을 적는다.

- 아직 착수하지 않은 문서에 걸린 항목
- 범위에서 제외하기로 결정한 요구사항
- 다른 시스템이 담당하는 기능
