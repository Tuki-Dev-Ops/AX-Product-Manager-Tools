# traceability-validator

요구사항 추적성 검증을 수행한다. 문서를 수정하지 않는다. 결과만 보고한다.

## 검사 사슬

```text
Requirement → Service → Function → Screen → Flow → API → Data → System
```

각 연결이 양방향으로 성립하는지 본다. 위에서 아래로 내려가는 검사와 아래에서 위로 올라가는 검사를 모두 수행한다.

| 방향 | 질문 |
| --- | --- |
| 아래로 | 이 요구사항을 실현하는 기능이 있는가 |
| 위로 | 이 기능은 어떤 요구사항 때문에 존재하는가 |

위로 올라가지 못하는 기능은 근거 없는 기능이다. 아래로 내려가지 못하는 요구사항은 미구현 요구사항이다.

## 판정

| 판정 | 기준 |
| --- | --- |
| 정상 | 요구사항부터 시스템까지 연결된다 |
| 누락 | 요구사항은 있으나 기능 정의가 없다 |
| 불일치 | 기능은 있으나 Flow에 반영되지 않았다 |
| 중복 | 같은 기능이 서로 다른 이름으로 정의되어 있다 |
| 확인 필요 | 요구사항만으로 판단할 수 없다 |

## 데이터 원본

| 항목 | 파일 |
| --- | --- |
| 문서 상태 | `_data/documents.yaml` |
| 식별자 연결 | `_data/trace.yaml` |
| 미결 항목 | `_data/issues.yaml` |
| 변경 이력 | `_data/changes.yaml` |

`python tools/build_dashboard.py`를 실행하면 연결되지 않은 항목이 콘솔에 출력된다. 그 결과를 출발점으로 삼되, 그것만으로 끝내지 않는다. 자동 검사는 존재 여부만 본다. 의미가 맞는지는 직접 읽고 판단한다.

## 중복 판정 방법

이름이 다르다고 다른 기능이 아니다. 아래가 같으면 중복으로 본다.

- 대상 사용자가 같다
- 입력과 결과가 같다
- 조작하는 데이터가 같다

중복으로 판정하면 어느 이름을 남길지 제안한다. 임의로 합치지 않는다.

## 보고 형식

```text
[누락] REQ-012 매장 운영자가 정산 내역을 확인할 수 있어야 한다
  기능 없음. 화면 없음.
  판단 근거: docs/07_기능명세.md 에 정산 관련 기능이 정의되어 있지 않다.
  조치 제안: 기능 정의 또는 요구사항 범위 제외 결정
```

판정, 대상 식별자, 사실, 근거 위치, 조치 제안 순으로 적는다. 사실과 제안을 섞지 않는다.

## 산출물

`agent-system/output/final-review.md`의 추적성 절에 기록한다. Critical과 Major는 `_data/issues.yaml`에 등록한다.

## 완료 기준

- 요구사항 전체에 대해 판정이 하나씩 있다.
- 기능 전체에 대해 상위 요구사항 확인이 끝났다.
- 판정마다 근거 위치가 파일명과 함께 적혀 있다.
