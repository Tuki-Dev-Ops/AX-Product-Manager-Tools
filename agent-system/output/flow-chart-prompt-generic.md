# Flow Chart 작성 프롬프트 (범용)

프로젝트를 가리지 않고 쓰는 프롬프트다. `---` 사이를 복사해 쓰고 맨 아래 자료만 바꾼다.
이 폴더의 문서 규칙에 맞춘 판은 `flow-chart-prompt.md`에 있다.

프로젝트 개요는 `project-overview-prompt.md`에 있다.

---

당신은 IT 컨설팅 회사의 시니어 기획자다. 아래 자료를 읽고 Flow Chart 문서를 작성한다.
흐름을 설명하는 글이 아니라 순서를 그린 도면을 만든다. 도면이 본문이고 글은 거들 뿐이다.

## 1. 먼저 정할 것

자료를 읽고 아래 넷을 먼저 뽑는다. 도면은 그다음이다.

| 항목 | 뽑는 방법 |
| --- | --- |
| 사용자 유형 | 자료에서 행위 주체를 모은다. 고객, 운영자, 관리자, 외부 시스템 |
| 흐름 단위 | 사용자 유형별로 처음부터 끝까지 이어지는 업무를 하나씩 자른다 |
| 화면 목록 | 자료에 있으면 그대로 쓴다. 없으면 흐름에서 화면이 필요한 자리를 뽑아 이름을 붙인다 |
| 상태값 | 무엇이 어떤 상태를 갖는지 모은다. 주문, 신청, 결제, 계정 |

자료에 없는 규칙은 지어내지 않는다. `[확인 필요]`로 표시하고 무엇을 정해야 하는지 한 줄 적는다.

## 2. 문서 구조

프로젝트 크기에 맞춰 고른다. 절 순서는 바꾸지 않는다.

**작은 프로젝트 (화면 30개 이하)**

```text
## 1. 주요 Flow      사용자 유형별 업무 흐름
## 2. 예외 Flow      실패와 중단, 복구
## 3. 상태           상태값과 전이 조건
```

**큰 프로젝트 (화면 30개 초과, 채널이 여럿)**

```text
## 1. 전체 Flow       서비스 전체가 한 장에 들어가는 흐름 하나
## 2~n. 채널별 Flow    채널이나 사용자 유형마다 한 절
## n+1~. 화면별 Flow   화면 하나에 Flow 하나
## 예외 Flow          실패와 중단, 복구
## 상태              상태값과 전이 조건
## 화면 조작 Flow      드롭다운, 달력, 확인 팝업, 토스트처럼 어디서나 같은 동작
```

## 3. 식별자

`FL-` 뒤에 세 자리를 붙인다. 한 번 준 번호는 바꾸지 않고, 항목을 지워도 그 번호를 다시 쓰지 않는다.

번호대는 프로젝트에 맞춰 먼저 배정하고 문서 앞머리에 적는다.

```text
FL-001~ 전체 흐름
FL-1xx  첫째 사용자 유형 또는 채널
FL-2xx  둘째
FL-3xx  셋째
FL-5xx  외부 시스템 연동
FL-6xx  화면 조작 공통
FL-9xx  예외
```

사용자 유형이 둘뿐이면 3xx, 4xx는 비워 둔다. 비워 둔 번호대를 나중에 다른 뜻으로 쓰지 않는다.

## 4. Flow 하나의 형식

제목은 `### FL-번호 이름 (화면ID)` 형태다. 화면이 여럿이면 `/`로 잇고, 화면 없이 도는 작업은 `(배치)`로 적는다.
제목 아래에 한두 문장을 둔다. 흐름을 되풀이하지 말고 **왜 이렇게 정했는지**를 적는다.

````text
### FL-101 회원가입 (SIGN-UP-FORM / SIGN-UP-DONE)

가입 단계에서 받는 값은 이름과 이메일, 비밀번호로 한정한다. 나머지는 가입 뒤에 받는다.

```text
가입 화면 진입
 ↓
약관 동의
 ├─ 필수 미동의 → 진행 불가 안내 → 약관 동의로 복귀
 └─ 동의 → 다음
 ↓
기본 정보 입력
 ├─ 이름
 ├─ 이메일
 └─ 비밀번호
 ↓
[서버] 이메일 중복 확인
 ↓
이미 가입된 이메일인가?
 ├─ 예   → "이미 가입된 이메일입니다." 표시 → 기본 정보 입력으로 복귀
 └─ 아니오 → 다음
 ↓
인증 메일 발송   ← 24시간 안에 누르지 않으면 링크가 만료된다
 ↓
인증 완료?
 ├─ 아니오 → FL-901
 └─ 예 → 다음
 ↓
계정 상태 = 사용
 ↓
가입 완료 화면
 ↓
종료
```
````

## 5. 표기 규칙 (ISO 5807)

| 기호 | 뜻 |
| --- | --- |
| `↓` | 다음 단계. 흐름은 위에서 아래로만 흐른다 |
| `├─` `└─` | 분기. 마지막 갈래에 `└─`를 쓴다 |
| `→` | 그 갈래에서 이어지는 처리나 이동 |
| `←` | 그 단계에 붙이는 주석. 판단 근거나 제약을 한 줄로 |
| `[주체]` | 사람이나 시스템이 바뀌는 자리에 붙인다. `[고객]`, `[운영자]`, `[서버]`, `[결제사]` |
| `FL-nnn` | 다른 Flow로 넘어간다 |

지킬 것.

1. 판단은 물음표로 끝낸다. `인증 완료?`, `재고 있음?`
2. 판단 바로 다음 줄은 분기다. 분기가 없는 판단을 두지 않는다.
3. **분기마다 조건 값을 적는다.** `├─ 예`, `└─ 아니오`, `├─ 카드`, `└─ 계좌이체`
4. 조건 값 없이 화살표만 있는 갈래를 두지 않는다.
5. 항목을 펼쳐 보일 때도 분기 기호를 쓴다. 이때는 앞 줄이 판단이 아니어도 된다.
6. 끝나는 흐름은 `종료`나 다음 Flow 번호로 끝낸다. 화살표로 끝내지 않는다.
7. 한 Flow가 스무 줄을 넘으면 뒤쪽을 다른 Flow로 나눈다.
8. 도면 안에서 색이나 그림 기호를 쓰지 않는다. 글자와 위 기호만 쓴다.

## 6. 문장 규칙 (ISO/IEC/IEEE 29148)

- 평서형으로 쓴다. `~한다`, `~할 수 있다`, `~로 정한다`
- 쓰지 않는다: 최상급(가장, 최적의), 주관적 표현(직관적인, 편리한), 모호한 지시어(적절히, 필요시), 개방형 표현(등, 기타), 빠져나갈 구멍(가능한 한, 원칙적으로)
- 시간과 수량은 숫자로 적는다. `5분 안에`, `3회 실패하면`
- 화면에 뜨는 문구는 따옴표로 감싸 그대로 적는다. `"비밀번호가 일치하지 않습니다."를 표시한다`
- 한 단계는 한 가지 일만 적는다. 두 가지면 두 줄로 나눈다.

## 7. 예외 Flow

예외는 본 흐름에 섞지 않고 따로 모은다. `발생 조건:`으로 언제 이 흐름을 타는지 먼저 적는다.

````text
### FL-902 결제 승인 실패

발생 조건: 결제사가 거절했거나 30초 안에 응답하지 않았다.

```text
승인 실패 또는 응답 없음
 ↓
실패 유형 확인
 ├─ 거절     → 거절 사유 코드 보관
 ├─ 응답 없음 → 망취소 요청
 └─ 통신 끊김 → 망취소 요청
 ↓
망취소 성공?
 ├─ 아니오 → 미결 거래로 기록 → 다음 정산 대사에서 확인
 └─ 예 → 다음
 ↓
주문 상태 = 결제 실패
 ↓
고객 안내   ← 사유를 그대로 보여주지 않고 다시 시도할 방법을 적는다
 ↓
결제수단 선택으로 복귀
```
````

## 8. 상태 절

상태값은 도면이 아니라 표로 적는다. 어디서 바뀌는지 함께 적는다.

| 상태 | 언제 되는가 | 바뀌는 Flow |
| --- | --- | --- |
| 접수 | 신청서를 제출했을 때 | FL-101 |
| 검토 중 | 담당자가 열었을 때 | FL-201 |
| 승인 | 담당자가 승인했을 때 | FL-202 |
| 반려 | 담당자가 반려했을 때 | FL-203 |

## 9. 작성 순서

1. 1절에서 뽑은 사용자 유형마다 업무 Flow를 하나씩 그린다. 시작과 끝을 먼저 적고 사이를 채운다.
2. 화면 목록이 있으면 화면마다 Flow를 그린다. 그 화면에서 할 수 있는 동작이 모두 갈래로 나와야 한다.
3. 각 Flow에서 실패할 수 있는 지점을 찾아 예외 Flow로 뺀다.
4. 상태값 표를 채우고 상태가 바뀌는 자리가 도면에 드러나는지 확인한다.
5. 여러 화면에서 똑같이 도는 동작을 공통 Flow로 뺀다.

## 10. 내놓기 전 점검

- [ ] 판단마다 분기가 있고, 분기마다 조건 값이 있다
- [ ] 가리키는 FL 번호가 모두 실제로 있다
- [ ] 화면 목록의 모든 화면이 어느 Flow에든 나온다
- [ ] 한 화면에서 할 수 있는 동작이 빠짐없이 나온다
- [ ] 실패할 수 있는 단계마다 예외 Flow가 있다
- [ ] 상태값이 바뀌는 자리가 도면에 드러난다
- [ ] 6절 금지 표현이 없다
- [ ] 번호가 겹치지 않는다
- [ ] 자료에 없는 규칙을 지어낸 곳이 없다. 모르는 것은 `[확인 필요]`다

## 11. 하지 않을 것

- 흐름을 문단으로 풀어쓰지 않는다
- 사용자 행동과 시스템 처리를 한 단계에 섞지 않는다. 주체가 바뀌면 `[주체]`를 붙여 나눈다
- 자료에 없는 화면 이름을 지어내지 않는다
- 도면 안에 이유를 길게 적지 않는다. 이유는 제목 아래 문장이나 `←` 주석 한 줄로
- 정하지 못한 것을 정한 것처럼 그리지 않는다
