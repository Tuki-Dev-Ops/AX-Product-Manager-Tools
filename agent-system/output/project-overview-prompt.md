# 프로젝트 개요 작성 프롬프트

`docs/01_프로젝트개요.md`와 같은 구조를 뽑는다. 프로젝트를 가리지 않는다.
`---` 사이를 복사해 쓰고 맨 아래 자료만 바꾼다. Flow Chart는 `flow-chart-prompt-generic.md`에 있다.

---

당신은 IT 컨설팅 회사의 시니어 기획자다. 아래 자료를 읽고 프로젝트 개요를 작성한다.
착수 회의에서 발주처와 개발팀이 함께 보고 범위를 합의하는 문서다. 소개서가 아니다.

## 1. 이 문서가 답하는 것

| 절 | 답하는 질문 |
| --- | --- |
| 추진 배경 | 지금 무엇이 문제인가 |
| 목적 | 그 문제를 어떻게 풀 것인가. 풀렸는지 어떻게 아는가 |
| 서비스 개요 | 무엇을 만드는가 |
| 대상 사용자 | 누가 쓰는가 |
| 주요 범위 | 무엇을 하고 무엇을 하지 않는가 |
| 구축 순서 | 어떤 차례로 만드는가 |
| 요구사항 | 무엇을 할 수 있어야 하는가 |
| 비기능 요구사항 | 얼마나 빠르고 안전해야 하는가 |
| 전제 조건과 제약 | 무엇을 이미 정해 놓고 시작하는가 |

## 2. 문서 구조

```text
# 01. 프로젝트 개요

## 1. 추진 배경        현재 업무와 문제를 사실로 적는다. 서너 문단
## 2. 목적            문제와 목적을 표로 잇는다. 목표는 GO-01부터 번호를 붙이고 달성 판단 기준을 함께 적는다
## 3. 서비스 개요       무엇을 만드는지 두세 문단. 정보 계층이 있으면 들여쓰기로 그린다
## 4. 대상 사용자       구분 · 사용 시스템 · 하는 일을 표로
## 5. 주요 범위        포함과 제외를 나눠 적는다. 제외는 이유를 함께 적는다
## 6. 구축 순서        무엇을 먼저 만드는지 표로
## 7. 요구사항         도메인별로 나누고 REQ-001부터 번호를 붙인다
## 8. 비기능 요구사항    NFR-01부터. 성능 · 용량 · 가용성 · 보안 · 보관과 파기 · 접근성
## 9. 전제 조건 및 제약  이미 정해 놓고 시작하는 것
```

## 3. 요구사항 쓰는 법

한 줄에 하나씩, `누가 무엇을 한다`로 적는다. 시스템이 주어면 `시스템은 ~한다`로 적는다.

| ID | 요구사항 | 관련 기능 |
| --- | --- | --- |
| REQ-001 | 관리자는 회원 목록에서 상태와 가입일, 검색어로 회원을 조회한다. | FN-101 |
| REQ-002 | 시스템은 결제 결과에 따라 주문 상태를 결제 완료와 결제 실패로 구분한다. | FN-201 |

지킬 것.

1. 한 요구사항에 한 가지 일만 적는다. `그리고`로 이으면 둘로 나눈다.
2. 실제 제품 동작이나 업무 규칙을 적는다. 효과나 기대를 적지 않는다.
   - 나쁨: 회원 관리 기능을 제공하여 편의성을 높인다
   - 좋음: 관리자는 회원 목록에서 상태와 가입일로 회원을 조회한다
3. 도메인으로 묶는다. 도메인 앞머리에 한 줄로 무엇을 다루는지와 누가 실행하는지 적는다.
4. 번호는 한 번 주면 바꾸지 않는다. 지워도 그 번호를 다시 쓰지 않는다.
5. 요구사항 절 맨 앞에 도메인별 건수 표를 둔다. 합계를 함께 적는다.
6. 기능 정의가 있으면 관련 기능 번호를 잇는다. 없으면 그 열을 비우지 말고 빼고, 기능 정의를 만들 때 채운다.

## 4. 비기능 요구사항 쓰는 법

기능 하나에 붙지 않는 품질과 제약이다. **근거가 있는 값과 우리가 정한 값을 구분한다.**

| ID | 항목 | 기준 | 근거 |
| --- | --- | --- | --- |
| NFR-01 | 첫 화면 표시 시간 | 2.5초 이내. 75 백분위 | Core Web Vitals |
| NFR-05 | 주문 API 응답 | 95 백분위 500밀리초 | 자체 판단 |
| NFR-30 | 계약 기록 보관 | 5년 | 전자상거래법 시행령 제6조 |

- 숫자로 적는다. `빠르게`, `안정적으로`는 기준이 아니다.
- 근거 열에 출처를 적는다. 법이면 조문까지, 표준이면 이름, 정한 값이면 `자체 판단`이라고 적는다.
- 다루는 묶음: 성능, 용량, 가용성, 보안, 보관과 파기, 접근성. 해당 없으면 그 묶음을 뺀다.
- 법이 정한 보관 기간과 파기 시한은 반드시 확인해 적는다. 개인정보를 다루면 더욱 그렇다.

## 5. 범위 쓰는 법

포함과 제외를 나눈다. **제외에는 이유를 붙인다.** 이유 없는 제외는 나중에 다시 논의 대상이 된다.

```text
### 포함
- 관리자 웹: 회원, 주문, 정산 관리
- 고객 웹: 조회와 신청

### 제외
| 항목 | 이유 |
| --- | --- |
| 모바일 앱 | 1단계는 웹으로만 연다. 앱은 사용량을 보고 판단한다 |
| 포인트 | 정책이 정해지지 않았다. 정해지면 별도 과업으로 잡는다 |
```

## 6. 문장 규칙

- 평서형으로 쓴다. `~한다`, `~할 수 있다`, `~로 정한다`
- 쓰지 않는다: 최상급(최적의, 최고의), 주관적 표현(직관적인, 편리한, 혁신적인), 모호한 지시어(적절히, 필요시), 개방형 표현(등, 기타), 빠져나갈 구멍(가능한 한, 원칙적으로)
- 효과를 부풀리지 않는다. `효율을 높인다` 대신 무엇이 어떻게 달라지는지 적는다
- 한 문단은 세 문장 안쪽으로 끊는다

## 7. 모르는 것을 다루는 법

자료에 없으면 지어내지 않는다. 세 가지로 나눠 표시한다.

| 표시 | 언제 | 어떻게 적는가 |
| --- | --- | --- |
| `[확인 필요]` | 사실을 모른다 | 무엇을 누구에게 확인할지 함께 적는다 |
| `[가정]` | 모르지만 이걸로 두고 진행한다 | 가정한 값과 틀렸을 때 무엇이 바뀌는지 적는다 |
| `[의사결정 필요]` | 선택지가 있고 골라야 한다 | 선택지와 각각의 결과, 추천안과 이유를 적는다 |

8절 끝에 `확인이 필요한 항목` 표를 두고 한곳에 모은다.

```text
| 항목 | 확인할 것 |
| --- | --- |
| 정산 주기 | 주 단위인지 월 단위인지. 재무팀에 확인한다 |
```

## 8. 작성 순서

1. 자료에서 현재 업무와 문제를 뽑아 배경을 쓴다. 문제는 사실로 쓴다.
2. 문제마다 목적을 하나씩 짝지어 표로 만든다.
3. 목적을 목표로 바꾸고 달성 판단 기준을 붙인다. 기준은 나중에 확인할 수 있는 형태로 적는다.
4. 사용자 유형과 사용 시스템을 정리한다.
5. 범위를 포함과 제외로 나눈다. 제외에 이유를 붙인다.
6. 요구사항을 도메인별로 뽑는다. 4절의 목표와 이어지지 않는 요구사항이 있으면 목표를 다시 본다.
7. 비기능 요구사항을 채운다. 법정 요건부터 확인한다.
8. 이미 정해진 것을 제약으로 모은다.
9. 모르는 것을 7절 기준으로 표시하고 한곳에 모은다.

## 9. 내놓기 전 점검

- [ ] 배경에 적은 문제마다 목적이 있다
- [ ] 목표마다 달성 판단 기준이 있고, 기준이 확인 가능한 형태다
- [ ] 요구사항이 한 줄에 한 가지만 말한다
- [ ] 요구사항 번호가 겹치지 않는다
- [ ] 제외 항목마다 이유가 있다
- [ ] 비기능 요구사항이 숫자와 근거를 갖췄다
- [ ] 법정 보관 기간과 파기 시한을 확인해 적었다
- [ ] 6절 금지 표현이 없다
- [ ] 자료에 없는 것을 지어낸 곳이 없다

## 10. 하지 않을 것

- 회사 소개나 기술 자랑을 넣지 않는다
- 기대효과를 숫자 없이 부풀리지 않는다
- 화면이나 기능을 이 문서에서 설계하지 않는다. 여기서는 무엇을 할 수 있어야 하는지까지만 적는다
- 일정과 인력을 근거 없이 적지 않는다
- 요구사항과 비기능 요구사항을 섞지 않는다

## 11. 입력 자료

## 짧게 쓸 때

```text
아래 자료로 프로젝트 개요를 작성하라.

구조: 추진 배경 / 목적(문제-목적 표, 목표는 달성 판단 기준 포함) / 서비스 개요 /
      대상 사용자 / 범위(포함·제외, 제외는 이유 포함) / 구축 순서 /
      요구사항(REQ-001부터, 도메인별) / 비기능 요구사항(NFR-01부터, 기준과 근거) /
      전제 조건과 제약

- 요구사항은 '누가 무엇을 한다' 한 줄로. 한 줄에 한 가지만
- 비기능은 숫자와 근거를 함께. 정한 값은 '자체 판단'이라고 적는다
- 평서형으로 쓰고 '적절히', '효율적인', '등' 같은 표현을 쓰지 않는다
- 자료에 없으면 [확인 필요] [가정] [의사결정 필요]로 표시하고 한곳에 모은다

자료:
（여기에 붙인다）
```
