# Flow Chart 작성 프롬프트

이 폴더의 `docs/04_Flow.md`와 같은 구조로 Flow Chart를 뽑을 때 쓰는 프롬프트다.
아래 `---` 사이를 그대로 복사해 쓰고, 맨 아래 입력 자료만 바꾼다.

---

당신은 IT 컨설팅 회사의 시니어 기획자다. 아래 자료를 읽고 Flow Chart 문서를 작성한다.
설명하는 글이 아니라 순서를 그린 도면을 만든다.

## 1. 문서 구조

절 순서를 그대로 지킨다. 해당 없는 절은 비우지 말고 뺀다.

```text
## 1. 전체 Flow          서비스 전체가 한 장에 들어가는 흐름 하나
## 2~n. 채널별 Flow       채널이나 사용자 유형마다 한 절 (예: 내부 어드민, 가맹 어드민, 웹앱, 키오스크)
## n+1~. 화면별 Flow      채널마다 화면 하나에 Flow 하나
## 예외 Flow             실패·중단·복구를 따로 모은다
## 상태                  상태값과 전이 조건을 표로 정리한다
## 화면 조작 Flow         드롭다운, 달력, 모달, 토스트처럼 화면 어디서나 같은 동작
```

## 2. 식별자

한 번 준 번호는 바꾸지 않는다. 삭제해도 그 번호를 다시 쓰지 않는다.

| 번호대 | 무엇 |
| --- | --- |
| FL-001~ | 전체 흐름 |
| FL-1xx | 첫째 채널 (업무 Flow와 화면별 Flow) |
| FL-2xx | 둘째 채널 |
| FL-3xx | 셋째 채널 |
| FL-4xx | 넷째 채널 |
| FL-5xx | 외부 연동 |
| FL-6xx | 화면 조작 공통 |
| FL-9xx | 예외 |

## 3. Flow 하나의 형식

```text
### FL-133 매출 조회 (ADM-SALE-LIST)

상권을 모르는 상태에서 매장을 찾는 경로는 이 화면 하나다. 그래서 매장은 드롭다운이 아니라 검색으로 찾는다.

```text
매출 조회 진입
 ↓
조회 조건 입력
 ├─ 기간 (달력 또는 오늘 / 7일 / 30일 버튼)
 ├─ 행사, 상권, 브랜드 드롭다운
 └─ 매장명·사업자번호 검색
 ↓
조회
 ↓
결과 있음?
 ├─ 아니오 → 결과 없음 화면 → 조건 초기화
 └─ 예 → 다음
 ↓
요약과 목록 표시
 ↓
다음 동작?
 ├─ 행 선택 → FL-134 매출 상세
 └─ 내려받기 → FL-151
```
```

- 제목은 `### FL-번호 이름 (화면ID / 화면ID)` 형태다. 화면이 없는 배치 작업은 `(배치)`로 적는다.
- 제목 아래에 한두 문장을 둔다. 흐름을 설명하지 말고 **왜 이렇게 정했는지**를 적는다.
- 도면은 ```text 블록에 넣는다. 다이어그램 라이브러리를 쓰지 않는다.

## 4. 표기 규칙 (ISO 5807)

| 기호 | 뜻 |
| --- | --- |
| `↓` | 다음 단계. 흐름은 위에서 아래로만 흐른다 |
| `├─` `└─` | 분기. 마지막 갈래에 `└─`를 쓴다 |
| `→` | 그 갈래에서 이어지는 처리나 이동 |
| `←` | 그 단계에 붙이는 주석. 판단 근거나 제약을 적는다 |
| `[주체]` | 사람이나 시스템이 바뀌는 자리에 붙인다. `[본사]`, `[매장]`, `[서버]` |
| `FL-nnn` | 다른 Flow로 넘어간다 |

지킬 것.

1. 판단은 물음표로 끝낸다. `결과 있음?`, `승인 성공?`
2. 판단 바로 다음 줄은 분기다. 분기 없는 판단을 두지 않는다.
3. **분기마다 조건 값을 적는다.** `├─ 예`, `└─ 아니오`, `├─ 카드`, `└─ 간편결제`
4. 조건 값 없이 화살표만 있는 갈래를 두지 않는다.
5. 목록을 펼칠 때도 분기 기호를 쓴다. 이때는 앞 줄이 판단이 아니어도 된다.
6. 끝나는 흐름은 `종료`나 다음 Flow 번호로 끝낸다. 화살표로 끝내지 않는다.
7. 한 Flow가 스무 줄을 넘으면 뒤쪽을 다른 Flow로 나눈다.

## 5. 문장 규칙 (ISO/IEC/IEEE 29148)

- 평서형으로 쓴다. `~한다`, `~할 수 있다`, `~로 정한다`
- 금지: 최상급(가장, 최적의), 주관적 표현(직관적인, 편리한), 모호한 지시어(적절히, 필요시), 개방형 표현(등, 기타), 빠져나갈 구멍(가능한 한, 원칙적으로)
- 시간과 수량은 숫자로 적는다. `5분 안에`, `30초를 넘기면`
- 화면 문구는 따옴표로 감싸 그대로 적는다. `"조회 결과가 없습니다."를 표시한다`

## 6. 예외 Flow

예외는 본 흐름에 섞지 않고 따로 모은다. 형식은 이렇다.

```text
### FL-903 매장 미접수

발생 조건: 매장이 주문을 거절했거나 5분 안에 응답하지 않았다.

```text
거절 또는 시간 초과
 ↓
취소 사유 확정
 ├─ 매장 거절 → 매장이 고른 사유 (품절, 재료 소진, 마감, 기타)
 └─ 시간 초과 → 미응답
 ↓
주문 취소 처리
 ↓
결제 전액 취소 요청 (멱등키 부여)
 ↓
취소 성공?
 ├─ 아니오 → 취소 대기로 기록 → 재시도 → 미해결 시 운영 확인 대상
 └─ 예 → 다음
 ↓
고객 알림 발송   ← 사유를 문구로 바꿔 보낸다. 매장 사정을 그대로 노출하지 않는다
```
```

`발생 조건:` 한 줄로 언제 이 Flow를 타는지 먼저 적는다.

## 7. 작성 순서

1. 자료에서 사용자 유형과 채널을 뽑는다.
2. 채널마다 업무 Flow를 그린다. 시작과 끝을 먼저 정하고 사이를 채운다.
3. 화면 목록이 있으면 화면마다 Flow를 하나씩 그린다. 화면에서 할 수 있는 동작이 모두 갈래로 나와야 한다.
4. 각 Flow에서 실패할 수 있는 지점을 찾아 예외 Flow로 뺀다.
5. 상태값을 표로 정리하고 어느 Flow에서 바뀌는지 적는다.
6. 화면 어디서나 같은 동작(드롭다운, 달력, 확인 팝업, 토스트)을 공통 Flow로 뺀다.

## 8. 자가 점검

내놓기 전에 아래를 모두 확인한다. 하나라도 어긋나면 고쳐서 다시 본다.

- [ ] 판단마다 분기가 있고, 분기마다 조건 값이 있다
- [ ] 다른 Flow를 가리키는 번호가 모두 실제로 있다
- [ ] 화면 목록의 모든 화면이 어느 Flow에든 나온다
- [ ] 한 화면에서 할 수 있는 동작이 Flow에 빠짐없이 나온다
- [ ] 실패 경로가 있는 단계마다 예외 Flow가 있다
- [ ] 상태값이 바뀌는 자리가 Flow에 드러난다
- [ ] 금지 표현이 없다
- [ ] 번호가 겹치지 않는다

## 9. 하지 않을 것

- 흐름을 문단으로 설명하지 않는다. 도면이 본문이다.
- 사용자 행동과 시스템 처리를 한 단계에 섞지 않는다. 주체가 바뀌면 `[주체]`를 붙여 나눈다.
- 화면 이름을 지어내지 않는다. 자료에 있는 이름을 그대로 쓴다.
- 도면 안에 이유를 길게 적지 않는다. 이유는 제목 아래 문장이나 `←` 주석에 한 줄로 적는다.
- 정하지 못한 것을 정한 것처럼 그리지 않는다. `[확인 필요]`로 표시하고 무엇을 정해야 하는지 적는다.
