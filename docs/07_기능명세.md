# 07. 기능 명세

화면 단위로 무엇을 처리하고 어떤 조건과 예외를 두는지 정의한다. 화면 ID와 화면명은 05 IA와 같다.

배치는 06 Wireframe, 처리 순서는 04 Flow에 있다. 여기서는 화면이 지켜야 할 규칙을 적는다.

확인 팝업과 결과 토스트는 05 문서 7절 공통 규칙을 따른다. 화면마다 다시 적지 않는다.

## 1. 내부 어드민

### 인증

#### ADM-AUTH-LOGIN 로그인

| 구분 | 내용 |
| --- | --- |
| 목적 | 이메일과 비밀번호로 인증한다 |
| 대상 | 전체 |
| 유형 | 페이지 |
| 연결 Flow | FL-101 매장 개설 · FL-110 로그인 · FL-908 로그인 실패 |

**처리**

1. 로그인 → 성공 시 ADM-AUTH-OTP
2. 이메일 저장 → 다음 접속 시 이메일을 채워 둔다

**조건**

* 실패 5회 시 계정을 잠근다
* 어느 항목이 틀렸는지 밝히지 않는다

**예외**

* 불일치 시 "이메일 또는 비밀번호가 올바르지 않습니다. (2/5)" 표시. 어느 항목이 틀렸는지 밝히지 않고 남은 횟수만 알린다
* 연속 5회 실패 시 "계정이 잠겼습니다. 관리자에게 문의해 주세요." 표시하고 잠금 시각을 함께 보여준다. 로그인 버튼을 비활성으로 둔다
* 잠긴 본사 계정은 다른 본사 운영자가 계정 목록에서 푼다
* 로그인에 성공하면 실패 횟수를 초기화한다

#### ADM-HOME-EXAM 개시 확정

| 구분 | 내용 |
| --- | --- |
| 목적 | 하위가맹점 심사가 끝난 매장의 개시를 확정한다 |
| 대상 | 본사 운영자 |
| 유형 | 레이어팝업 |
| 상태값 | 심사 대기, 심사 완료 |
| 연결 Flow | FL-112 대시보드 · FL-234 매장 등록·관리 |

**목록 구성**

| 구분 | 내용 |
| --- | --- |
| 조회 조건 | 행사, 심사 |
| 열 | 선택, 순번, 매장명, 소속 행사, 심사, 심사일, 메뉴 |
| 기본 정렬 | 심사일 (최근이 위) |
| 행 동작 | 없다. 선택해서 일괄 확정한다 |
| 선택 처리 | 심사 완료 매장만 고를 수 있다 |

**처리**

1. 대시보드 개시 준비의 심사 열에서 연다. 그 행사의 개설 준비 매장이 나온다
2. 결제대행사 결과가 자동으로 온 매장은 심사 완료로 나온다. 오지 않은 매장은 심사 대기다
3. 결과를 직접 확인한 매장은 행에서 심사 완료로 바꾼다. 심사일을 함께 적는다
4. 심사 완료 매장을 골라 개시 확정 → 확인 팝업에 건수와 메뉴 없는 매장 수를 적는다 → 확정
5. 확정한 매장은 영업으로 바뀌고 소속 행사가 잠기며 주문 채널에 노출된다

**조건**

* 심사 대기 매장은 확정할 수 없다
* 되돌릴 수 없다. 확정 뒤 문제가 있으면 매장이 일시중지로 바꾼다
* 확정 시각과 조작자를 이력에 남긴다

**예외**

* 확정할 매장이 없으면 "확정할 매장이 없습니다."를 표시한다
* 메뉴가 하나도 없는 매장은 확정은 되지만 판매할 것이 없어 채널에 노출되지 않는다. 확인 팝업에 그 수를 적는다
* 결제대행사 심사가 거절이면 심사 거절로 표시하고 사유를 적는다. 매장이 정보를 고쳐 다시 요청한다

#### ADM-AUTH-OTP 2차 인증

| 구분 | 내용 |
| --- | --- |
| 목적 | 등록 단말로 인증번호를 확인한다 |
| 대상 | 전체 |
| 유형 | 페이지 |
| 연결 Flow | FL-101 매장 개설 · FL-111 2차 인증 |

**처리**

1. 인증하기 → 성공 시 ADM-HOME-MAIN
2. 시간이 남아 있으면 버튼은 인증하기로 둔다
3. 유효시간이 끝나면 버튼을 재발급으로 바꾸고 입력칸을 비활성으로 둔다
4. 재발급 → 새 인증번호를 보내고 남은 시간을 초기화한다
5. 다른 계정으로 로그인하기 → 진행 중이던 인증을 버리고 로그인 화면으로 돌아간다

**조건**

* 외부 접속은 2차 인증을 건너뛸 수 없다
* 인증번호 유효시간 3분

**예외**

* 인증번호를 다 입력하기 전에는 인증하기를 비활성으로 둔다
* 불일치 시 "인증번호가 올바르지 않습니다. (2/5)" 표시하고 남은 횟수를 알린다
* 유효시간 3분이 지나면 "인증 시간이 지났습니다. 다시 받아 주세요." 표시하고 버튼을 재발급으로 바꾼다
* 실패 횟수를 넘기면 일정 시간 차단한다
* 다른 계정으로 돌아가면 발송한 인증번호를 무효로 만든다. 이전 번호로는 인증할 수 없다

### 대시보드

#### ADM-HOME-MAIN 대시보드

| 구분 | 내용 |
| --- | --- |
| 목적 | 조치가 필요한 항목과 오늘 실적, 정산 상태, 행사 개시 준비를 표시한다 |
| 대상 | 본사 운영자 |
| 유형 | 페이지 |
| 연결 Flow | FL-112 대시보드 |

**처리**

1. 이상 항목을 판정해 지금 확인할 것 영역에 발생 시각 순으로 표시한다
2. 오늘 실적을 주문, 결제, 취소, 순매출로 표시하고 집계 시점을 함께 적는다
3. 처리 대기를 건수와 가장 오래된 건의 경과 시간으로 표시한다
4. 최근 정산 대사 상태를 기준일별로 표시한다
5. 개시 7일 이내 행사의 준비 완료 수를 표시한다
6. 개시 준비의 심사 열 → ADM-HOME-EXAM
7. 각 항목을 선택하면 해당 화면으로 이동한다

**이상 판정 기준**

| 유형 | 기준 |
| --- | --- |
| 단말 미연결 | 마지막 통신 후 30분 경과 |
| 접수 지연 | 접수 대기가 30초를 넘긴 주문이 있는 매장 |
| 매출 급락 | 최근 1시간 주문이 같은 요일 같은 시간대 평균의 30% 미만 |
| 품절 급증 | 판매 메뉴의 30% 이상이 품절 |

**조건**

* 매장 화면에서 처리해야 하는 항목은 대행 접속으로 보낸다. 본사가 매장 화면을 직접 고치지 않는다

* 추세 그래프와 매장 순위를 두지 않는다. 비교는 매출 화면에서 한다
* 모든 항목에 이동 경로를 붙인다. 누를 곳이 없는 숫자는 두지 않는다
* 이상 판정 기준은 전체 공통이다. 매장별로 다르게 두지 않는다
* 한 화면의 지표 묶음을 다섯 개 이하로 유지한다

**예외**

* 이상 항목이 없으면 "확인할 항목이 없습니다."를 표시한다
* 집계가 아직 돌지 않은 구간은 수치를 비우고 "집계 중"으로 표시한다
* 개시 7일 이내 행사가 없으면 개시 준비 영역을 숨긴다
* 매출 급락은 개시 첫날과 종료일에는 판정하지 않는다. 비교할 과거 구간이 없다

### 행사

#### ADM-EVNT-LIST 행사 목록

| 구분 | 내용 |
| --- | --- |
| 목적 | 기간과 상태로 행사를 조회한다 |
| 대상 | 본사 운영자 |
| 유형 | 페이지 |
| 상태값 | 진행 전, 진행 중, 종료 |
| 연결 Flow | FL-101 매장 개설 · FL-113 행사 목록·등록 |

**목록 구성**

| 구분 | 내용 |
| --- | --- |
| 조회 조건 | 시작일, 종료일, 상태, 행사명 |
| 열 | 선택, 순번, 행사명, 등록된 브랜드, 시작일, 종료일, 상태, 동작 |
| 기본 정렬 | 시작일 (최근이 위) |
| 행 동작 | 동작 열에 둔다 |
| 선택 처리 | 행을 고르면 표 위에 건수와 처리 버튼을 띄운다 |

**처리**

1. 조회 → 조건에 맞는 행사를 표시한다
2. 행 선택 → ADM-EVNT-FORM
3. 행사 등록 → ADM-EVNT-FORM 신규

**조건**

* 종료 행사는 기본 조회에서 제외한다
* 삭제는 진행 전 행사만 할 수 있다. 붙어 있던 상권은 그 행사에서 떼어지고 상권은 남는다

**예외**

* 결과가 없으면 "조회 결과가 없습니다." 표시
* 그 행사에 속한 매장이 있으면 삭제할 수 없다. "이 행사에 속한 매장 N개가 있어 삭제할 수 없습니다."를 표시한다

#### ADM-EVNT-FORM 행사 등록·수정

| 구분 | 내용 |
| --- | --- |
| 목적 | 행사명, 기간, 장소를 등록한다 |
| 대상 | 본사 운영자 |
| 유형 | 레이어팝업 |
| 연결 Flow | FL-101 매장 개설 · FL-113 행사 목록·등록 |

**처리**

1. 정보 탭에서 행사명, 시작일, 종료일, 장소, 관리자 메모를 입력한다
2. 장소 선택 → ADM-ADDR-FIND
3. 저장 → 전체 항목 검증 → 확인 팝업 → 목록으로 이동
4. 상권 탭 → 참여할 상권을 붙이거나 뗀다 (ADM-EVNT-ZONE). 비워 두고 저장할 수 있다

**입력 항목**

| 항목 | 필수 | 형식 | 검증 |
| --- | --- | --- | --- |
| 행사명 | 필수 | 문자 50자 이내 | 기간이 겹치는 행사와 이름이 같을 수 없다 |
| 시작일 | 필수 | 날짜 | 신규 등록은 오늘 이후만 고른다 |
| 종료일 | 필수 | 날짜 | 시작일 이후여야 한다. 기간은 최대 90일 |
| 장소 | 필수 | 주소 | 주소 검색으로만 입력한다. 직접 입력할 수 없다 |
| 관리자 메모 | 선택 | 문자 200자 이내 | - |

**조건**

* 검증은 저장을 누를 때 한 번에 한다. 입력 도중에는 오류를 띄우지 않는다
* 오류가 둘 이상이면 항목마다 문구를 표시하고 화면 위에 건수를 함께 적는다. 첫 오류 항목으로 이동한다
* 탭이 있는 화면은 오류가 있는 탭에 표시를 남기고 안내 문구에 탭 이름을 적는다
* 항목을 고치면 그 항목의 오류만 지운다
* 종료된 행사는 수정할 수 없다

**예외**

| 상황 | 표시 문구 |
| --- | --- |
| 행사명 미입력 | 행사명을 입력해 주세요. |
| 행사명 50자 초과 | 행사명은 50자까지 입력할 수 있습니다. |
| 행사명 중복 | 이미 등록된 행사명입니다. 다른 이름을 입력해 주세요. |
| 시작일 미선택 | 시작일을 선택해 주세요. |
| 종료일 미선택 | 종료일을 선택해 주세요. |
| 종료일이 시작일보다 빠름 | 종료일은 시작일 이후여야 합니다. |
| 기간 90일 초과 | 행사 기간은 최대 90일까지 등록할 수 있습니다. |
| 장소 미입력 | 장소를 검색해 주세요. |
| 종료된 행사 수정 시도 | 입력을 읽기 전용으로 두고 "종료된 행사는 수정할 수 없습니다." 표시 |
| 저장 실패 | 저장하지 못했습니다. 잠시 후 다시 시도해 주세요. 입력한 값은 지우지 않는다 |

#### ADM-EVNT-ZONE 상권 붙이기

| 구분 | 내용 |
| --- | --- |
| 목적 | 이미 만든 상권을 이 행사에 붙인다 |
| 대상 | 본사 운영자 |
| 유형 | 레이어팝업 |
| 연결 Flow | FL-113 행사 목록·등록 |

**목록 구성**

| 구분 | 내용 |
| --- | --- |
| 조회 조건 | 브랜드명 |
| 열 | 선택, 순번, 브랜드명, 참여 행사, 매장 수 |
| 기본 정렬 | 등록 순 |
| 행 동작 | 행을 선택하면 상세로 간다 |
| 선택 처리 | 행을 고르면 표 위에 건수와 처리 버튼을 띄운다 |

**처리**

1. 행사 등록·수정의 상권 탭에서 상권 붙이기를 선택한다
2. 브랜드명으로 조회한다
3. 붙일 상권을 여러 건 고른다
4. 붙이기 → 상권 탭 목록에 더한다

**조건**

* 행사 등록·수정 모달 위에 겹쳐 띄운다
* 이미 이 행사에 붙어 있는 상권은 목록에 나오지 않는다
* 상권 하나가 여러 행사에 붙을 수 있다
* 목록에 없으면 상권 메뉴에서 새로 만든다. 이 화면에서 상권을 만들지 않는다

**예외**

* 조회 결과가 없으면 빈 결과 화면을 표시하고 상권 메뉴를 안내한다
* 하나도 고르지 않고 붙이기를 누르면 "붙일 상권을 선택해 주세요."를 표시한다

#### ADM-ADDR-FIND 주소 검색

| 구분 | 내용 |
| --- | --- |
| 목적 | 도로명, 건물명, 지번으로 주소를 찾아 입력 칸에 넣는다 |
| 대상 | 본사 운영자, 가맹 관리자 |
| 유형 | 레이어팝업 |
| 연결 Flow | FL-113 행사 목록·등록 · FL-114 상권 목록·등록 |

**처리**

1. 주소 입력 칸 선택 → 주소 검색 열기
2. 검색어 입력 후 검색 → 우편번호와 도로명주소 목록 표시
3. 주소 선택 → 상세주소 칸 활성화
4. 적용 → 우편번호, 도로명주소, 상세주소를 호출한 화면에 넣고 닫는다

**조건**

* 주소 입력 칸에 직접 입력할 수 없다. 검색 결과에서만 고른다
* 검색어는 2자 이상 입력해야 검색한다
* 우편번호와 도로명주소는 수정할 수 없다. 상세주소만 입력한다

**예외**

* 주소를 고르지 않고 적용하면 "주소를 선택해 주세요." 표시하고 닫지 않는다
* 주소 조회에 실패하면 "주소를 불러오지 못했습니다. 잠시 후 다시 시도해 주세요." 표시

#### ADM-COMN-CONF 확인 팝업

| 구분 | 내용 |
| --- | --- |

| 대상 | 본사 운영자, 가맹 관리자 |
| 유형 | 레이어팝업 |
| 연결 Flow | FL-605 처리 확인과 결과 안내 · FL-606 목록 일괄 처리 |

**처리**

1. 저장, 삭제, 상태 변경, 작업 취소를 누르면 확인 팝업을 연다
2. 확인 → 처리 요청 → 결과를 하단 가운데 토스트로 알린다
3. 취소 → 처리하지 않고 닫는다. 하단 토스트로 "취소되었습니다."를 알린다

**조건**

* 실행 버튼의 이름은 실제 동작으로 쓴다. "확인"이 아니라 "저장", "삭제", "종료"로 적는다
* 성공과 취소 토스트는 화면 아래 가운데에 3초 표시하고 사라진다. 화면을 가리지 않는다
* 실패 토스트는 사라지지 않는다. 닫기를 눌러야 없어진다
* 처리에 실패해도 화면을 벗어나지 않는다. 입력한 값을 지우지 않는다

**예외**

#### ADM-ZONE-FORM 상권 등록·수정

| 구분 | 내용 |
| --- | --- |
| 목적 | 브랜드 정보와 본사 사업자 정보, 담당 계정을 등록하고 그 브랜드의 매장을 확인한다 |
| 대상 | 본사 운영자 |
| 유형 | 레이어팝업 |
| 연결 Flow | FL-114 상권 목록·등록 · FL-116 상권 매장 관리 |

**처리**

2. 위치 선택 → ADM-ADDR-FIND
3. 계정 탭에서 담당 계정의 이메일, 이름, 휴대폰번호, 비밀번호를 입력한다
4. 저장 → 두 탭의 항목을 함께 검증 → 상권을 만들고 계정을 발급한다 → 확인 팝업 → 목록으로 이동
5. 수정에서는 계정 탭에 발급된 계정 정보를 읽기 전용으로 표시한다
6. 히스토리 탭에서 이 브랜드와 소속 매장의 변경 내역을 조회한다

**입력 항목 — 정보**

| 항목 | 필수 | 형식 | 검증 |
| --- | --- | --- | --- |
| 참여 행사 | 선택 | 여러 건 선택 | 진행 전 또는 진행 중인 행사만 고른다. 비워 둘 수 있고 나중에 붙일 수 있다 |
| 브랜드명 | 필수 | 문자 30자 이내 | 상권 하나에 브랜드 하나를 둔다. 전체에서 중복할 수 없다. 이 상권의 매장은 모두 이 브랜드에 속한다 |
| 위치 | 필수 | 주소 | 주소 검색으로만 입력한다 |
| 상호 | 필수 | 문자 | 본사 사업자의 상호 |
| 사업자등록번호 | 필수 | 숫자 10자리 | 휴폐업 조회에서 폐업으로 나오면 저장할 수 없다 |
| 대표자 | 필수 | 문자 | - |
| 대표 연락처 | 필수 | 숫자 10~11자리 | - |
| 정산계좌 | 필수 | 은행, 계좌번호, 예금주 | - |
| 관리자 메모 | 선택 | 문자 200자 이내 | - |

**입력 항목 — 계정**

| 항목 | 필수 | 형식 | 검증 |
| --- | --- | --- | --- |
| 이메일 | 필수 | 이메일 형식 | 로그인 아이디로 쓴다. 전체 계정에서 중복할 수 없다. 등록한 뒤에는 바꿀 수 없다 |
| 이름 | 필수 | 문자 20자 이내 | - |
| 휴대폰번호 | 필수 | 숫자 10~11자리 | 형식이 맞아야 한다 |
| 비밀번호 | 필수 | 8~20자, 영문·숫자·특수문자 중 2종 이상 | - |
| 비밀번호 재확인 | 필수 | 비밀번호와 같은 값 | 비밀번호와 같아야 한다 |
| 역할 | - | 고정 | 가맹 관리자로 둔다. 바꿀 수 없다 |
| 담당 범위 | - | 고정 | 등록하는 상권으로 둔다. 바꿀 수 없다 |

**히스토리 탭**

| 항목 | 내용 |
| --- | --- |
| 목록 | 변경일시, 대상, 항목, 변경 전, 변경 후, 변경자 |
| 대상 | 이 브랜드와 그 브랜드에 속한 매장 |
| 조회 조건 | 기간, 대상 |
| 기록 시점 | 본사와 매장이 바꾼 값을 모두 남긴다. 변경자에 소속을 함께 적는다 |
| 보관 | 지우지 않는다. 매장이 폐점해도 남긴다 |

**조건**

* 매장은 이 상권에만 속한다. 상권은 이 화면의 값으로 자동으로 정해진다
* 이 브랜드의 매장 목록은 매출 조회에서 상권 조건을 걸어 본다
* 상권명이 곧 브랜드명이다. 정보 탭에서 정한다
* 매장 표시명은 브랜드명과 지점번호로 만든다. 지점번호는 자동으로 부여한다
* 본사는 매장을 등록하거나 고치거나 상태를 바꾸지 않는다. 조회만 한다
* 브랜드를 입력하고 관리하는 주체는 본사 운영자다. 매장은 브랜드를 만들지 않는다
* 매장이 등록된 상권은 브랜드명을 바꿀 수 없다. 표시명이 모두 달라진다
* 상권을 여러 행사에 붙일 수 있다. 매출은 주문 시점의 참여 행사로 집계한다
* 검증은 저장을 누를 때 세 탭을 함께 한다. 오류가 있는 탭에 표시를 남기고 그 탭으로 이동한다
* 상권 등록은 담당 계정 발급을 포함한다. 계정 없이 상권만 저장할 수 없다
* 계정 항목은 등록할 때만 입력한다. 수정 화면에서는 모두 읽기 전용으로 둔다
* 계정 정보 수정, 비밀번호 재설정, 사용 중지는 ADM-USER-FORM에서 처리한다. 같은 항목을 두 화면에서 고치지 않는다
* 상권과 계정은 한 번에 처리한다. 계정 발급에 실패하면 상권도 저장하지 않는다
* 본사 운영자가 비밀번호를 지정한다. 발급한 비밀번호는 첫 로그인에서 바꾸게 한다
* 상권은 행사 여러 개에 참여할 수 있다. 참여 행사 열에 첫 행사와 나머지 수를 적는다
* 삭제는 매장이 없는 상권만 할 수 있다. 삭제하면 참여 행사에서 빠지고 담당 계정은 사용 중지된다
* 그 행사에 속한 매장이 있으면 뗄 수 없다. 행사가 끝나 매장이 정리된 뒤에 뗀다. 붙이는 것은 언제든 할 수 있다

**조건**

* 준비 시간은 5, 10, 15, 20, 30분에서 고른다
* 기본값은 매점 정보의 기본 준비 시간이다
* 접수 대기 상태에서만 열 수 있다. 5분이 지난 주문은 이미 취소되어 열리지 않는다

**예외**

* 여는 사이에 자동 취소되면 "이미 취소된 주문입니다."를 표시하고 목록을 갱신한다
* 접수에 실패하면 실패 안내를 띄우고 주문 상태를 바꾸지 않는다

| 구분 | 내용 |

4. 거절 → 주문을 취소하고 결제 전액 취소를 요청한다

**예외**

* 사유를 고르지 않으면 칸 아래에 "거절 사유를 선택해 주세요."를 표시한다
* 결제 취소에 실패하면 취소 대기로 기록하고 재시도한다. 주문은 취소로 둔다
* 마감을 고르면 영업 상태를 일시중지로 바꿀지 함께 묻는다

#### STR-STOR-LIST 매장 목록

| 구분 | 내용 |
| --- | --- |
| 목적 | 담당 상권의 매장을 조회하고 폐점 처리한다 |

| 상태값 | 개설 준비, 영업, 일시중지, 폐점 |
| 연결 Flow | FL-201 매점 운영 · FL-234 매장 등록·관리 |

**목록 구성**

| 구분 | 내용 |
| --- | --- |
| 조회 조건 | 소속 행사, 상태, 매장명 |
| 열 | 선택, 순번, 지점번호, 매장명, 소속 행사, 상태, 주문 채널, 등록일, 동작 |
| 기본 정렬 | 등록일 (최근이 위) |
| 행 동작 | 동작 열에 둔다 |
| 선택 처리 | 행을 고르면 표 위에 건수와 처리 버튼을 띄운다 |

**처리**

1. 매장 등록 → STR-STOR-FORM
2. 수정 → STR-STOR-FORM (수정)
3. 폐점 → 확인 팝업에 진행 중 주문 수와 연결 단말 수를 적은 뒤 처리

**조건**

* 담당 상권의 매장만 본다. 다른 상권은 조회할 수 없다
* 등록하면 개설 준비다. 본사가 하위가맹점 심사 결과로 개시를 확정해야 영업이 된다
* 개설 준비 매장은 주문 채널에 나오지 않고 정산에 들어가지 않는다. 메뉴와 단말은 미리 갖출 수 있다
* 지점번호는 브랜드 안에서 1부터 자동으로 붙는다. 사람이 입력하지 않는다
* 폐점은 되돌릴 수 없다. 폐점한 지점번호는 다시 쓰지 않는다
* 폐점하면 연결된 단말은 사용 중지로 바뀌고 주문 채널에서 빠진다

**예외**

* 진행 중 주문이 있으면 폐점할 수 없다. "진행 중인 주문 N건을 먼저 처리해 주세요."를 표시한다
* 조회 결과가 없으면 빈 결과 화면에 매장 등록을 안내한다

#### STR-STOR-FORM 매장 등록·수정

| 구분 | 내용 |
| --- | --- |
| 목적 | 매장을 만들고 소속 행사와 영업 정보를 정한다 |
| 대상 | 가맹 관리자 |
| 유형 | 레이어팝업 |
| 연결 Flow | FL-234 매장 등록·관리 |

**처리**

1. 브랜드는 담당 상권의 것으로 고정해 표시한다
2. 소속 행사, 위치, 영업시간, 대표 연락처, 기본 준비 시간, 주문 채널을 입력한다
3. 위치 선택 → ADM-ADDR-FIND
4. 저장 → 지점번호를 부여하고 매장명을 만든다 → 확인 팝업 → 목록 갱신

**입력 항목**

| 항목 | 필수 | 형식 | 검증 |
| --- | --- | --- | --- |
| 소속 행사 | 필수 | 선택 | 상권의 참여 행사 중 진행 전·진행 중인 것만 고른다 |
| 위치 | 필수 | 주소 | 주소 검색으로만 입력한다 |
| 영업 시작·종료 | 필수 | 시각 | 종료가 시작보다 늦어야 한다 |
| 대표 연락처 | 필수 | 숫자 10~11자리 | 형식이 맞아야 한다 |
| 기본 준비 시간 | 필수 | 5, 10, 15, 20, 30분 | 기본값 10분. 결제 전 고객 안내에 쓴다 |
| 주문 채널 | 필수 | 웹앱, 키오스크 중 하나 이상 | 하나도 고르지 않으면 저장할 수 없다 |
| 관리자 메모 | 선택 | 문자 200자 이내 | - |

**조건**

* 매장명은 브랜드명과 지점번호로 만든다. 따로 입력받지 않는다
* 정산계좌와 사업자 정보는 상권의 것을 그대로 쓴다. 매점 정보 변경에서 매장별로 바꿀 수 있다
* 개설 준비 동안은 소속 행사를 바꿀 수 있다. 개시가 확정되면 읽기 전용으로 둔다
* 소속 행사를 고르면 그 행사가 끝날 때까지 상권은 그 행사를 뗄 수 없다

**예외**

* 상권에 참여 행사가 없으면 "상권에 참여 행사가 없습니다. 본사에 요청해 주세요."를 표시하고 저장할 수 없다
* 저장에 실패하면 실패 안내를 띄우고 입력값을 유지한다

#### STR-DEVC-LIST 단말기 목록

| 구분 | 내용 |

| 대상 | 가맹 관리자, 본사 운영자 |
| 유형 | 페이지 |
| 상태값 | 연결, 연결 끊김, 사용 중지 |
| 연결 Flow | FL-232 단말기 목록 |

**목록 구성**

| 구분 | 내용 |
| --- | --- |
| 조회 조건 | 종류, 상태, 행사, 상권, 매장 |
| 열 | 선택, 순번, 단말명, 종류, 설치 위치, 상태, 마지막 통신 |
| 기본 정렬 | 마지막 통신 (최근이 위) |
| 행 동작 | 행을 선택하면 상세로 간다 |
| 선택 처리 | 행을 고르면 표 위에 건수와 처리 버튼을 띄운다 |

**처리**

1. 등록과 수정 → 매장만 할 수 있다. 본사 접속 시 버튼을 두지 않는다
2. 사용 중지 → 양쪽 다 할 수 있다. 사유를 받고 처리한다
3. 사용 재개 → 자기가 중지한 단말만 고를 수 있다

**조건**

* 매장은 담당 매장, 본사는 전체를 본다
* 등록과 수정, 삭제는 매장만 한다
* 사용 중지는 양쪽 다 하고 중지한 쪽이 재개한다

**예외**

* 연결 끊김 단말은 경과 시간을 함께 표시한다
* 폐점한 매장의 단말은 사용 중지로 바뀌고 재개할 수 없다. 목록에는 폐점 매장 표시를 붙인다
* 본사가 중지하면 매장에 통지하고, 매장은 재개할 수 없다
* 본사 접속 시 조작자와 대상 매장을 함께 기록한다

#### KSK-ADMN-MAIN 관리자 메뉴

| 구분 | 내용 |
| --- | --- |
| 목적 | 관리자 기능을 고른다 |
| 대상 | 가맹 관리자 |
| 유형 | 전체화면 |
| 연결 Flow | FL-403 키오스크 관리자 처리 · FL-421 관리자 메뉴 |

**처리**

1. 각 버튼 → 해당 화면으로 이동
2. 나가기 → 대기화면으로 복귀

**조건**

* 관리자 인증을 마친 뒤에만 들어온다
* 주문을 받는 중에도 들어올 수 있다. 진행 중인 주문은 그대로 둔다
* 일정 시간 조작이 없으면 대기화면으로 돌아간다

**예외**

* 단말 오류가 있으면 요약 영역에 사유를 표시한다

#### KSK-ADMN-SYNC 메뉴 갱신

| 구분 | 내용 |
| --- | --- |
| 목적 | ERP의 최신 메뉴를 단말로 받아온다 |
| 대상 | 가맹 관리자 |
| 유형 | 전체화면 |
| 연결 Flow | FL-425 메뉴 갱신 |

**처리**

1. 마지막 동기화 시각과 대기 중인 변경 수를 표시한다
2. 동기화 → 확인 팝업 → 메뉴 마스터를 다시 받는다
3. 결과(반영 건수, 실패 건수)를 화면에 표시한다
4. 실패하면 이전 마스터를 유지한다

**조건**

* 마지막 갱신 시각 이후 변경분만 받는다
* 주문 진행 중에는 갱신하지 않는다

**예외**

* 주문이 진행 중이면 갱신하지 않는다. 끝난 뒤 하도록 안내한다
* 바뀐 내용이 없으면 "최신 상태입니다." 표시한다
* 반영에 실패하면 사유를 표시하고 기존 메뉴를 유지한다
#### KSK-ADMN-OPEN 판매 메뉴 설정

| 구분 | 내용 |
| --- | --- |
| 목적 | 그날 판매할 메뉴를 연다 |
| 대상 | 가맹 관리자 |
| 유형 | 전체화면 |
| 상태값 | 노출, 미노출 |
| 연결 Flow | FL-426 판매 메뉴 설정 |

**처리**

1. 저장 → 확인 팝업에 여는 수와 닫는 수를 적고 처리한다
2. 저장하면 매장별 메뉴 설정의 노출 여부가 바뀐다

**조건**

* 매장별 메뉴 설정의 노출 여부를 바꾼다
* 웹앱과 외부 POS에도 함께 적용한다
* 노출 메뉴가 하나도 없으면 저장할 수 없다

**예외**

* 품절 메뉴는 노출로 바꿔도 주문 화면에 나오지 않는다. 품절 해제를 함께 안내한다
* 반영에 실패하면 이전 상태를 유지하고 사유를 표시한다
#### KSK-ADMN-SOUT 품절 설정

| 구분 | 내용 |
| --- | --- |
| 목적 | 단말에서 품절을 설정하고 ERP로 올린다 |
| 대상 | 가맹 관리자 |
| 유형 | 전체화면 |
| 상태값 | 판매중, 품절 |
| 연결 Flow | FL-403 키오스크 관리자 처리 · FL-423 품절 설정 |

**처리**

1. 품절 → 재개 시각을 고르고 처리한다. 비우면 수동 해제까지 유지한다
2. 판매 재개 → 확인 팝업 후 처리한다

**조건**

* 단말에만 남기지 않는다
* 네트워크가 끊기면 단말에 두었다가 복구 시 전송한다

**예외**

* 단말에만 남기지 않는다. 서버로 올려 다른 채널에 함께 적용한다
* 네트워크가 끊기면 단말에 두고 미전송으로 표시한 뒤 복구 시 보낸다
* 가맹 어드민에서 이미 바꿨으면 마지막 값을 적용하고 처리자를 기록한다

#### KSK-ADMN-DEVC 단말 상태 확인

| 구분 | 내용 |
| --- | --- |
| 목적 | 프린터, 카드 단말, 네트워크 상태를 확인한다 |
| 대상 | 가맹 관리자 |
| 유형 | 전체화면 |
| 상태값 | 정상, 오류 |
| 연결 Flow | FL-403 키오스크 관리자 처리 · FL-424 단말 상태 확인 |

**처리**

1. 다시 확인 → 상태를 새로 읽어 표시한다
2. 시험 결제 → 소액 승인과 즉시 취소로 경로를 확인한다

**조건**

* 오류가 있으면 사유와 마지막 통신 시각을 표시한다

**예외**

* 오류가 있으면 사유와 마지막 통신 시각을 함께 표시한다
* 프린터 오류 상태에서도 주문은 받는다. 주문서는 화면으로 확인하게 한다
