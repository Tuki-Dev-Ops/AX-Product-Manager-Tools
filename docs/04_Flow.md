# 04. Flow Chart

## 1. 전체 Flow

### FL-001 서비스 전체 흐름

기준정보를 만들어 주문 채널로 내보내고, 고객 주문을 받아 매출로 집계하기까지의 전체 순서다. 네 채널이 하나의 업무로 이어지는 모습을 본다.

```text
서비스 개시
 ↓
[본사] FL-101
 ↓
[본사] 기준정보 확정
 ├─ 행사 → 상권 → 매장
 └─ 브랜드 → 매장 소속
 ↓
[매장] 메뉴 등록
 ↓
표시 정보 입력 완료?
 ├─ 아니오 → 판매 불가 상태로 둔다
 └─ 예 → 다음
 ↓
주문 채널 개시
 ├─ 하이브리드 웹앱
 ├─ 키오스크
 └─ 외부 POS
 ↓
고객 진입 경로?
 ├─ 웹앱 → FL-301
 ├─ 키오스크 → FL-401
 └─ 외부 POS → FL-501
 ↓
주문 생성
 ↓
[가맹] FL-203
 ↓
매장 접수?
 ├─ 아니오 → FL-903
 └─ 예 → 다음
 ↓
조리 → 수령
 ↓
주문 종결
 ↓
[본사] 매출 집계
 ↓
[본사] FL-103
 ↓
운영 판단
 ├─ 행사·상권별 실적 비교
 └─ 차기 행사 구성에 반영
 ↓
종료
```

### FL-002 주문 처리 전체 흐름

채널이 달라도 주문은 같은 상태를 지난다. 채널별로 갈라지는 지점과 다시 합쳐지는 지점을 본다.

```text
주문 시작
 ↓
채널 구분?
 ├─ 웹앱 → 비회원 주문, PG 결제
 ├─ 키오스크 → 현장 주문, VAN 결제
 └─ 외부 POS → 매장 자체 처리
 ↓
장바구니 구성
 ↓
주문 금액 확정
 ↓
결제 수단 확정
 ↓
결제 방식?
 ├─ PG → FL-301
 └─ VAN → FL-401
 ↓
결제 승인 성공?
 ├─ 아니오 → 주문 미생성 상태로 종료
 └─ 예 → 다음
 ↓
주문번호 발번
 ↓
주문 상태 = 접수 대기
 ↓
매장 알림 발송
 ↓
1분 내 접수?
 ├─ 아니오 → FL-903
 └─ 예 → 주문 상태 = 접수 완료
 ↓
조리 착수
 ↓
주문 상태 = 조리 완료
 ↓
수령 방식?
 ├─ 매장 식사 → 호출 후 전달
 └─ 포장 → 픽업대 전달
 ↓
주문 상태 = 수령 완료
 ↓
매출 확정
 ↓
종료
```

### FL-003 메뉴 등록과 반영 전체 흐름

매장이 등록한 메뉴가 각 채널에 반영되기까지의 경로다. 본사를 거치지 않는다.

```text
메뉴 변경 발생
 ↓
[매장] 변경 유형?
 ├─ 신규 등록 → 표시 정보 필수 입력 대상
 ├─ 가격 변경 → 진행 중 주문 영향 확인
 └─ 판매 중지 → 목록에서 제외
 ↓
[매장] FL-224
 ↓
[매장] FL-225
 ↓
표시 정보 입력 완료?
 ├─ 아니오 → 판매 불가 상태로 저장
 └─ 예 → 다음
 ↓
[매장] 저장
 ↓
채널별 반영 방식?
 ├─ 웹앱 → 다음 진입 시 즉시 반영
 ├─ 키오스크 → FL-402
 └─ 외부 POS → FL-501
 ↓
변경 이력 기록
 ├─ 변경 시각, 처리자
 └─ 변경 항목
 ↓
종료
```

### FL-004 결제·정산 전체 흐름

결제 승인부터 매장 정산까지의 경로다. 정산은 외부 결제대행사가 수행하고 본사는 대사만 한다.

```text
결제 요청
 ↓
결제 방식?
 ├─ PG → 인증 후 서버에서 승인 요청
 └─ VAN → 단말에서 직접 승인
 ↓
서버 금액 검증
 ↓
금액 일치?
 ├─ 아니오 → FL-902
 └─ 예 → 다음
 ↓
승인 요청 발송
 ↓
승인 결과 수신
 ├─ 성공 → 거래번호 기록
 └─ 실패 → 사유 기록 후 종료
 ↓
결과 유실 여부?
 ├─ 예 → FL-901
 └─ 아니오 → 다음
 ↓
매출 원장 기록
 ├─ 매장, 주문번호, 결제수단
 ├─ 승인금액, 승인시각, 거래번호
 └─ 취소 시 원거래 연결
 ↓
[결제대행사] 대금 정산
 ├─ 정산 주기에 따라 매장 계좌로 지급
 └─ 정산 명세 생성
 ↓
[본사] 정산 대사
 ↓
금액 불일치?
 ├─ 예 → 차이 내역 기록 후 결제대행사에 확인 요청
 └─ 아니오 → 대사 완료
 ↓
종료
```

### FL-005 매출 집계·통계 전체 흐름

주문 데이터가 행사와 상권 단위 통계로 올라가는 경로다. 어떤 행사의 어떤 상권이 잘 팔리는지 보기 위한 흐름이다.

```text
주문 종결
 ↓
매출 원장 적재
 ↓
집계 단위 산정
 ├─ 매장 단위 일 매출
 ├─ 브랜드 단위 합산
 ├─ 상권 단위 합산
 └─ 행사 단위 합산
 ↓
집계 시점?
 ├─ 당일 → 집계 시점 표시 후 잠정치 제공
 └─ 전일 이전 → 확정치 제공
 ↓
취소·환불 반영
 ├─ 원거래 차감
 └─ 취소 사유 분류
 ↓
[본사] FL-103
 ↓
[본사] FL-135
 ↓
비교 기준?
 ├─ 행사 간 비교 → 동일 기간 환산
 ├─ 상권 간 비교 → 매장 수로 나눈 평균
 └─ 브랜드 간 비교 → 메뉴 구성 차이 표시
 ↓
[가맹] FL-221
 ↓
종료
```

## 2. 내부 어드민


### FL-101 매장 개설

본사 운영자가 행사와 상권을 만들고 그 아래 매장을 등록한다. 메뉴는 매장이 직접 등록한다. 매장을 처음 열 때 한 번 수행한다.

```text
로그인 화면
 ↓
계정·비밀번호 입력
 ↓
2차 인증 입력
 ↓
인증 성공?
 ├─ 아니오 → FL-908
 └─ 예 → 다음
 ↓
행사 관리 화면
 ↓
행사 신규 등록?
 ├─ 예   → 행사명, 시작일, 종료일 입력 → 저장
 └─ 아니오 → 목록에서 행사 선택
 ↓
상권 관리 화면
 ↓
상권 신규 등록?
 ├─ 예   → 상권명 입력, 소속 행사 지정 → 저장
 └─ 아니오 → 목록에서 상권 선택
 ↓
브랜드 관리 화면
 ↓
브랜드 신규 등록?
 ├─ 예   → 브랜드명 입력 → 저장
 └─ 아니오 → 목록에서 브랜드 선택
 ↓
매장 등록 화면
 ↓
매장 정보 입력
 ├─ 사업자 정보 (상호, 사업자번호, 대표자, 연락처)
 ├─ 주소·좌표
 ├─ 영업시간·휴무일
 ├─ 브랜드 선택, 지점번호 입력
 └─ 채널 사용 여부 (웹앱 / 키오스크 / 외부 POS)
 ↓
사업자 상태 확인
 ↓
폐업 상태?
 ├─ 예   → 확인 안내 표시 → 매장 정보 입력으로 복귀
 └─ 아니오 → 다음
 ↓
매장 저장
 ↓
가맹 관리자 계정 발급
 ├─ 이메일과 초기 비밀번호
 └─ 담당 매장 범위 지정
 ↓
매장이 메뉴를 등록할 수 있는 상태
 ↓
종료
```

### FL-103 매출 통계 조회

기간과 축을 골라 매출을 조회한다. 행사와 상권을 축으로 비교해 어느 구간이 잘 팔리는지 확인한다.

```text
매출 화면 진입
 ↓
조회 조건 입력
 ├─ 기간
 ├─ 축 선택 (행사 / 상권 / 매장 / 채널 / 결제수단)
 └─ 비교 대상 선택
 ↓
조회 권한 있음?
 ├─ 아니오 → "조회 권한이 없습니다." 표시 → 종료
 └─ 예 → 다음
 ↓
집계 완료 구간?
 ├─ 예   → 집계 테이블 조회
 └─ 아니오 → 운영 데이터 조회, 집계 시점 표시
 ↓
조회 결과 있음?
 ├─ 아니오 → "조회 결과가 없습니다." 표시
 └─ 예 → 목록·비교 표시
 ↓
상세 조회
```

### FL-104 계정·권한 운영

계정을 만들고 역할과 접근 범위를 부여한다. 본사가 가맹 화면을 대신 보는 대행 접속과, 접속기록 점검을 함께 다룬다.

```text
계정 목록 화면
 ↓
계정 등록
 ├─ 계정 정보 입력 (이름, 이메일, 연락처)
 ├─ 역할 지정
 └─ 접근 범위 지정 (행사 / 상권 / 매장)
 ↓
이메일 중복?
 ├─ 예   → "이미 사용 중인 이메일입니다." 표시 → 계정 등록으로 복귀
 └─ 아니오 → 저장
 ↓
계정 등록 완료

[별도 경로] 대행 접속
대상 매장 선택
 ↓
대행 접속 권한 있음?
 ├─ 아니오 → "권한이 없습니다." 표시 → 종료
 └─ 예 → 대행 접속 실행
 ↓
가맹 어드민 화면 진입
 └─ 실제 조작자와 대상 계정을 함께 기록한다
 ↓
대행 종료 → 본래 계정으로 복귀

[별도 경로] 접속기록 점검
조회 조건 입력 (기간, 계정, 접속지)
 ↓
조회
 ↓
이상 징후 있음?
 ├─ 예   → 확인 대상으로 지정
 └─ 아니오 → 점검 완료 기록
```

### FL-105 매장 상태 전환

매장의 영업 시작과 종료를 처리한다. 상태에 따라 주문 채널에 노출할지가 결정된다.

```text
상권 상세 진입 → 매장 탭
 ↓
매장 선택
 ↓
전환할 상태 선택 (영업 시작 / 영업 종료)
 ↓
영업 종료인가?
 ├─ 아니오 → 채널 노출 시작
 └─ 예 → 다음
 ↓
진행 중 주문 존재?
 ├─ 예   → "진행 중 주문 완료 후 종료됩니다." 표시 → 완료 대기
 └─ 아니오 → 즉시 종료
 ↓
채널 노출 중단
 ↓
상태 전환 완료
```

## 3. 가맹 어드민


### FL-201 매점 운영

가맹 관리자가 로그인해 담당 매점의 정보와 영업 상태를 관리한다. 본사 확정이 필요한 항목은 변경 요청으로 처리한다.

```text
로그인 화면
 ↓
계정·비밀번호 입력
 ↓
2차 인증 입력
 ↓
인증 성공?
 ├─ 아니오 → FL-908
 └─ 예 → 담당 매장 확인
 ↓
담당 매장이 하나인가?
 ├─ 예   → 해당 매장으로 진입
 └─ 아니오 → 매장 선택 화면 → 매장 선택
 ↓
매점 홈
 ↓
처리 선택
 ├─ 매점 정보 조회 → 수정 항목 입력
 ├─ 영업 상태 변경 (일시중지 / 재개)
 └─ 매출 조회 → 담당 매장 범위로 제한
 ↓
직접 수정 가능 항목인가?
 ├─ 예   → 저장 → 즉시 반영
 └─ 아니오 → 변경 요청 등록 → 본사 확정 대기 → 확정 후 반영
```

### FL-202 품절 처리

매장에서 특정 메뉴의 판매를 중지한다. 재개 시각을 함께 받아 지정 시각에 자동으로 되돌린다.

```text
메뉴 목록 화면
 ↓
메뉴 선택
 ↓
판매 중지
 ↓
재개 시각 지정?
 ├─ 예   → 재개 시각 입력 → 해당 시각에 자동 재개
 └─ 아니오 → 수동 재개까지 유지
 ↓
채널 반영
 ├─ 웹앱      → 즉시. 담기 차단
 ├─ 키오스크   → 즉시. 목록에서 제외
 └─ 외부 POS  → 항목 단위 통지
 ↓
장바구니에 담긴 건 존재?
 ├─ 예   → 처리자와 시각을 기록하고 마지막 값을 적용
 └─ 아니오 → 품절 처리 완료
```

### FL-203 주문 접수

매장이 들어온 주문을 수락하고 수령까지 진행한다. 수락하면 매장 프린터로 주문서를 출력한다. 거절하거나 1분 내 응답하지 않으면 주문이 취소된다. 접수 완료 후 1분이 지나면 조리 중으로 자동 전환되고 그때부터 취소할 수 없다.

```text
주문 알림 수신
 ↓
주문 내용 확인
 ↓
1분 내 응답?
 ├─ 아니오 → FL-903
 └─ 예 → 다음
 ↓
주문 수락?
 ├─ 아니오 → FL-903
 └─ 예 → 주문 상태 = 접수 완료
 ↓
주문서 출력 요청
 ↓
프린터 출력 성공?
 ├─ 아니오 → 화면에 출력 실패 표시 → 재출력 또는 화면 확인
 └─ 예 → 주방이 주문서로 확인
 ↓
[서버] 접수 완료 후 1분 경과
 ↓
고객 취소 있었음?
 ├─ 예 → 취소 처리 후 종료
 └─ 아니오 → 주문 상태 = 조리 중
 ↓
조리 완료 처리
 ↓
고객 호출 발송
 ↓
수령 완료 처리
```

### FL-204 알레르기 정보 등록

알레르기 정보는 메뉴 단위로 등록하며 필수 입력이다. 법정 표시 의무 대상 여부와 무관하게 항상 받는다. 옵션 단위 등록은 두지 않는다. 옵션 선택에 따라 알레르기 유발물질이 달라지는 메뉴는 조합별로 상품을 복제해 각각 등록한다.

```text
메뉴 선택
 ↓
알레르기 유발물질 선택 (법정 18개 품목)
 ↓
영양성분 입력 (열량, 당류, 단백질, 포화지방, 나트륨)
 ↓
옵션이 알레르기 유발물질을 바꾸는가?
 ├─ 아니오 → 옵션으로 유지
 └─ 예 → 상품 복제
 ↓
상품 복제 처리
 ├─ 조합별 메뉴 생성
 ├─ 조합별 알레르기 정보 입력
 ├─ 원 메뉴에서 해당 옵션 제거
 └─ 복제 관계 기록   ← 원 메뉴 수정 시 복제본을 확인 대상으로 표시
 ↓
필수 항목 모두 입력?
 ├─ 아니오 → 저장 차단, 미입력 항목 표시 → 알레르기 유발물질 선택으로 복귀
 └─ 예 → 저장
 ↓
채널 반영 → 메뉴 정보와 함께 제공
```

## 4. 하이브리드 웹앱


### FL-301 웹앱 주문·결제

고객이 QR이나 링크로 매장에 들어와 메뉴를 담고 결제까지 마친다. 회원 가입과 로그인은 없다. 결제는 인증과 승인이 분리되며, 그 사이에 서버가 주문 금액을 검증한다.

```text
QR 촬영 또는 링크 진입
 ↓
QR에 매장·테이블 포함?
 ├─ 예   → 매장 자동 확정
 └─ 아니오 → 매장 목록 → 매장 선택
 ↓
주문 가능한 매장?
 ├─ 영업시간 외   → "영업시간이 아닙니다." 표시, 메뉴 열람만 허용 → 종료
 ├─ 영업 일시중지  → 준비중 표시, 재개 시각 안내 → 종료
 ├─ 매장 반경 밖   → "매장에서 주문해 주세요." 표시 → 종료
 └─ 정상         → 다음
 ↓
수령 방식 선택 (매장 식사 / 포장)
 ↓
메뉴 조회
 ├─ 판매 시간 외 메뉴 → 미노출
 ├─ 품절 메뉴        → 목록에서 제외
 └─ 원산지·알레르기 표시
 ↓
메뉴 선택
 ↓
옵션 선택
 ↓
필수 옵션 선택 완료?
 ├─ 아니오 → "필수 옵션을 선택해 주세요." 표시 → 옵션 선택으로 복귀
 └─ 예 → 수량 지정
 ↓
담기 방식?
 ├─ 장바구니에 담기 → 장바구니 → 메뉴를 더 고르거나 주문하기
 └─ 바로 결제      → 장바구니를 거치지 않고 결제 상세로 이동
 ↓
다른 매장 항목 존재?
 ├─ 예   → 초기화 확인 → 초기화
 └─ 아니오 → 다음
 ↓
결제 상세 작성
 ├─ 이름 입력
 ├─ 휴대폰번호 입력      ← 알림톡 발송과 주문 조회에 쓴다
 ├─ 개인정보 수집 동의
 ├─ 요청사항 입력
 └─ 최종 금액 확정
 ↓
주문 생성
 └─ 서버에 주문번호와 최종 금액 저장   ← 위변조 검증 기준값
 ↓
결제창 호출
 ↓
결제수단 인증
 ↓
인증 성공?
 ├─ 아니오 → "결제수단 인증에 실패했습니다." 표시 → 결제수단 선택으로 복귀
 └─ 예 → 다음
 ↓
인증 결과 수신 성공?
 ├─ 아니오 → FL-901
 └─ 예 → 다음
 ↓
저장 금액과 일치?
 ├─ 아니오 → FL-902
 └─ 예 → 다음
 ↓
승인 요청 (멱등키 부여)
 ↓
승인 성공?
 ├─ 실패    → "결제에 실패했습니다." 표시, 주문 미확정 → 결제수단 선택으로 복귀
 ├─ 응답 없음 → FL-901
 └─ 예 → 다음
 ↓
주문 확정
 ↓
매장 전달 → FL-203
 ↓
접수 알림톡 발송
 ↓
주문 완료 화면
```

### FL-302 주문 상태 확인·픽업

고객이 접수와 준비 상태를 확인하고 매장에서 주문을 수령한다. 회원 계정이 없으므로 주문번호와 휴대폰번호로 조회한다. 상태는 서버에서 조회한다.

```text
주문 완료 화면 또는 알림톡 링크
 ↓
주문번호와 휴대폰번호로 조회
 ↓
주문 확인?
 ├─ 아니오 → "주문을 찾을 수 없습니다." 표시 → 종료
 └─ 예 → 다음
 ↓
주문 상태 조회
 ↓
현재 상태?
 ├─ 접수 대기 → 대기 안내 표시
 ├─ 접수 완료  → 준비 중 표시
 ├─ 취소     → 취소 사유 표시 → 종료
 └─ 조리 완료 → 준비 완료 알림톡 발송
 ↓
매장 방문
 ↓
주문번호 확인
 ↓
수령 완료
```

### FL-303 주문 취소

고객이 접수 완료 후 1분 안에 주문을 취소한다. 그 시간이 지나면 조리 중으로 자동 전환되어 취소할 수 없다. 주문 취소와 결제 취소를 함께 처리한다.

```text
주문번호와 휴대폰번호로 조회
 ↓
주문 선택
 ↓
주문 상태가 접수 대기 또는 접수 완료?
 ├─ 아니오 → "조리가 시작되어 취소할 수 없습니다. 매장에 문의해 주세요." 표시 → 종료
 └─ 예 → 다음
 ↓
취소 확인
 ↓
결제 취소 요청 (멱등키 부여)
 ↓
취소 성공?
 ├─ 아니오 → 취소 대기 상태로 기록 → 재시도
 └─ 예 → 주문 상태 취소로 변경
 ↓
취소 알림 발송
```

## 5. 키오스크


### FL-401 키오스크 주문·결제

고객이 매장 키오스크에서 직접 주문하고 카드 단말로 결제한다. 결제가 끝나면 주문번호를 발행하고 주방에 전달한다.

```text
대기화면
 ↓
화면 터치
 ↓
두 취식유형을 운영?
 ├─ 아니오 → 자동 확정
 └─ 예 → 취식유형 선택 (먹고가기 / 포장)
 ↓
카테고리·메뉴 선택
 ├─ 품절 메뉴        → 목록에서 제외
 ├─ 판매 시간 외 메뉴 → 미노출
 └─ 원산지·알레르기 표시
 ↓
옵션 선택
 ↓
필수 옵션 선택 완료?
 ├─ 아니오 → 진행 불가 안내 → 옵션 선택으로 복귀
 └─ 예 → 수량 지정 → 장바구니에 담기
 ↓
주문 내역 확인
 ↓
결제수단 선택
 ├─ 카드
 └─ 간편결제 → 바코드·QR 스캔
 ↓
결제 금액 5만원 초과?
 ├─ 예   → 할부 개월 입력
 └─ 아니오 → 다음
 ↓
단말 승인 요청 전송
 ↓
승인 성공?
 ├─ 거절     → 오류 표시 → 결제수단 선택으로 복귀
 ├─ 응답 없음  → FL-904
 ├─ 판단 불가  → FL-904
 └─ 예 → 다음
 ↓
결제 금액 5만원 이상?
 ├─ 예   → 사인패드 서명
 └─ 아니오 → 서명 생략
 ↓
주문 서버 전송
 ↓
전송 성공?
 ├─ 아니오 → FL-905
 └─ 예 → 다음
 ↓
주문번호 발행
 ↓
영수증 출력
 ↓
주방 전달 → 접수 완료
 ↓
고객 호출 방식?
 ├─ 주문번호   → 화면 표시
 └─ 휴대폰번호 → 번호 입력 → 알림톡 발송
 ↓
대기화면 복귀
```

### FL-402 메뉴 마스터 수신

단말이 유휴 상태에 들어갈 때 변경된 메뉴를 내려받아 반영한다. 주문 중에는 화면이 바뀌지 않는다.

```text
단말 유휴 상태 진입
 ├─ 대기화면 무조작 지속
 └─ 결제 완료 후 대기화면 전환
 ↓
서버에 최종 변경 시각 조회
 ↓
변경 있음?
 ├─ 아니오 → 종료
 └─ 예 → 변경분 수신
 ↓
단말 반영
 ↓
반영 성공?
 ├─ 아니오 → 직전 상태 유지, 오류 보고
 └─ 예 → 반영 시각 기록
```

### FL-403 키오스크 관리자 처리

매장 담당자가 인증 후 키오스크 설정에 들어간다. 품절 처리, 환불, 단말 상태 확인을 다룬다.

```text
관리자 인증 입력
 ↓
인증 성공?
 ├─ 아니오 → 주문 화면 복귀
 └─ 예 → 관리자 화면
 ↓
처리 선택
 ├─ 품절 설정    → 메뉴 선택 → 판매 중지·재개
 ├─ 거래내역 조회 → 건 선택 → 환불 → 원 결제수단 확인 → 취소 처리
 └─ 단말 상태 확인 → 프린터·단말·네트워크 상태 표시
 ↓
종료 → 대기화면 복귀
```

## 6. 외부 POS 연동


### FL-501 메뉴 정보 제공

ERP가 매장과 메뉴 정보를 외부 POS에 제공한다. 변경이 생기면 통지를 보내고, 상대가 조회해 가져간다.

```text
[사전] 연동 계정 등록
접근 키 발급
 ↓
매장 범위 지정
 ↓
연동 활성화

[ERP] 메뉴 또는 매장 정보 변경 확정
 ↓
변경 통지 발송   ← 매장 식별자와 변경 시각만 전송
 ↓
2xx 응답 수신?
 ├─ 아니오 → 재전송 → 반복 실패 시 전송 중단
 └─ 예 → 다음
 ↓
[외부 POS] 매장·메뉴 조회
 ↓
[외부 POS] 자체 반영

[별도 경로] 백업 폴링
[외부 POS] 최종 변경 시각 조회   … 30분 주기
 ↓
변경 있음?
 ├─ 아니오 → 종료
 └─ 예 → 조회 후 반영

[별도 경로] 품절·일시중지
[ERP] 상태 변경 → 항목 단위 통지   … 실시간
```

## 7. 내부 어드민 화면별 Flow

화면 하나에 들어와서 나갈 때까지의 흐름이다. 화면ID는 05 IA의 화면 목록을 따른다.

### FL-110 로그인 (ADM-AUTH-LOGIN)

```text
로그인 화면 진입
 ↓
계정·비밀번호 입력
 ↓
입력값 있음?
 ├─ 아니오 → 안내 문구 표시 → 계정·비밀번호 입력으로 복귀
 └─ 예 → 다음
 ↓
계정 상태 확인
 ↓
계정 잠금 상태?
 ├─ 예 → 관리자 문의 안내 표시 → 종료
 └─ 아니오 → 다음
 ↓
비밀번호 일치?
 ├─ 아니오 → FL-908
 └─ 예 → 다음
 ↓
비밀번호 변경 필요?
 ├─ 예 → 비밀번호 변경 화면으로 이동 → 변경 후 다음
 └─ 아니오 → 다음
 ↓
2차 인증 화면으로 이동
```

### FL-111 2차 인증 (ADM-AUTH-OTP)

```text
2차 인증 화면 진입
 ↓
등록 단말 있음?
 ├─ 아니오 → 단말 등록 안내 표시 → 등록 후 다음
 └─ 예 → 다음
 ↓
인증번호 발송
 ↓
인증번호 입력
 ↓
유효시간 내 입력?

 └─ 예 → 다음
 ↓
인증번호 일치?
 ├─ 아니오 → 실패 횟수 누적 → 인증번호 입력으로 복귀

 ↓
접속기록 기록

 └─ 인증 수단
 ↓
대시보드로 이동
```

### FL-112 대시보드 (ADM-HOME-MAIN)

대시보드는 조치할 항목을 먼저 보여준다. 추세와 비교는 매출 화면에서 본다.

```text
대시보드 진입
 ↓
[서버] 이상 항목 판정
 ├─ 단말 미연결   ← 마지막 통신 30분 경과
 ├─ 접수 지연     ← 접수 대기가 30초를 넘긴 주문
 ├─ 매출 급락     ← 최근 1시간 주문이 같은 요일 같은 시간대 평균의 30% 미만
 └─ 품절 급증     ← 판매 메뉴의 30% 이상이 품절
 ↓
이상 항목 있음?
 ├─ 예 → 지금 확인할 것 영역에 표시. 발생 시각 순으로 정렬
 └─ 아니오 → "확인할 항목이 없습니다." 표시
 ↓
[서버] 오늘 실적 조회
 └─ 집계 시점을 함께 표시한다. 당일은 잠정치다
 ↓
[서버] 처리 대기 조회
 └─ 매점 정보 변경 요청
 ↓
[서버] 정산 상태 조회
 └─ 최근 대사 기준일별 완료 여부, 불일치, 미정산
 ↓
[서버] 개시 준비 조회
 ↓
개시 7일 이내 행사 있음?
 ├─ 예 → 매장·메뉴·표시 정보·심사 완료 수를 표시
 └─ 아니오 → 개시 준비 영역을 숨긴다
 ↓
항목 선택?
 ├─ 단말 미연결 → FL-232
 ├─ 접수 지연   → 해당 매장의 주문으로 이동
 ├─ 매출 급락   → FL-116
 ├─ 품절 급증   → 해당 매장 상세로 이동
 ├─ 변경 요청   → 해당 매장 상세로 이동
 ├─ 대사 보기   → FL-141
 ├─ 개시 준비   → FL-116
 └─ 선택 없음   → 대시보드 유지
 ↓
종료
```

이상 항목의 판정 기준은 고정값이다. 매장마다 다르게 두지 않는다. 기준을 매장별로 두면 어느 매장이 왜 걸렸는지 설명할 수 없다.

### FL-113 행사 목록·등록 (ADM-EVNT-LIST / ADM-EVNT-FORM / ADM-ADDR-FIND)

```text
행사 목록 진입
 ↓
검색 조건 입력
 ├─ 행사명
 └─ 진행 상태 (진행 전, 진행 중, 종료)
 ↓
목록 표시
 ↓
동작 선택?
 ├─ 신규 등록 → 행사 등록 화면
 ├─ 행 선택 → 행사 수정 화면
```

### FL-421 관리자 메뉴 (KSK-ADMN-MAIN)

```text
관리자 메뉴 표시
 ↓
단말 상태 요약 표시
 ├─ 프린터
 ├─ 결제 단말
 └─ 네트워크
 ↓
동작 선택?
 ├─ 메뉴 갱신 → FL-425
 ├─ 판매 메뉴 설정 → FL-426
 ├─ 품절 설정 → FL-423
 ├─ 단말 상태 → FL-424
 └─ 나가기 → 대기화면으로 복귀
 ↓
종료
```

### FL-423 품절 설정 (KSK-ADMN-SOUT)

현장에서 재료가 떨어졌을 때 단말에서 바로 처리한다. 단말에만 반영하지 않고 ERP로 올려 다른 채널에도 함께 적용한다.

```text
품절 설정 화면 표시
 ↓
메뉴 목록과 판매 상태 표시
 ↓
상태 변경
 ├─ 품절 처리 (재개 시각 지정 가능)
 └─ 판매 재개
 ↓
네트워크 연결 정상?
 ├─ 아니오 → 단말에만 반영하고 복구 시 전송 예약 → 화면에 미전송 표시
 └─ 예 → 다음
 ↓
[서버] ERP 반영
 ├─ 매장별 메뉴 설정의 품절 상태를 바꾼다
 ├─ 하이브리드 웹앱 목록에서 제외한다
 └─ 외부 POS에 항목 단위로 통지한다
 ↓
가맹 어드민에서 이미 변경함?
 ├─ 예 → 처리자와 시각을 기록하고 마지막 값을 적용
 └─ 아니오 → 다음
 ↓
화면 표시 갱신
 ↓
관리자 메뉴로 복귀
```

### FL-425 메뉴 갱신 (KSK-ADMN-SYNC)

단말은 유휴 시점과 결제 완료 시점에 메뉴를 확인한다. 매장이 메뉴를 고치고 바로 반영하고 싶을 때 이 화면에서 직접 받아온다.

```text
메뉴 갱신 화면 표시
 ↓
현재 단말 메뉴 정보 표시
 ├─ 마지막 갱신 시각
 └─ 메뉴 수, 카테고리 수
 ↓
[매장] 갱신 선택
 ↓
주문 진행 중인가?
 ├─ 예 → 진행 중 안내 표시. 주문이 끝난 뒤 갱신한다 → 종료
 └─ 아니오 → 다음
 ↓
[서버] 변경분 조회
 └─ 마지막 갱신 시각 이후 변경만 받는다
 ↓
변경 있음?
 ├─ 아니오 → 최신 상태 안내 표시 → 관리자 메뉴로 복귀
 └─ 예 → 다음
 ↓
변경 내용 표시
 ├─ 추가된 메뉴
 ├─ 수정된 메뉴와 가격
 └─ 삭제된 메뉴
 ↓
[매장] 적용 선택
 ↓
[단말] 메뉴 반영
 ↓
반영 성공?
 ├─ 아니오 → 실패 사유 표시. 기존 메뉴를 유지한다 → 관리자 메뉴로 복귀
 └─ 예 → 갱신 시각 기록
 ↓
관리자 메뉴로 복귀
```

### FL-426 판매 메뉴 설정 (KSK-ADMN-OPEN)

그날 준비된 메뉴만 화면에 연다. 매장별 메뉴 설정의 노출 여부를 바꾸는 것이므로 단말에만 적용되지 않는다.

```text
판매 메뉴 설정 화면 표시
 ↓
카테고리별 메뉴 목록 표시
 ├─ 메뉴명, 판매가
 ├─ 노출 여부
 └─ 품절 상태
 ↓
[매장] 노출 여부 변경
 ├─ 개별 선택
 └─ 카테고리 단위 일괄 선택
 ↓
노출 메뉴가 하나도 없음?
 ├─ 예 → 최소 한 개 필요 안내 표시 → 노출 여부 변경으로 복귀
 └─ 아니오 → 다음
 ↓
확인 팝업 표시
 └─ 여는 메뉴 수와 닫는 메뉴 수를 함께 표시
 ↓
확인 선택?
 ├─ 아니오 → 판매 메뉴 설정 화면 유지
 └─ 예 → 다음
 ↓
[서버] ERP 반영
 ├─ 매장별 메뉴 설정의 노출 여부를 바꾼다
 ├─ 하이브리드 웹앱에 함께 적용한다
 └─ 외부 POS에 변경을 통지한다
 ↓
반영 성공?
 ├─ 아니오 → 실패 사유 표시. 이전 상태를 유지한다
 └─ 예 → 처리자와 시각을 기록
 ↓
관리자 메뉴로 복귀
```

### FL-424 단말 상태 확인 (KSK-ADMN-DEVC)

```text
단말 상태 화면 표시
 ↓
연결 점검 실행
 ├─ 프린터 응답
 ├─ 결제 단말 응답
 └─ 서버 통신
 ↓
오류 항목 있음?
 ├─ 예 → 항목별 조치 안내 표시
 └─ 아니오 → 정상 표시
 ↓
재점검 선택?
 ├─ 예 → 연결 점검 실행으로 복귀
 └─ 아니오 → 다음
 ↓
점검 결과 전송
 ↓
전송 성공?
 ├─ 아니오 → 복구 시 재전송 예약
 └─ 예 → 다음
 ↓
관리자 메뉴로 복귀
```

## 11. 예외 Flow


### FL-901 결제 결과 유실

발생 조건: 결제 앱에서 복귀하지 못했거나, 승인 요청에 응답이 없다.

```text
결과 미수신 감지
 ↓
서버가 결제 상태 조회
 ↓
결제 상태?
 ├─ 승인됨   → 주문 확정 → 완료 화면
 ├─ 미승인   → 주문 미확정 → 재시도 안내
 └─ 판단 불가 → 대기 상태 유지
 ↓
웹훅 수신 대기
 ↓
일정 시간 내 승인 통지 수신?
 ├─ 예   → 주문 확정
 └─ 아니오 → 결제 취소 요청 → 주문 실패 처리
```

같은 주문에 대한 재시도는 동일 멱등키를 쓴다. 중복 승인이 발생하지 않는다.

### FL-902 금액 검증 실패

발생 조건: 저장된 금액과 결제창에서 돌아온 금액이 다르다.

```text
불일치 감지
 ↓
승인 요청 중단   ← 승인 API를 호출하지 않는다
 ↓
주문 실패 처리
 ↓
"결제 정보가 올바르지 않습니다. 다시 시도해 주세요." 표시
 ↓
기록 남김
```

### FL-903 매장 미접수

발생 조건: 매장이 주문을 거절했거나 제한 시간 내 응답하지 않았다.

```text
거절 또는 시간 초과
 ↓
주문 취소 처리
 ↓
결제 전액 취소 요청 (멱등키 부여)
 ↓
취소 성공?
 ├─ 아니오 → 취소 대기로 기록 → 재시도 → 미해결 시 운영 확인 대상
 └─ 예 → 다음
 ↓
고객 알림 발송
 ↓
주문 상태 취소로 변경
```

### FL-904 VAN 망취소

발생 조건: 승인 응답 타임아웃, 승인 중 통신 단절, 응답을 받았으나 성공 여부를 판단할 수 없음.

```text
이상 감지
 ↓
망취소 요청   ← 원 승인 요청과 동일한 데이터를 재사용한다
 ↓
망취소 성공?
 ├─ 아니오 → 재시도 → 미해결 시 관리자 확인 대상으로 기록
 └─ 예 → 결제 미완료 처리
 ↓
"결제를 처리하지 못했습니다. 다시 시도해 주세요." 표시
 ↓
결제수단 선택으로 복귀
```

승인은 성공했으나 금액이 불일치하거나 주문 저장에 실패한 경우에도 망취소를 호출한다.

### FL-905 키오스크 네트워크 단절

발생 조건: 단말이 서버에 연결하지 못한다.

```text
연결 실패 감지
 ↓
결제 이전 단계인가?
 ├─ 예 → 주문 불가 안내 → 대기화면 복귀
 └─ 아니오 → 다음
 ↓
승인 결과를 단말에 보관
 ↓
주문번호 발행과 영수증 출력은 정상 진행
 ↓
연결 복구 대기
 ↓
일정 시간 내 복구?
 ├─ 아니오 → 관리자 확인 대상으로 표시
 └─ 예 → 서버로 재전송
 ↓
전송 성공?
 ├─ 아니오 → 재시도
 └─ 예 → 보관분 삭제
```

카드 승인은 온라인 실시간이 전제이므로 오프라인 결제를 시도하지 않는다.

### FL-908 로그인 실패

발생 조건: 인증에 실패했다.

```text
인증 실패
 ↓
실패 횟수 누적
 ↓
제한 횟수 도달?
 ├─ 아니오 → "이메일 또는 비밀번호가 일치하지 않습니다." 표시 → 로그인 화면 복귀
 └─ 예 → 계정 잠금 → 관리자 해제 안내
 ↓
기록 남김
```

## 12. 주문 상태

전 채널에 같은 상태값을 쓴다.

```text
접수 대기
 ↓
매장 수락?
 ├─ 거절 또는 미응답 1분 → 취소
 └─ 수락 → 다음
 ↓
접수 완료
 ↓
1분 안에 취소 요청 있음?
 ├─ 예 → 취소
 └─ 아니오 → 다음
 ↓
조리 중 (자동 전환)
 ↓
조리 완료
 ↓
수령 완료
```

| 상태 | 전환 조건 | 취소 |
| --- | --- | --- |
| 접수 대기 | 결제 승인 완료. 매장 수락 전 | 고객 취소, 매장 거절, 미응답 자동 취소 |
| 접수 완료 | 매장이 수락. 키오스크 주문은 결제 완료 시 바로 이 상태로 들어간다 | 고객 취소, 매장 취소 |
| 조리 중 | 접수 완료 후 1분 경과. 자동 전환한다 | 불가 |
| 조리 완료 | 매장이 완료 처리. 고객 호출을 발송한다 | 불가 |
| 수령 완료 | 고객이 수령 | 불가 |
| 취소 | 취소 확정. 결제 취소를 함께 처리한다 | |

조리 중 전환은 매장이 조작하지 않는다. 접수 완료 후 1분이 지나면 시스템이 자동으로 바꾼다. 매장마다 취소 가능 구간이 달라지지 않게 한다.

취소는 접수 대기와 접수 완료 상태에서만 할 수 있다. 취소 가능 시간은 접수 완료 후 1분이다.

조리 시작 이후에는 주문 취소 기능을 제공하지 않는다. 고객이 환불을 요구하면 매장이 현장에서 판단한다. 플랫폼은 환불 요청 화면이나 승인 절차를 두지 않는다. 매장이 환불하기로 정한 경우 카드 단말 자체의 취소 기능으로 처리한다. 키오스크 관리자 모드에는 환불 화면을 두지 않는다.

시간 기준이 두 곳에 있다. 접수 대기에서 1분은 매장이 응답하지 않아 자동 취소하는 시간이고, 접수 완료에서 1분은 고객이 취소할 수 있는 시간이다.

서빙 완료는 후불 홀 매장에서만 필요하므로 현재 범위에서 제외한다.
