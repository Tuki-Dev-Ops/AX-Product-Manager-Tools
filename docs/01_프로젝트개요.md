# 01. 프로젝트 개요

## 1. 추진 배경

본사는 여러 브랜드를 행사 단위로 운영한다. 행사마다 상권을 나누고 그 아래 매장을 배치한다. 행사가 끝나면 매장을 철수하고 다음 행사에 다시 배치한다.

현재는 매장별 판매 실적을 행사가 끝난 뒤에 모아서 확인한다. 행사가 진행되는 동안에는 어느 상권이 잘 팔리는지 판단할 근거가 없다. 그래서 매장 배치와 메뉴 구성을 다음 행사에 반영하는 시점이 한 주기 늦는다.

메뉴 정보는 매장이 각자 관리한다. 표시 정보를 종이나 개별 도구로 다루다 보니 누락이 생기고, 주문 채널마다 다시 입력한다. 행사가 시작될 때마다 같은 작업을 반복한다.

## 2. 목적

세 가지를 해결한다.

| 문제 | 목적 |
| --- | --- |
| 행사 종료 후에야 상권별 실적을 알 수 있다 | 행사 진행 중 일 단위로 상권별 매출을 확인한다 |
| 표시 정보 누락과 채널별 재입력이 생긴다 | 매장이 한 번 등록하면 모든 주문 채널이 같은 정보를 쓴다 |
| 주문 채널마다 메뉴 정보가 다르다 | 하나의 메뉴 마스터를 웹앱, 키오스크, 외부 POS가 함께 사용한다 |

### 목표

| ID | 목표 | 달성 판단 기준 |
| --- | --- | --- |
| GO-01 | 행사 진행 중 상권별 매출을 확인한다 | 전일 매출이 확정치로, 당일 매출이 잠정치로 조회된다 |
| GO-02 | 행사 간과 상권 간 실적을 비교한다 | 기간과 매장 수가 다른 대상을 같은 기준으로 환산해 비교한다 |
| GO-03 | 매장이 한 번 등록한 메뉴를 모든 채널이 쓴다 | 매장에서 메뉴를 바꾸면 웹앱, 키오스크, 외부 POS에 같은 값이 나간다 |
| GO-04 | 법정 표시 정보를 누락 없이 관리한다 | 알레르기와 원산지가 입력되지 않은 메뉴는 저장되지 않는다 |
| GO-05 | 매장 개설과 메뉴 등록을 분리한다 | 본사가 매장을 열면 매장이 바로 메뉴를 등록할 수 있다 |

### 기대효과

| 항목 | 내용 |
| --- | --- |
| 운영 판단 시점 | 행사 종료 후에서 행사 진행 중으로 앞당긴다 |
| 메뉴 정보 관리 | 채널마다 반복하던 등록을 매장 단위 1회로 줄인다 |
| 표시 정보 누락 | 등록 단계에서 막아 매장 운영 중 발생을 없앤다 |

수치 목표는 정하지 않는다. 현재 운영의 기준값이 확인되지 않았기 때문이다. 대신 구축과 함께 측정을 시작해 다음 행사부터 비교할 수 있게 한다.

| 측정 항목 | 수집 방법 | 비교 시점 |
| --- | --- | --- |
| 매장당 메뉴 등록 소요 시간 | 메뉴 가져오기 사용 여부와 등록 완료까지의 시각 차 | 두 번째 행사부터 |
| 표시 정보 누락 건수 | 판매 불가 상태로 남은 메뉴 수 | 행사 종료 시 |
| 실적 확인 시점 | 매출 집계 완료 시각과 운영자 조회 시각 | 매 행사 |
| 주문 미접수 건수 | 제한 시간 초과로 자동 취소된 건 | 매 행사 |

첫 행사는 기준값을 만드는 회차로 본다. 개선 폭은 두 번째 행사부터 판정한다.

## 3. 서비스 개요

F&B 매장 운영을 위한 플랫폼이다. 본사 ERP에서 행사, 상권, 매장, 메뉴 정보를 관리하고, 주문 채널이 이 정보를 받아 사용한다.

정보 계층은 다음과 같이 정의한다.

```ia
본사 :: 전체 기준
  행사 :: 기간 단위 운영
    상권 :: 지역 구분
      매장 :: 브랜드와 지점번호를 갖는다
  브랜드 :: 메뉴를 소유한다
    카테고리 :: 상품 분류
      메뉴 :: 판매 단위
```
