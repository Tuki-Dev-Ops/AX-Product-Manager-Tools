# 05. IA

## 1. 화면ID 부여 규칙

```text
{채널}-{업무}-{유형}
```

| 구분 | 값 |
| --- | --- |
| 채널 | ADM 내부 어드민, STR 가맹 어드민, WEB 하이브리드 웹앱, KSK 키오스크 |
| 업무 | 3~4자리 영문 약어. 업무 영역을 가리킨다 |
| 유형 | LIST 목록, DETAIL 상세, FORM 등록·수정, MAIN 메인, POPUP 팝업, 그 밖의 화면은 성격을 나타내는 약어 |

한 번 부여한 화면ID는 바꾸지 않는다. 화면이 삭제되어도 재사용하지 않는다.

## 2. 화면 유형

| 유형 | 정의 |
| --- | --- |
| 페이지 | 독립된 주소를 갖는 화면 |
| 레이어팝업 | 현재 화면 위에 겹쳐 뜨는 화면 |
| 전체화면 | 키오스크처럼 주소 없이 전환되는 화면 |

경고와 확인 대화상자는 IA에 넣지 않는다. 화면설계서의 디스크립션에서 다룬다.

| 관리자 |  |  | KSK-ADMN-SOUT | 품절 설정 | 전체화면 | 가맹 관리자 | 판매중, 품절 | 단말에서 품절을 설정하고 ERP로 올린다 | 단말에만 남기지 않는다. 네트워크가 끊기면 단말에 두었다가 복구 시 전송한다 |
| 관리자 |  |  | KSK-ADMN-DEVC | 단말 상태 확인 | 전체화면 | 가맹 관리자 | 정상, 오류 | 프린터, 카드 단말, 네트워크 상태를 확인한다 | 오류가 있으면 사유와 마지막 통신 시각을 표시한다 |

## 6. 공통 화면 규칙

| 항목 | 규칙 |
| --- | --- |
| 목록 화면 | 검색 조건, 목록, 페이지네이션을 둔다. 결과가 없으면 "조회 결과가 없습니다."를 표시한다 |
| 등록·수정 화면 | 필수 항목을 표시한다. 검증에 실패하면 해당 항목에 오류를 표시하고 저장을 막는다 |
| 검증 시점 | 저장을 누를 때 전체 항목을 한 번에 검증한다. 입력 도중에는 오류를 띄우지 않는다 |
| 오류 표시 | 오류가 있는 항목마다 칸 아래에 문구를 둔다. 오류가 둘 이상이면 화면 위에 건수를 함께 표시하고 첫 오류 항목으로 이동한다 |
| 오류 해제 | 해당 항목을 고치면 그 항목의 오류만 지운다. 다른 항목의 오류는 남긴다 |
| 오류 문구 | 무엇을 해야 하는지 적는다. "필수 항목입니다"가 아니라 "행사명을 입력해 주세요."로 쓴다 |
| 조회 조건 | 값이 셋 이상인 조건은 드롭다운으로 둔다. 라디오 버튼은 값이 둘일 때만 쓴다 |
| 조회 조건 배치 | 첫 줄에 기간과 상태 같은 조건을 두고, 둘째 줄 왼쪽에 검색어를 둔다 |
| 동작 버튼 위치 | 조회는 검색어 칸 오른쪽에 붙인다. 등록은 첫 줄 오른쪽 끝에 둔다 |
| 초기화 버튼 | 기간, 상태, 검색어 중 하나라도 설정된 상태에서만 조회 버튼 오른쪽에 표시한다 |
| 조회 건수 | 조회 조건 줄 오른쪽 끝에 조건에 맞는 전체 건수를 "총 24건"으로 표시한다. 결과가 없으면 "0건"으로 표시한다 |
| 조회 조건 크기 | 입력 칸과 버튼의 높이를 같게 한다. 날짜와 상태는 200px, 검색어는 320px, 버튼은 120px을 넘기지 않고 왼쪽부터 붙여 둔다 |
| 등록·수정 | 모달로 연다. 목록을 벗어나지 않아 조회 조건과 스크롤 위치가 유지된다 |
| 모달 뒤 화면 | 목록을 그대로 두고 덮개만 덮는다. 어느 목록에서 열었는지 보이게 한다 |
| 권한 표기 | 여러 유형이 함께 쓰는 화면은 본사 운영자, 가맹 관리자, 고객 순으로 적는다 |
| 입력 항목 | 라벨을 칸 위에 두고 칸 안에는 안내 문구나 입력값만 넣는다. 라벨을 칸 안에 넣지 않는다. 필수 항목은 라벨 옆에 별표로 표시한다 |
| 계정 식별자 | 로그인 아이디는 이메일을 쓴다. 별도 아이디를 두지 않는다. 한 번 등록한 이메일은 바꿀 수 없다 |
| 모달 머리말 | 화면 이름만 둔다. 저장과 취소는 아래 버튼으로만 둔다 |
| 색 사용 | 강조색은 기본 버튼, 선택한 탭, 입력 중인 칸에만 쓴다. 오류는 별도 색으로 구분한다. 그 밖에는 무채색을 쓴다 |
| 입력 칸 상태 | 기본, 입력 중, 입력됨, 읽기 전용, 오류 다섯 가지를 구분한다. 읽기 전용은 배경을 채우고 오류는 테두리와 문구를 함께 바꾼다 |
| 칸 종류 유지 | 상태가 바뀌어도 칸의 종류는 그대로 둔다. 드롭다운은 화살표, 날짜는 달력, 검색 입력은 돋보기를 오류 상태에서도 유지한다 |
| 펼친 상태 | 드롭다운, 달력, 검색은 펼친 화면을 함께 정의한다. 드롭다운과 달력은 칸 바로 아래에 띄우고 주소 검색은 팝업으로 연다 |
| 구역 제목 | 화면 제목과 같은 내용을 되풀이하는 구역 제목은 두지 않는다. 구분이 필요한 구역에만 붙인다 |
| 표 정렬 | 숫자 열은 오른쪽, 글자 열은 왼쪽으로 맞춘다. 머리글과 본문의 열 너비를 같게 한다 |
| 조회 조건 유지 | 목록에서 상세로 갔다 돌아오면 조건과 페이지와 스크롤 위치를 되살린다. 뒤로 가기와 목록 버튼이 같게 동작한다 |
| 빈 상태 | 목록 영역 전체를 쓰고 아이콘과 문구를 가운데 정렬한다. 문구 아래에 다음 행동을 안내한다 |
| 주소 입력 | 주소 칸을 누르면 주소 검색(ADM-ADDR-FIND)을 연다. 직접 입력을 막고 검색 결과에서만 고른다 |
| 겹친 팝업 | 팝업 안에서 연 팝업은 앞 팝업을 닫지 않고 위에 띄운다. 닫으면 앞 팝업으로 돌아간다 |
| 일괄 처리 | 목록에서 여러 건을 골라 한 번에 처리한다. 확인 팝업에 대상 건수를 적는다 |
| 상위 항목 추가 | 선택 칸에 원하는 값이 없으면 그 자리에서 만든다. 화면을 벗어나지 않는다 |
| 목록 선택 | 첫 열에 선택 체크박스, 둘째 열에 순번을 둔다. 마지막 열에 행 단위 동작을 둔다 |
| 날짜 입력 | 달력 아이콘을 붙인다. 기간은 시작일과 종료일을 나란히 둔다 |
| 검색 입력 | 돋보기 아이콘을 앞에 붙여 다른 입력칸과 구분한다 |
| 권한 없는 화면 | 진입을 차단하고 "권한이 없습니다."를 표시한다 |
| 로딩 | 조회 중에는 진행 상태를 표시한다 |
| 오류 | 처리하지 못한 경우 무엇이 잘못되었고 무엇을 하면 되는지 표시한다 |
| 원산지·알레르기 표시 | 고객이 보는 메뉴 화면에 표시한다. 원산지 글자 크기는 메뉴 이름과 같거나 커야 한다. 열량은 식품명 또는 가격 활자 크기의 80퍼센트 이상으로 표시한다 |
| 키오스크 접근성 | 검증기준 준수 단말과 음성안내장치를 전제로 화면을 설계한다 |

## 7. 처리 확인과 결과 안내

### 7.1 어드민

내부 어드민과 가맹 어드민에서 데이터를 저장, 수정, 삭제, 상태 변경할 때 같은 방식으로 처리한다.

#### 처리 순서

```text
[사용자] 저장·삭제·변경 선택
 ↓
확인 팝업 표시
 ↓
확인 또는 취소?
 ├─ 취소 → 하단 토스트 "취소되었습니다." → 원래 화면 유지
 └─ 확인 → 다음
 ↓
[서버] 처리 요청
 ↓
처리 성공?
 ├─ 아니오 → 하단 토스트에 실패 사유 표시 → 원래 화면 유지
 └─ 예 → 하단 토스트 "저장되었습니다." → 화면 갱신
```

#### 확인 팝업

| 항목 | 규칙 |
| --- | --- |
| 표시 대상 | 저장, 수정, 삭제, 상태 변경. 조회와 검색은 제외한다 |
| 구성 | 제목, 처리 내용, 확인 버튼, 취소 버튼 |
| 처리 내용 | 무엇이 어떻게 바뀌는지 적는다. "저장하시겠습니까?"만 적지 않는다 |
| 되돌릴 수 없는 처리 | 대상 건수와 결과를 함께 적는다. 확인 버튼을 기본 선택으로 두지 않는다 |
| 기본 선택 | 취소를 기본으로 둔다 |

되돌릴 수 없는 처리는 매장 폐점, 계정 삭제, 연동 계정 삭제, 개인정보 파기다.

#### 결과 토스트

| 항목 | 규칙 |
| --- | --- |
| 위치 | 화면 하단 |
| 표시 시간 | 3초. 사용자가 닫을 수 있다 |
| 성공 문구 | "저장되었습니다." "삭제되었습니다." "변경되었습니다." |
| 취소 문구 | "취소되었습니다." |
| 실패 문구 | 무엇이 잘못되었고 무엇을 하면 되는지 적는다 |
| 화면 이동 | 토스트가 사라지기를 기다리지 않는다. 처리 직후 갱신하거나 이동한다 |
| 중복 | 같은 처리를 연속으로 하면 마지막 하나만 남긴다 |

문구는 처리한 동작을 그대로 쓴다. "작업이 완료되었습니다."처럼 무엇을 했는지 알 수 없는 문구는 쓰지 않는다.

#### 예외

| 상황 | 처리 |
| --- | --- |
| 목록에서 여러 건 처리 | 확인 팝업에 대상 건수를 적는다. 일부만 실패하면 성공과 실패 건수를 함께 표시한다 |
| 입력 검증 실패 | 확인 팝업을 띄우지 않는다. 해당 입력 항목에 바로 표시한다 |
| 자동 저장 | 두지 않는다. 저장은 사용자가 선택한 시점에만 한다 |
| 처리 중 재선택 | 처리가 끝날 때까지 버튼을 다시 누를 수 없게 한다 |

이 규칙은 어드민 전 화면에 적용하므로 개별 Flow에 확인 팝업과 토스트 단계를 따로 그리지 않는다. 처리 결과에 따라 흐름이 갈리는 경우에만 Flow에 표시한다.

### 7.2 하이브리드 웹앱

고객 화면은 어드민과 다르게 다룬다. 모든 동작에 팝업을 띄우면 주문 단계가 늘어난다. 되돌릴 수 없는 동작에만 확인을 받는다.

| 동작 | 확인 팝업 | 결과 안내 |
| --- | --- | --- |
| 장바구니 담기 | 없음 | 하단 토스트 "장바구니에 담았습니다." |
| 수량 변경 | 없음 | 화면에서 금액이 바로 바뀐다 |
| 항목 삭제 | 있음 | 하단 토스트 "삭제되었습니다." |
| 장바구니 비우기 | 있음 | 하단 토스트 "장바구니를 비웠습니다." |
| 다른 매장 항목 초기화 | 있음 | 하단 토스트 "장바구니를 비웠습니다." |
| 결제 | 없음. 결제 상세 화면이 확인 단계다 | 결제 완료 화면으로 이동 |
| 주문 취소 | 있음 | 하단 토스트 "취소되었습니다." |

결제는 별도 확인 팝업을 두지 않는다. 결제 상세 화면 자체가 확인 단계이고, 그 뒤에 결제대행사 결제창이 한 번 더 확인을 받는다. 팝업을 끼워 넣으면 확인이 세 번이 된다.

토스트 규칙은 위치, 표시 시간, 중복 처리 모두 어드민과 같다.

### 7.3 키오스크

현장에서 서서 쓰는 화면이므로 토스트를 쓰지 않는다. 결과는 화면 자체가 바뀌어 보여준다. 삭제와 전체 취소에만 확인 팝업을 둔다.

무입력 대기가 걸려 있으므로 팝업을 띄운 동안에도 남은 시간을 함께 표시한다.
